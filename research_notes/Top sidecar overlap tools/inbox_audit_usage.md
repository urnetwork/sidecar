# Inbox, group messaging, and admin auth/audit overlap (as of 2026-10-31)

Scope is only the brief's jobs 4–6, scored against jobs 1–3 and 7 at the end. The unreleased product was not researched. Vendor case studies and vendor headlines are labeled as vendor claims. Chat-tool user counts are not treated as agent-inbox adoption.

Two lists, ranked by evidence of actual use that was opened, not by how large the human product is:

**List A — tools agents are shown using as an inbox or group channel**

1. Slack, as a place agents are installed and mentioned (strongest opened product evidence; no opened 2025–2026 official user count, and no opened survey of how many developers message an agent there).
2. AgentMail, a purpose-built agent email API with live pricing and named customer stories (vendor claims; no company-wide usage number opened).
3. Resend Inboxes, shipped 2026-10-22, priced, no usage number. Too new to rank on use.
4. Microsoft Teams, only a single vendor customer blurb that one product "lives in" Teams. Not ranked as an agent channel.
5. Discord, Google email, and Microsoft email: not verified as agent inboxes on a page opened for this note.

**List B — where admins already get team auth and an audit trail on agent or developer tools**

1. GitHub Copilot, on GitHub Enterprise: SAML SSO plus an enterprise audit log of agent actions. Widest dev-platform evidence. No absolute seat count was recovered from a full page body.
2. Cursor Teams/Enterprise: SAML SSO, Member/Admin/Unpaid Admin, Enterprise audit log of admin and configuration actions. The same page says prompts and agent output are not in that log.
3. Claude Team/Enterprise: SSO, roles, Enterprise audit export. Conversation metadata is logged; chat title and content are not in that export.
4. Devin Enterprise: audit API records sessions, messages, guardrail violations, login, SCIM, and IdP groups. No usage number opened.
5. Dust Enterprise: audit log that separates human and agent actions, including `agent.executed`. No usage number opened.
6. LangSmith Enterprise: SSO-related operations and an audit log that includes agent-registry writes. Not a transcript of agent actions. No usage number opened.
7. Sourcegraph: structured audit log for auth, RBAC, users, and completion quotas. Not an in-app admin viewer, and the opened entity list does not include Cody prompt content.
8. Zep Enterprise: SSO plus a dashboard audit log. API and SDK calls are excluded from that log. Memory product, not a coding-agent admin console.
9. Mem0: not ranked. Opened evidence does not show SAML/OIDC SSO or an admin audit of what an agent did.

## Agent email products: what shipped, limits, and usage

### Takeaway

Two agent-inbox products were verified from their own pages: AgentMail, already selling Free / $20 / $200 tiers with named customer stories, and Resend Inboxes, announced on 2026-10-22 with 3 included inboxes and $1 per extra inbox on paid plans. Neither page states a user, inbox, or message total for the product. Case-study volumes are vendor claims about individual customers, not a market count.

### Cited Findings

- AgentMail's own pricing page lists Free at $0 with no card: 3 inboxes, 3,000 emails/month, 100 emails/day, 3 GB storage. Developer is $20/month: 10 inboxes, 10,000 emails/month, 1,000 emails/day, 100 emails per 5 minutes, 10 GB, 10 custom domains, 2 organization seats, email support. Startup is $200/month: 150 inboxes, 15,000 emails/day, 1,500 per 5 minutes, no separate monthly email cap, unlimited storage, 150 custom domains, 10 seats, SOC 2 report. Enterprise is custom and adds white-label, EU cloud, BYO cloud, dedicated IPs, and OIDC/SAML SSO. — [AgentMail pricing](https://www.agentmail.to/pricing.md)
- The same page says Developer and Startup can buy add-ons at $2/month each for one inbox, one custom domain, or 1,000 more monthly emails ($19.20/year on yearly plans), and seats at $5/month ($48/year). Social SSO and MFA are on every tier. OIDC/SAML SSO is Enterprise only. SOC 2 report access starts at Startup. Free mail carries a "Sent via AgentMail" footer; paid tiers remove it. MCP server, SDKs, webhooks, websockets, and SMTP relay are on every tier. — [AgentMail pricing](https://www.agentmail.to/pricing.md)
- AgentMail's customers index, a vendor page, lists 13 customer stories and quotes named deployments. Examples it states: Lanesurf agents run "hundreds of programmatic inboxes, millions of messages, thousands of loads a day" (story dated 2026-07-27); AISDR has "hundreds of AgentMail inboxes in production, thousands of emails per week" (2026-05-14); Alchemy AgentCard gives every paying agent an inbox and claims "~70% increase in agentic transactions post-integration" (2026-07-16); Cofounder sent "800+ emails through agent inboxes in week one" (2026-05-03); Balance's AI accountant Bea serves "50+ SMB customers" (2026-05-07). Browser Use, Opendoor, Junior/Kuse, Locus, Eragon, DoAnything, Pancake, and Dossium are also named. These are vendor claims, not an independent census. — [AgentMail customers](https://www.agentmail.to/customers)
- That customers index does not give AgentMail's own inbox count, customer count, or emails processed. No usage number for the company was found on the pricing or customers pages. — [AgentMail pricing](https://www.agentmail.to/pricing.md); [AgentMail customers](https://www.agentmail.to/customers)
- Resend announced Inboxes on 2026-10-22 as "the inbox for agents." An inbox sends and receives on the customer's domain. Threads are shared by the app, the team, and agents. The post says people and agents can work the same inbox, and that Claude Code, Cursor, Codex, Grok, or Gemini can be connected through MCP or skills. A built-in agent takes instructions, a tone, and allowed actions such as draft reply, forward, label, assign, mark spam, archive, and delete. — [Announcing Inboxes](https://resend.com/blog/announcing-inboxes)
- The announcement says you can start free with up to 3 inboxes, and additional inboxes on paid plans are $1 per inbox. It states no customer or volume number. — [Announcing Inboxes](https://resend.com/blog/announcing-inboxes)
- Resend's pricing page, opened the same day, matches that: every plan includes 3 inboxes; paid plans add more at $1 per inbox per month; the Free plan stops at 3. Inbox email has no separate allowance. Every email sent or received through an inbox counts toward the transactional quota. Free is 3,000 emails/month and 100/day. Pro is $20/month for 50,000 or $35/month for 100,000, overage $0.90 per 1,000. Scale runs from $90/month for 100,000 up to $1,150/month for 2,500,000. Enterprise is custom. Self-serve plans are monthly only. SSO is a $150/month add-on on Scale and included on Enterprise. Data retention on Free, Pro, and Scale is 30 days. — [Resend pricing](https://resend.com/pricing)
- Resend's pricing page also does not publish an Inboxes usage number. As of 2026-10-31 the product had been public for nine days. — [Resend pricing](https://resend.com/pricing); [Announcing Inboxes](https://resend.com/blog/announcing-inboxes)

### Inferences

- AgentMail is the only agent-email product in this pass with both a shipped price list and multiple named production stories. That is evidence of use, but it is vendor-authored, so it cannot be turned into a market share or a total volume.
- Resend Inboxes should be treated as newly shipped infrastructure from an existing email API, not as a proven agent inbox. Price is public; adoption is not.
- Third-party comparison blogs that restate AgentMail as 150,000 emails/month on Startup disagree with the pricing markdown opened here, which says Startup has no separate monthly cap and a 15,000/day cap. Prefer the first-party markdown.

### Gaps

- No opened page states AgentMail's total customers, inboxes, or emails processed. A July 2025 Hacker News comment about "10,000,000+ emails processed" was seen in search snippets and was not opened, so it is not used.
- No opened page states Resend Inboxes usage.
- Other agent-inbox brands that appeared in competitor comparison posts (Dead Simple Email, Robotomail, Lumbox, LobsterMail, Inkbox, Shipmail, SentFromAI, CarlyEmail, Nylas Agent Accounts) were not opened on their own docs. They are not verified here.
- AgentMail's original ship date was not taken from an opened launch post. Pricing and customer stories show it was on sale before Resend Inboxes.

## Group messaging developers already use with agents

### Takeaway

The only chat product whose own docs, opened here, show an agent living in the channel is Slack: Claude can be DMed, mentioned in threads, and can hand coding tasks to Claude Code. Cursor's audit log records Slack account link and unlink. That is not the same as a count of developers who use Slack as an agent inbox. No opened 2025–2026 survey or official user-count page was found that measures agent use of Slack, Teams, Discord, Gmail, or Outlook. Historical "hundreds of millions of users" claims for Teams or Slack were not re-opened from the vendor and are not used.

### Cited Findings

- Anthropic's Slack connector doc says the Claude in Slack app puts Claude inside the workspace so people can message it there, and a separate connector lets Claude search channels, DMs, and files. The app needs a paid Slack plan and a Slack admin. After install, Claude is reachable by direct message, Slack's AI assistant panel, and @Claude in a thread. On Team and Enterprise, people with Claude Code access can route coding tasks to Claude Code by mentioning @Claude. The connector itself is Team and Enterprise and requires the app first. The page says this describes an earlier per-user app and points at Claude Tag as the current product. It gives no install count. — [Slack integration, Claude docs](https://claude.com/docs/connectors/slack)
- The same page says Slack conversations with Claude are kept out of claude.ai history, and disconnecting deletes those Slack conversations within 30 days. Workspace Slack retention still applies to the Slack messages. — [Slack integration, Claude docs](https://claude.com/docs/connectors/slack)
- Cursor's Enterprise audit-log doc records `slack_account_link` when a member links or relinks a Slack account, with Slack team id, Slack user id, and whether the workspace changed. Team settings also include Slack defaults (`slack_default_repo`, `slack_default_branch`, `slack_default_model`, `slack_share_summary`, `slack_share_summary_in_external_channel`). That shows Cursor has a Slack linkage admins can see. It is not a user count. — [Cursor compliance and monitoring](https://cursor.com/docs/enterprise/compliance-and-monitoring)
- AgentMail's customers index says Junior, by Kuse, "is an AI employee that lives in Slack, Teams, Lark, and email" and that each AI employee needed a real email identity. That is one vendor sentence. The underlying story was not opened. — [AgentMail customers](https://www.agentmail.to/customers)
- Stack Overflow's 2025 AI section, opened, says 84% of respondents are using or planning to use AI tools in development, up from 76%, and 51% of professional developers use AI tools daily. The opened portion does not break out Slack, Teams, Discord, or email as the channel those agents use. The page is about AI sentiment and workflow, not messaging products. — [2025 Stack Overflow Developer Survey, AI](https://survey.stackoverflow.co/2025/ai)
- GitHub's Octoverse 2026 post URL was fetched and returned only the title, so percentages in search extracts of that post (including a claim that 55% of Copilot monthly active users use agentic features) are not treated as verified. The changelog posts that were returned in search do show Copilot projects accepting "Slack threads" as context. Those changelog pages were not fully fetched. — [Octoverse 2026](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/)
- AgentMail's pricing page lists a Discord community on every plan and a Slack support channel only on Enterprise. That is human support, not an agent inbox. — [AgentMail pricing](https://www.agentmail.to/pricing.md)

### Inferences

- Rank Slack first on List A because two independent product docs (Anthropic and Cursor) show agents or agent products attached to Slack workspaces. Rank AgentMail second because its customers page shows agents receiving real email, with the caveat that every volume figure there is a vendor claim. Rank Resend third as shipped but unused-in-public. Do not rank Teams, Discord, Gmail, or Outlook as agent channels.
- A chat tool's total human users, even if the last official Teams figure was on the order of hundreds of millions, would still not be evidence that agents use it as an inbox. No such official count was opened in this pass, so the lists do not depend on it.

### Gaps

- No opened official Slack, Microsoft Teams, Discord, Gmail, or Outlook user count for 2025 or 2026. Third-party Slack DAU/MAU articles conflict with each other and were not used.
- No opened Stack Overflow or similar 2025–2026 chart ranks Slack vs Teams vs Discord vs email as the channel developers use with agents. The 2026 survey page was seen in search mentioning "internal chat tools, such as Slack or Teams" as a place people look for trusted answers (45.4% in that snippet). That page was not opened, and that question is not agent-channel use.
- Claude Tag's marketing line that Teams is "coming soon" was in a search snippet of https://claude.com/product/tag and was not opened, so it is not a finding.
- No opened page shows Discord as a group inbox for coding agents. Bot platforms exist; they were not verified against this brief.

## Auth and audit on the agent platforms people use

### Takeaway

GitHub Copilot, Cursor, Claude, Devin, Dust, LangSmith, Sourcegraph, and Zep all document some admin identity control and some audit log. Only GitHub's opened agent-audit page, Dust's opened audit page, and Devin's opened action list clearly record what an agent did, as distinct from who changed a setting. Cursor states the opposite for its main audit log: payloads never include prompts, agent output, or generated code. Mem0's opened trail stops at project roles and, in self-hosted docs found via search, a request log. No opened page gives a customer count for Cursor, Claude, Devin, Dust, Sourcegraph, Zep, Mem0, or LangSmith.

### Cited Findings

- GitHub: enterprise owners can filter the enterprise audit log with `actor:Copilot` and see agentic activity for the last 180 days. Fields include `action` (example `pull_request.create`), `actor_is_agent` (always true for these events), `agent_session_id`, and `user` (the person who initiated the event). A public-preview stream of Copilot API usage records, for Enterprise Managed Users and Enterprise Cloud with data residency, includes request or response type, user id, enterprise id, endpoint, and a JSON body that can be truncated at 1 MB. — [Audit log events for agents](https://docs.github.com/en/copilot/reference/agentic-audit-log-events)
- GitHub SAML: GitHub is the SAML service provider for organization or enterprise SSO. Enterprise Managed Users can enable SAML only at the enterprise level. Organization metadata lives at `https://github.com/orgs/ORGANIZATION/saml/metadata`. Default session invalidation is 24 hours if the IdP does not send `SessionNotOnOrAfter`. The opened page does not list enterprise role names. — [SAML configuration reference](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/iam-configuration-reference/saml-configuration-reference)
- Cursor audit logs, Enterprise only, "record who changed what in your team and organization: sign-ins, membership, roles, API keys, settings, integrations, Cloud Agent environments, Grok Bot configuration, and Origin repositories." Every event has time, actor, client IP, and product surface when present. "Payloads carry identifiers, names, and changed settings, never prompts, agent output, generated code, or credentials." Explicitly not logged: agent responses, prompts, and generated code (the page says use hooks for that); Grok Bot shell and browser actions (those are a separate Action Recording / OpenTelemetry path); Cloud Agent automation runs; failed sign-ins. Roles in `update_user_role` include `OWNER`, `MEMBER`, and `FREE_OWNER`. Actors can be a member email, an API key, `Bot: <owner email>` for a Grok Bot, `SCIM`, or an installed app. — [Cursor compliance and monitoring](https://cursor.com/docs/enterprise/compliance-and-monitoring)
- Cursor team roles, opened: Members have paid features and no admin dashboard. Admins add and remove members, change roles, set up SSO, and see analytics. Unpaid Admins have the same admin powers, are not billable, and have no paid Cursor features. SAML 2.0 SSO is on Team plans, with domain verification required. SSO and domain join are also described for teams not using SCIM; if SCIM is on, the IdP manages members. Enterprise admins can review and revoke members' personal API keys, and those revocations are `user_api_key` audit events. No customer count. — [Cursor members, roles, and seat types](https://cursor.com/docs/account/teams/members)
- Claude audit logs are Enterprise only. Organization Owners and Primary Owners export them from Organization settings > Data and privacy. The export covers the past 180 days; the download link lasts 24 hours. "Title and content of chats and projects are not available to be exported in audit logs (only their unique identifiers will be exported)." Columns include `created_at`, actor, event, entity, IP, device id, and user agent. Recorded events include sign-in (SSO, Google, Apple), sign-out, invites, user deleted, SSO toggled, SSO connection activated/deactivated/deleted, JIT toggled, domain verified, and `conversation_created`, `conversation_deleted`, and `conversation_renamed`. Orgs on customer-managed encryption keys cannot use the export button; events are in the Compliance API instead. — [How to access audit logs](https://support.claude.com/en/articles/9970975-how-to-access-audit-logs)
- Claude SSO "is available for Team plans, Enterprise plans, and Console organizations." Team or Enterprise setup requires an Owner or Primary Owner. Console requires an Admin. Domain verification uses a DNS TXT record. Owners can require SSO for Claude and for Console separately. Provisioning modes named on the page: invite only (default), just-in-time, and SCIM with IdP group mappings for roles or seat tiers. WorkOS is the SSO provider. No seat count. — [Set up single sign-on (SSO)](https://support.claude.com/en/articles/13132885-set-up-single-sign-on-sso)
- Devin's opened v3 audit API, `GET /v3/enterprise/audit-logs`, requires `ViewAccountAuditLogs`. Each item has `action`, `audit_log_id`, `created_at`, `user_email`, `user_id`, `org_id`, optional service user, and a `data` object. The action enum includes `login`, `create_session`, `send_message`, `terminate_session`, `ai_guardrail_violation`, `expose_port`, `deploy_app`, `authorize_ssh_access`, membership and role changes, `create_scim_user` / update / delete, and IdP group create/update/delete plus member add/remove. A filtered time window must be 100 days or less. The page does not state retention or a customer count. The SSO setup guide was not fully opened. — [Devin list audit logs](https://docs.devin.ai/api-reference/v3/audit-logs/enterprise-audit-logs)
- Dust audit logs are Enterprise only. The opened page says they are a tamper-evident record of who did what, to which resource, from where, and when, and that they "distinguish between actions taken by human users and actions taken by AI agents." Admins and members of groups granted "Access security features" view them at Admin > Security > Audit Logs, with search, time filter, and CSV export. Actor types are `user`, `api_key`, and `system`. For `agent.executed` and `tool.executed`, the actor is whoever initiated the action; AI-driven is in `metadata.actor_type`, `metadata.initiating_user_id`, and `metadata.initiating_user_email`. Streaming targets include Datadog, Splunk, S3, GCS, and custom HTTPS. No customer count. The events-reference and SAML pages were not fully opened. — [Dust audit logs](https://docs.dust.tt/docs/audit-logs)
- LangSmith audit logs are Enterprise only. Organization Admin or Organization Operator (`organization:manage`) views them at Organization Settings > Audit logs, or via `GET /api/v1/audit-logs` in OCSF 1.7.0 API Activity. Retention is up to 400 days. Each event has timestamp, actor, operation, resources, and success. Tracked operations include SSO and SCIM (`create_sso_settings`, `update_sso_settings`, `login`, SCIM user and group writes) and an Agents group: `create_agent`, `create_agent_environment`, `update_agent`, `delete_agent`, `create_agent_runtime_binding`. The FAQ says logs are "primarily focused on write operations." The opened page does not say the log stores prompts or model output. Self-hosted audit logs need Helm chart 0.12.33 or later. No customer count. — [LangSmith audit logs](https://docs.langchain.com/langsmith/audit-logs.md)
- Sourcegraph's audit log is structured JSON on STDERR for security specialists ingesting a SIEM. The page says "Administrators are currently not the target audience, but we'll likely offer an easy-to-use in-app audit log." Audited areas include login and access tokens, permission and role changes, user create/modify/delete, site config, repository access, and code-host webhooks. Entities include `user.completions.quota` and `user.codecompletions.quota` changed. The opened entity list does not include chat prompts or an "agent executed" event. Actor is a user id and IP, not an email, until an admin joins it in the API console. No customer count. SSO/SCIM was not on this page. — [Sourcegraph audit log](https://sourcegraph.com/docs/admin/audit-log)
- Zep's governance page says RBAC governs dashboard teammates, enterprise SSO is how those teammates authenticate, and ABAC policies limit what each agent and Context MCP user can reach. It points at a separate audit log of "member, API key, project, access-control, settings, and data-operation events," plus separate API logs. — [Zep governance](https://help.getzep.com/governance.md)
- Zep audit logging is Enterprise only and "records actions performed by team members through the Zep web dashboard." "API requests and SDK calls made by your applications are not included." Logged categories: member invites and removals, API key create/revoke and role changes, project create/update/delete, RBAC binding create/delete and permission denied, dashboard data operations on users, threads, and graphs, and audited settings changes. Each row has timestamp, actor email, actor role, action, resource, request id, IP, and user agent. The page says the list does not mean every dashboard read or mutation is logged. No customer count. — [Zep audit logging](https://help.getzep.com/audit-logging.md)
- Mem0: no first-party page documenting SAML or OIDC SSO, or an admin audit of agent actions, was opened. Search of Mem0's own docs shows platform projects with READER and OWNER roles, and a self-hosted dashboard "Requests" page described as a live audit log of API calls (method, path, status, latency). A Mem0 blog says viewer/editor/owner permissions are not native and that `history()` returns ADD, UPDATE, and DELETE for one memory with old value, new value, and timestamp. Those pages were not fully fetched. A third-party "governance pack" that wraps Mem0 with Keycloak and Postgres is not Mem0. — search extracts only; not used as ranked evidence. Trust center snippet (SOC 2 Type I compliant, Type II in progress) was also not opened.

### Inferences

- Rank List B by how much opened evidence shows admins already using the control, which here tracks how central the product is to developer work and how explicit the audit of agent actions is. GitHub is first because the audit is of agent actions on the forge developers already administer, and SAML is documented on the same vendor. Cursor is second because team SSO and roles are documented in the product admins already open, even though the audit log is of configuration, not of what the agent wrote. Claude is third on the same logic: SSO and an org audit exist, but the export omits chat content. Devin and Dust have richer agent-action logs and no opened evidence they are as widely administered. LangSmith, Sourcegraph, and Zep are real admin trails for narrower products (traces, code search, memory). Mem0 does not clear the bar on opened pages.
- "Audit trail an admin can view" is not one feature. Dust and Devin log agent execution. GitHub logs agent actions on GitHub objects and can stream Copilot request/response bodies in a preview. Cursor, Claude's CSV export, LangSmith, Sourcegraph, and Zep mostly log who changed access or configuration. Quoting them as the same control would be wrong.

### Gaps

- No opened usage or customer count for Cursor, Claude, Devin, Dust, Sourcegraph, Zep, Mem0, or LangSmith. GitHub's Octoverse body did not load, so Copilot's agentic-feature share is unverified here.
- GitHub enterprise role names (owner, member, billing manager, and so on) were not opened beyond "enterprise owners" on the Copilot audit page.
- Devin SSO setup steps, Dust SAML steps, LangSmith SAML setup steps, and Sourcegraph SAML/SCIM pages were not fully opened. Their existence is partly implied by audit events (Devin SCIM and IdP groups; LangSmith `create_sso_settings`) but the configuration docs were not quoted from a full fetch.
- Mem0 enterprise SSO, if it exists, was not found.
- Cursor's separate hooks and Grok Bot Action Recording were named on the compliance page and not opened. They may log more of what the agent did than the Enterprise audit log. That was not verified.

## What these tools do not do from the brief

### Takeaway

The tools above cover email or chat for agents, and, separately, admin SSO and an audit log. None of the pages opened show them doing the rest of the brief: a real-time encrypted store with a git front end, IP and port forwarding for local services, a public TLS edge in front of those local services, or a userspace subprocess of any harness with a text protocol. MCP and HTTP APIs are not that subprocess.

### Cited Findings

- AgentMail and Resend Inboxes are email APIs. Their opened pages list inboxes, threads, webhooks, SMTP, and MCP. They do not describe git-backed encrypted storage, inbound port forwarding, or a public TLS hostname for a process on the user's machine. — [AgentMail pricing](https://www.agentmail.to/pricing.md); [Announcing Inboxes](https://resend.com/blog/announcing-inboxes)
- Slack, as documented for Claude, is a workspace the agent joins. The opened page does not give the agent a git store, a forwarded port, or a TLS edge. — [Slack integration, Claude docs](https://claude.com/docs/connectors/slack)
- Cursor's opened audit and roles pages cover team SSO, seats, and an Enterprise log of settings and membership. They state the log omits prompts and agent output. They do not describe Cursor as a userspace text-protocol sidecar, a port forwarder, or a public TLS edge. — [Cursor compliance and monitoring](https://cursor.com/docs/enterprise/compliance-and-monitoring); [Cursor members](https://cursor.com/docs/account/teams/members)
- GitHub's opened pages cover SAML and an audit of agent actions such as `pull_request.create`. GitHub stores git repositories, which is adjacent to "a git front end," but the opened pages do not describe real-time encrypted project storage for arbitrary agent context, port forwarding, or a public TLS edge for local services. — [Audit log events for agents](https://docs.github.com/en/copilot/reference/agentic-audit-log-events); [SAML configuration reference](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/iam-configuration-reference/saml-configuration-reference)
- Claude, Devin, Dust, LangSmith, Sourcegraph, and Zep pages opened here are admin, SSO, and audit docs. None describe running as a subprocess of an arbitrary harness, forwarding the user's ports, or terminating public TLS for a local service. Zep explicitly says its access policies do not authorize an action in an external system. — [Claude audit logs](https://support.claude.com/en/articles/9970975-how-to-access-audit-logs); [Devin audit logs](https://docs.devin.ai/api-reference/v3/audit-logs/enterprise-audit-logs); [Dust audit logs](https://docs.dust.tt/docs/audit-logs); [LangSmith audit logs](https://docs.langchain.com/langsmith/audit-logs.md); [Sourcegraph audit log](https://sourcegraph.com/docs/admin/audit-log); [Zep governance](https://help.getzep.com/governance.md)
- Where a text interface for agents does appear, it is MCP or HTTPS, hosted by the vendor: AgentMail lists an MCP server on every plan; Resend tells people to connect agents through MCP or skills; Zep documents a Context MCP server. That is a remote tool protocol, not a local subprocess of any harness. — [AgentMail pricing](https://www.agentmail.to/pricing.md); [Announcing Inboxes](https://resend.com/blog/announcing-inboxes); [Zep governance](https://help.getzep.com/governance.md)

### Inferences

- Overlap with the brief is split. List A overlaps job 4 only (inbox and group messaging). List B overlaps jobs 5 and 6 only (team auth and an admin audit), and several List B logs do not record what the agent actually did. No opened tool overlaps jobs 1, 2, 3, or 7.
- Admins who already have GitHub or Cursor are not shown, on these pages, to be missing email for agents. Admins who buy AgentMail or Resend are not shown to be getting an audit of coding-agent actions. The jobs are adjacent, not combined, in the products that have evidence of use.

### Gaps

- A page could still exist that documents port forwarding, a TLS edge, or a local text protocol for one of these vendors. It was not part of the docs opened for inbox and audit, and it was not found by the searches used here.
- GitHub as a general git host is out of scope for this note beyond the negative finding above. Depth of GitHub's repo encryption and audit outside Copilot agent events was not reviewed.
