# Reach and usage of port-publishing tunnels

Scope is tools developers use, as of 2026-10-31, to publish a port from a laptop or other private machine so an agent or remote client can call it, including private (team-only) exposure when the same product offers it. Overlap is scored only against the brief: (1) real-time encrypted storage with a git front end, (2) IP address and port forwarding for local services, (3) a public TLS edge, (4) email inbox and group inbox, (5) easy auth and team management, (6) an admin audit trail, (7) a userspace subprocess of any harness with a text protocol interface. No 2025–2026 developer survey that ranks these tools was found. No filing or trustworthy revenue figure was found for the tunnel products. GitHub stars are labeled weak. Vendor signup and customer counts are vendor claims.

Rank for this job, by the strength of usage evidence actually found, not by feature checklists:

1. **ngrok** — only product with a large signup figure for the tunnel product itself.
2. **Microsoft dev tunnels** — no user count, but it is the port-forwarding implementation inside current VS Code, and it is still documented as a public preview.
3. **Cloudflare Tunnel (`cloudflared`)** — no tunnel customer count; active client, no-account quick tunnels, and first-party coding-agent docs that name it.
4. **Tailscale Serve (private) and Funnel (public)** — large network-product usage, but those counts are not Funnel or Serve counts. Funnel is still documented as beta.
5. **frp** — top open-source self-hosted reverse proxy by stars. Not a managed public TLS edge. Stars only.
6. **localtunnel, bore, zrok** — real repos, weaker or stale activity. Not established as the top set by user counts.
7. **Pinggy** — named in 2026 comparison articles only. No user count or repo star count was verified, so it is not ranked in the top set.

## Compare ngrok, Cloudflare Tunnel, Tailscale Funnel and Serve, and other verified tunnel products

### Takeaway

The tools that both forward a local port and put a public TLS name in front of it are ngrok, Cloudflare Tunnel (quick tunnels and named tunnels), Tailscale Funnel, and Microsoft dev tunnels. Tailscale Serve is the same product’s private TLS path and is not on the public internet. frp forwards ports only if the operator runs the server side. None of them is a git memory store, an inbox, or a harness-agnostic text protocol.

### Cited Findings

- **ngrok forwards** local HTTP, TCP, and (on Pay-as-you-go) TLS to public endpoints. Free includes HTTP, TCP only with credit-card verification, up to 3 online endpoints, up to 1 GB data transfer, up to 20k HTTP/S requests, a $5 one-time usage credit, an assigned dev domain, an interstitial page on HTTP/S endpoints, and 1 team member. Hobbyist is $10/month, no interstitial, still 1 team member. Pay-as-you-go is $20/month plus usage, bring-your-own domain, unlimited endpoints, 3 users included then $5 per user. TLS is terminated by ngrok unless the customer pays for end-to-end TLS or brings certificates. Page checked 2026-10-31. — [ngrok pricing](https://ngrok.com/pricing)
- **ngrok auth and teams** are optional and mostly paid. Traffic Policy OAuth/SAML/OIDC is metered as “Traffic Identities”: 3 monthly active users on Free, 5 on Hobbyist, 5 then $1 each on Pay-as-you-go. SSO/RBAC is a $10 per user/month add-on that must cover all users. The “Identity and Access Governance Suite” (SCIM, account-wide IP restrictions, **audit logs**) is $15 per user/month and requires the SSO/RBAC add-on. — [ngrok pricing](https://ngrok.com/pricing)
- **ngrok’s practical request log** is Traffic Inspector, separate from those account audit logs: 24 hours retention on Free, 72 hours on Hobbyist and Pay-as-you-go. Exporting traffic logs is $0.25 per 2k events. — [ngrok pricing](https://ngrok.com/pricing)
- **ngrok also documents private internal endpoints** that are not reachable until a Traffic Policy `forward-internal` action publishes them, in its guide to putting a local MCP server behind ngrok. Retrieved page dated 2026-09-21. — [Using ngrok as your MCP gateway](https://ngrok.com/docs/using-ngrok-with/using-mcp)
- **Cloudflare Quick Tunnels** (`cloudflared tunnel --url http://localhost:8080`) create a temporary `trycloudflare.com` URL with no Cloudflare account. “Anyone with the URL can access your local service.” The URL dies when the process stops and changes every run. As of the page last updated 2026-09-30, `--allowed-mail` can require an email one-time PIN, including `*@example.com`, but “Email authentication requires an interactive browser session. It does not support non-interactive clients.” Limits: no uptime guarantee, 200 in-flight requests then HTTP 429, no Server-Sent Events. The page says quick tunnels are for testing, not production. — [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
- **Cloudflare account audit logs** are a real admin view. The Zero Trust logs page, last updated 2026-10-15, lists admin logs retained 18 months on Free, Standard, Access, Gateway, and Enterprise. Access (per-request / authentication) logs are 24 hours on Free, 30 days on the Access plan, and up to 180 days on Enterprise. A changelog entry dated 2026-10-30 adds Audit Logs v2 account analytics (actions over time, unique actors, failure rate). — [Zero Trust logs](https://developers.cloudflare.com/cloudflare-one/insights/logs/); [Audit Logs changelog](https://developers.cloudflare.com/changelog/product/audit-logs/)
- **Cloudflare Access** is the team-auth layer in front of self-hosted apps, not the quick-tunnel default. Docs last updated 2026-10-12 describe Zero Trust roles (Super Administrator, Access edit, and others) and say there is no limit on how many members can be added to the account. Identity-provider docs (Google Workspace, SAML/SCIM) were updated 2026-10-30. A seat price and a free-user cap were **not** present on the marketing pricing page retrieved the same day (the page did not render plan numbers). — [Cloudflare One roles](https://developers.cloudflare.com/cloudflare-one/roles-permissions/); [Zero Trust pricing](https://www.cloudflare.com/plans/zero-trust-services/)
- **`cloudflared` is the connector**, not the edge. GitHub API on 2026-10-31: `cloudflare/cloudflared` 16,361 stars, 1,509 forks, last push 2026-10-30. The repo describes a daemon that proxies from Cloudflare’s network to an origin without inbound ports. Stars are a weak proxy for tunnel users. — [cloudflare/cloudflared](https://github.com/cloudflare/cloudflared)
- **Tailscale Serve** publishes a local port, file, or directory only inside the tailnet, on an HTTPS `*.ts.net` name. ACLs apply. Serve adds identity headers (`Tailscale-User-Login`, `Tailscale-User-Name`, `Tailscale-User-Profile-Pic`) and, since client v1.92, an optional app-capabilities header. Those headers are not set for Funnel traffic and not for tagged devices. Docs last validated 2026-01-20. — [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)
- **Tailscale Funnel** is the public path: internet to a local service via Funnel relay servers, TLS only, ports 443, 8443, and 10000 only, tailnet DNS name only, non-configurable bandwidth limits. “Tailscale Funnel is currently in beta” and “available for all plans.” Who may turn it on is a `funnel` node attribute; the CLI default is `autogroup:member`. Relay servers do not decrypt the proxied stream; the node terminates TLS. Docs last validated 2026-01-20. There is no login wall for the visitor. — [Tailscale Funnel](https://tailscale.com/kb/1223/funnel)
- **Tailscale audit.** The 2026-02-02 log-streaming doc says log streaming of configuration audit logs and network flow logs “is available for the Premium and Enterprise plans.” A 2026-02-20 product post says network flow logs now include actor identity (user, device, device name) and that Kubernetes API proxy audit logging was in beta. The 2025-04-03 company post lists “audit logs” as a product capability and does not state a plan gate for viewing them in the admin console. Whether Free can see configuration audit logs in the console was not confirmed. — [Log streaming](https://tailscale.com/docs/features/logging/log-streaming); [Auditable infrastructure access](https://tailscale.com/blog/auditable-infrastructure-access); [5 years of Tailscale](https://tailscale.com/blog/5-things-5-years)
- **Microsoft dev tunnels** forward local ports through an Azure relay. Web ports are reached at `https://…devtunnels.ms`. Insecure clients are upgraded to HTTPS/WSS, minimum TLS 1.2, TLS 1.3 preferred, TLS terminated at the service with a Microsoft CA certificate. Default access is the creating Microsoft, Entra ID, or GitHub account. Anonymous access is opt-in (`--allow-anonymous`). Access can be widened to the Entra tenant or a GitHub organization, or to a bearer of a tunnel token (currently 24 hours) sent as `X-Tunnel-Authorization`. First browser GET of a web URL shows an anti-phishing interstitial. Overview still says public preview, no SLA, not for production. Security page `updated_at` 2026-02-12; overview content still contained the preview banner when fetched 2026-10-31. — [What are dev tunnels?](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/overview); [Dev tunnels security](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/security)
- **Dev tunnel limits**, monthly, on the Azure limits page (`ms.date` 2026-08-04, `updated_at` 2026-09-29): 5 GB bandwidth per user, 10 tunnels per user, 1,000 active connections per port, 10 ports per tunnel, 1,500 HTTP requests/min per port, up to 20 MB/s per tunnel, 16 MB max web-forwarding HTTP body. Unused tunnels are deleted after 30 days of inactivity (FAQ page; custom expiration 1 hour to 30 days). — [Azure subscription and service limits](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/azure-subscription-service-limits); [Dev tunnels FAQ](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/faq)
- **VS Code port forwarding is dev tunnels.** Page dated 2026-10-28: Ports view, GitHub sign-in, private by default (same GitHub account), public visibility does not require sign-in. No user count. — [VS Code port forwarding](https://code.visualstudio.com/docs/debugtest/port-forwarding)
- **frp** is a self-hosted reverse proxy: the operator runs `frps` on a machine with a public address and `frpc` on the private machine. GitHub API 2026-10-31: `fatedier/frp` 110,353 stars, 15,290 forks, last push 2026-10-23, not archived. Description: “A fast reverse proxy to help you expose a local server behind a NAT or firewall to the internet.” It does not itself provide a hosted public TLS edge or a vendor audit log. Stars are weak evidence. — [fatedier/frp](https://github.com/fatedier/frp)
- **localtunnel** GitHub API 2026-10-31: `localtunnel/localtunnel` 22,496 stars, 1,566 forks, last push 2025-08-29, not archived. No user count. Feature behavior was not re-verified from the README. — [localtunnel/localtunnel](https://github.com/localtunnel/localtunnel)
- **bore** GitHub API 2026-10-31: `ekzhang/bore` 11,571 stars, 531 forks, last push 2026-02-04. No user count. A secondary comparison (facts checked 2026-10-01) describes `bore.pub` as raw TCP with no TLS and no auth, 24-hour timeout claimed by the maintainer. That feature detail is secondary, not a page opened on the project itself. — [ekzhang/bore](https://github.com/ekzhang/bore); [LayerV localhost tunnels](https://layerv.ai/compare/localhost-tunnels/)
- **zrok** GitHub API 2026-10-31: `openziti/zrok` 4,797 stars, 229 forks, last push 2026-10-31. No user count. Secondary descriptions say it can do private shares as well as public ones. Not verified from zrok’s own docs in this pass. — [openziti/zrok](https://github.com/openziti/zrok)
- **The old open-source ngrok 1.x repo is not the current product.** GitHub API 2026-10-31: `inconshreveable/ngrok` 24,389 stars, archived, last push 2024-04-26. Do not treat those stars as 2026 ngrok usage. — [inconshreveable/ngrok](https://github.com/inconshreveable/ngrok)
- **`microsoft/dev-tunnels` is a small repo, not a usage figure.** GitHub API 2026-10-31: 518 stars, 54 forks, last push 2026-10-21. VS Code distribution is the usage signal, not this star count. — [microsoft/dev-tunnels](https://github.com/microsoft/dev-tunnels)

### Inferences

- For “publish this laptop port to a public HTTPS URL an agent can call,” the products with a managed TLS edge are ngrok, Cloudflare Tunnel, Tailscale Funnel, and dev tunnels. frp, bore, and localtunnel only belong in that set if “top” is defined by open-source attention. On that definition frp is first and localtunnel is stale.
- Private exposure, same products: Tailscale Serve (tailnet membership plus ACLs, identity headers), dev tunnels (private by default; tenant or GitHub org), Cloudflare Access on a named tunnel (team IdP; not the quick-tunnel default), ngrok Traffic Policy auth and internal endpoints (thin on the free plan). Funnel and unauthenticated quick tunnels are URL-is-the-secret.
- Auth is not the same as an admin audit trail. ngrok’s request log exists on every plan for 1–3 days; account audit logs are an expensive add-on. Cloudflare’s account audit log is long-lived even when Access request logs on Free are only 24 hours. Tailscale’s exportable audit and flow logs are paid. Dev tunnels document a DevTools-style inspector, not a retained admin audit log.
- Brief overlap for this whole set is almost entirely items 2 and 3, plus a partial 5 and a partial 6. Items 1, 4, and 7 are misses. See the last section.

### Gaps

- Cloudflare’s current Zero Trust seat price and free-user cap were not visible on the pricing page that was opened. A secondary write-up (ITSecureOps, checked 2026-10-25) claims Free is $0 up to 50 users and Pay-as-you-go is $7 per user per month. That number is not used here.
- No page opened gives a customer or tunnel count for Cloudflare Tunnel, Funnel, Serve, dev tunnels, frp, localtunnel, bore, zrok, or Pinggy.
- Pinggy, localhost.run, Serveo, Expose, and Tunnelmole appear in 2026 roundups. No official user count was found, so they are not ranked.
- Whether Tailscale Free includes an in-console configuration audit log, as opposed to log streaming, was not confirmed.
- frp, bore, localtunnel, and zrok feature details beyond GitHub metadata were not all re-read from each project’s README.

Tailscale has published company-level counts, not Funnel counts. Everyone else is stars, IDE distribution, or agent documentation. No survey share and no credible revenue figure were found.

### Inferences

- If the question is “what do developers actually run to publish a port,” ngrok is the only one that has published a signup number for that job, and the number is a vendor claim with no as-of date. 15.3 million signups is not 15.3 million monthly active tunnels.
- Cloudflare Tunnel and dev tunnels can be more widely *installed* than the evidence can show: `cloudflared` is a single binary with a no-account mode, and dev tunnels ship inside VS Code. Absence of a count is not evidence of small usage. It is an evidence gap.
- Tailscale’s “millions of users” should not be rewritten as “millions of Funnel users.” Funnel was still beta on the 2026-01-20 docs page. Serve is the more natural use of an already-large tailnet, and it is private.
- frp’s 110k stars, with a push on 2026-10-23, are enough to keep it in the top open-source set. They are not enough to claim it is used more than ngrok.
- localtunnel’s star count overstates 2026 use. Last push was 2025-08-29.

### Gaps

- No as-of date on ngrok’s 5 million or 15.3 million figures, and no definition (accounts vs. monthly active vs. agents started).
- No Tailscale figure after the vague “millions” sentence on 2026-01-21, and no Funnel/Serve split.
- No Cloudflare Tunnel metric of any kind (tunnels, quick-tunnel hostnames, `cloudflared` downloads).
- No dev-tunnel MAU despite VS Code distribution.
- No 2025 or 2026 survey share.
- No credible revenue for ngrok or Tailscale. Cloudflare public-company revenue was not opened and would not isolate Tunnel anyway.
- npm or Homebrew download counts were not collected.

## Which coding-agent docs tell people to use these?

### Takeaway

First-party agent docs that name a tunnel name ngrok and Cloudflare Tunnel, not Tailscale, frp, or dev tunnels. Anthropic’s own private MCP path is `cloudflared`. xAI’s Grok doc tells people to use ngrok or a Cloudflare quick tunnel to put a laptop MCP server on the public internet. Cursor’s MCP doc does not name a tunnel. VS Code’s port-forwarding doc, which agents in that editor inherit, is Microsoft dev tunnels.

### Cited Findings

- **Grok (xAI), custom MCP connectors.** Fetched 2026-10-31 from `docs.x.ai`. Grok rejects `localhost` and private addresses. The page says “Below are two popular options,” then gives install-and-run steps for ngrok (`ngrok http 3001`, copy `https://….ngrok-free.app`) and Cloudflare quick tunnels (`cloudflared tunnel --url http://localhost:3001`, copy `*.trycloudflare.com`). It warns that Cloudflare quick tunnels do not support SSE and says to use ngrok if the server is SSE; Streamable HTTP is fine on Cloudflare. It also says the tunnel does not replace MCP OAuth or API keys, and that free URLs usually change on restart. ngrok is described as not affiliated with SpaceXSI or Grok. — [Custom MCP Server Tunneling](https://docs.x.ai/grok/connectors/custom-mcp-tunneling)
- **Claude Platform (Anthropic), MCP tunnels, research preview.** Fetched 2026-10-31. The tunnel stack inside the customer network is Anthropic’s proxy plus **`cloudflared`**, which dials Cloudflare’s edge on port 7844. The stated goal is the opposite of a public laptop URL: outbound-only, no inbound firewall rule, no public origin. Inner TLS is terminated by the customer proxy so Cloudflare cannot read MCP payloads. OAuth on the MCP server is still the customer’s job. “MCP tunnels created through the Console are not available as connectors in claude.ai.” The overview does **not** say the feature is Enterprise-only; it says research preview, request access, and that Anthropic may discontinue it. A third-party blog’s “Enterprise plan” claim was not used. — [MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview)
- **ngrok’s own agent doc, vendor.** Retrieved page dated 2026-10-21, “Expose an MCP Server to ChatGPT, Claude, Grok, and Cursor.” It says Claude Code and Cursor can already use `localhost` on the same machine, and to use ngrok when the server is on another machine or when the client is remote. Command shape: `ngrok http 3001` with a traffic-policy file, then `claude mcp add --transport http … https://….ngrok-free.dev/mcp`. A separate page dated 2026-09-21 shows internal endpoints plus a cloud endpoint as an MCP gateway. ngrok also ships its own account-management MCP server at `https://mcp.ngrok.com/mcp` (invite-only as of the page dated 2026-10-29); that server manages ngrok, it does not publish the user’s port. — [ngrok MCP gateway](https://ngrok.com/docs/gateway/api-gateway/mcp-gateway); [Using ngrok as your MCP gateway](https://ngrok.com/docs/using-ngrok-with/using-mcp); [ngrok MCP server](https://ngrok.com/docs/mcp-server)
- **Cursor’s own MCP doc does not name a tunnel.** Fetched 2026-10-31. Cursor supports `stdio`, SSE, and Streamable HTTP. The remote example is a URL, including `http://localhost:3000/mcp`. No ngrok, Cloudflare, Tailscale, or dev tunnels mention. Cloud agents need a URL Cursor’s servers can reach, but the doc does not say how to get one. — [Cursor MCP](https://cursor.com/docs/context/mcp)
- **VS Code, not an agent vendor but the editor agents run in.** Port forwarding doc dated 2026-10-28: built-in forwarding “via Microsoft dev tunnels,” private unless the user switches the port to Public. — [VS Code port forwarding](https://code.visualstudio.com/docs/debugtest/port-forwarding)
- **Cloudflare’s Agents docs are a different product.** Pages last updated 2026-10-27 tell readers to deploy a remote MCP server on Workers (`*.workers.dev/mcp`), with or without OAuth, or to call Cloudflare’s hosted MCP servers. They do not tell a developer to run `cloudflared` on a laptop. Do not merge that with quick tunnels. — [Build a Remote MCP server](https://developers.cloudflare.com/agents/model-context-protocol/guides/remote-mcp-server/)
- **Tailscale, frp, bore, localtunnel, Pinggy, zrok:** no first-party Claude, Cursor, or Grok doc opened in this pass tells the reader to use them for an agent. A third-party MCP roundup (2026-10-10) discusses Tailscale Funnel and claims failures with claude.ai; that is not an agent vendor’s doc and is not treated as usage. — [MCP Warp comparison](https://mcpwarp.io/blog/ngrok-alternative-for-mcp/)

### Inferences

- When an agent vendor has to name a way to publish a laptop port, the names that show up are ngrok and Cloudflare quick tunnels. That matches “public TLS URL the agent’s cloud can call,” not “join our VPN.”
- Anthropic’s first-party answer for a *private* MCP server is still Cloudflare’s connector, wrapped in Anthropic’s own proxy and access control. It is not Tailscale, and it is not a general public edge.
- Cursor assumes either stdio on the same machine or a URL you already have. It does not create demand for a specific tunnel in its own docs. Demand shows up in ngrok’s Cursor instructions and in Grok’s connector doc.
- Dev tunnels are the path of least resistance inside VS Code, including Copilot’s editor, but the port-forwarding doc is about humans sharing a port, not about an agent protocol.
- Tailscale Serve is a good fit for agents that already run on a machine in the tailnet. Nothing in the agent docs opened here tells users to do that.

### Gaps

- Claude Code’s local CLI docs were not opened as a separate page. The platform MCP-tunnels overview is the Anthropic page that names `cloudflared`. Whether Claude Code’s docs also name ngrok was not checked beyond ngrok’s own guide.
- OpenAI / ChatGPT connector docs were not opened. ngrok claims ChatGPT as a client; that claim was not confirmed on an OpenAI page.
- No agent doc was found that names dev tunnels, Tailscale, or frp. That absence is only as good as the pages searched.
- The MCP Warp “Enterprise only” and “Funnel fails with claude.ai” claims were not verified and conflict, on the Enterprise point, with the Anthropic overview that was opened.

## What do these tools not do from the brief?

### Takeaway

Against the seven-point brief, this set covers local port forwarding and, for the managed products, a public TLS edge. Private exposure and some auth exist. An admin audit trail exists only in pieces and is often paid or short-lived. None of them is git-backed project storage, an inbox, or a userspace text protocol that any harness can speak.

### Cited Findings

- **(1) Real-time encrypted storage with a git front end.** None of the product pages opened — ngrok about and pricing, Cloudflare quick tunnels, Tailscale Serve and Funnel, dev tunnels overview and security, VS Code port forwarding, frp’s GitHub description — describe a git remote, a repository, or a document store. Tailscale can connect you to a git server you run; it does not host one. Cloudflare Workers and R2 are separate products and were not part of the tunnel docs used here. — [About ngrok](https://ngrok.com/about); [Tailscale Funnel](https://tailscale.com/kb/1223/funnel); [What are dev tunnels?](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/overview)
- **(2) IP address and port forwarding for local services.** This is the core job. ngrok forwards HTTP and TCP (TLS endpoints on Pay-as-you-go). Cloudflare quick tunnels forward one local HTTP URL. Tailscale Serve and Funnel proxy a local port, or serve files, on `*.ts.net`. Dev tunnels host one or more local ports (up to 10 per tunnel). frp is a reverse proxy for a local server. — [ngrok pricing](https://ngrok.com/pricing); [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/); [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve); [Dev tunnels security](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/security)
- **(3) A public TLS edge.** ngrok assigns an HTTPS dev domain and terminates TLS (interstitial on Free). Cloudflare quick tunnels mint `https://….trycloudflare.com`. Funnel is TLS-only on 443/8443/10000, still beta on the 2026-01-20 page. Dev tunnels upgrade web clients to HTTPS and terminate TLS at Azure. frp does not include a vendor-operated public TLS edge. bore, per a secondary source only, is raw TCP. — [ngrok pricing](https://ngrok.com/pricing); [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/); [Tailscale Funnel](https://tailscale.com/kb/1223/funnel); [Dev tunnels security](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/security)
- **(4) Email inbox and group inbox / messaging.** Not found in any tunnel doc opened. Cloudflare Zero Trust role tables mention Email security as another Cloudflare product, which is not an inbox inside Tunnel, Serve, ngrok, or dev tunnels. — [Cloudflare One roles](https://developers.cloudflare.com/cloudflare-one/roles-permissions/)
- **(5) Easy auth and team management.** Partial, and not uniform. Dev tunnels are private to the creating account by default, with tenant and GitHub-org grants. Tailscale Serve uses tailnet membership, ACLs, and identity headers; Funnel has no visitor login. ngrok’s free plan is one user and an interstitial, not team SSO; SSO/RBAC and SCIM are paid add-ons. Cloudflare Access is a full IdP-backed team gate for self-hosted apps, while quick tunnels are public unless the operator passes `--allowed-mail`, and that PIN flow does not work for non-interactive agents. “Easy” is true for dev tunnels’ default and for Tailscale if the team is already a tailnet. It is not true for a stock public ngrok or quick-tunnel URL. — [Dev tunnels security](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/security); [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve); [ngrok pricing](https://ngrok.com/pricing); [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
- **(6) An audit trail for an admin view.** Partial. ngrok: Traffic Inspector for 24 or 72 hours on self-serve plans; account audit logs only inside the $15/user governance add-on. Cloudflare: account audit logs described as 18 months, plus Access logs whose retention on Free is 24 hours (logs page last updated 2026-10-15). Tailscale: configuration and network-flow log *streaming* on Premium and Enterprise (doc last validated 2026-02-02); actor names in flow logs announced 2026-02-20. Dev tunnels: “Tunnel inspection” in browser DevTools is the overview’s feature; the security page does not describe a retained admin audit log of who connected. frp has whatever logs the operator configures. — [ngrok pricing](https://ngrok.com/pricing); [Zero Trust logs](https://developers.cloudflare.com/cloudflare-one/insights/logs/); [Log streaming](https://tailscale.com/docs/features/logging/log-streaming); [What are dev tunnels?](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/overview)
- **(7) Runs in userspace as a subprocess of any harness, with a text protocol interface.** Each managed tool has a userspace agent a human or script can spawn: `ngrok`, `cloudflared`, `tailscale`, `devtunnel`. That is not the brief. The interfaces found are product CLIs and product protocols (ngrok’s local agent and YAML traffic policy, cloudflared’s tunnel protocol to Cloudflare on 7844, Tailscale’s userspace WireGuard client, dev tunnels’ Azure relay). None of the docs opened describe a single text protocol that an arbitrary harness uses to drive storage, mail, auth, and audit. ngrok’s MCP server is an MCP endpoint for the ngrok account, invite-only as of 2026-10-29, not a harness protocol. — [ngrok pricing](https://ngrok.com/pricing); [Claude MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview); [ngrok MCP server](https://ngrok.com/docs/mcp-server)

### Inferences

- A buyer who only needs “agent on the internet, call my laptop port over HTTPS” is choosing among ngrok, Cloudflare quick or named tunnels, Tailscale Funnel, and dev tunnels. The rest of the brief is not why those tools are adopted.
- The closest accidental overlap with “team auth plus an admin trail” is Cloudflare Access in front of a named tunnel, or a paid ngrok account, or a Tailscale tailnet using Serve rather than Funnel. Each still stops at the network edge. None stores the project or the conversation.
- Shipping as a subprocess is necessary but not sufficient for brief item 7. These agents are tunnels. They are not a sidecar API.

### Gaps

- ngrok’s local agent API (the inspection API on localhost) was not opened as its own page. It might be scriptable. It was not found described as a harness-agnostic text protocol, and it should not be upgraded to one without that page.
- Cloudflare Email Routing and Email security were not reviewed. They are out of scope for the tunnel product even if the company has them.
- No doc was found that adds git storage or an inbox to Funnel, Serve, dev tunnels, or frp. The gap is the missing feature, not a missing search hit inside those products.
