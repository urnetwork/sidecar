# Recursive feedback loops for AI agents (eval, trace, review, memory)

Scope is product and research reality as of 2026-10-31. 2023 papers are labeled as such and are not treated as evidence that those loops still compound on 2025–2026 agents. Every cited finding below is from a page opened in this pass. Search-only excerpts that were not fetched are in Gaps, not findings.

## What eval, trace, and observability products exist, and which loop does each close?

### Takeaway
The leading 2025–2026 platforms close the same engineering loop: capture a trace, score it (code, LLM judge, or human), turn failures into a dataset, rerun an experiment, and gate regressions. They do not, on the pages opened, write improved weights or durable agent memory by themselves. A newer class of harnesses (Inspect, Claude Code, OpenHands) closes a different loop: the agent acts, an external check or a second judge looks at evidence, and the run continues or stops.

### Cited Findings
- LangSmith’s own evaluation-page promise is “Evaluate and test agent quality at scale with datasets, evaluators, prompts, and Studio.” The same page says “Add real traces to a dataset so a failure you saw once becomes a test you run every time.” Offline eval runs curated datasets before ship; online eval scores live traffic. Evaluators listed are human review, code rules, LLM-as-judge, and pairwise comparison. The online path ends in an explicit step: “Establish a feedback loop” by adding failing production traces to the dataset, creating targeted evaluators, validating fixes offline, and redeploying. Audience is teams already tracing agents into LangSmith (account at smith.langchain.com). — [LangSmith Evaluation](https://docs.langchain.com/langsmith/evaluation)
- LangSmith hosting, opened separately: Cloud (LangChain runs it; “sensitive data” lives in LangChain’s cloud), Bring Your Own Cloud (data in your VPC, LangChain runs the control plane), and Self-hosted (you run observability, evaluation, and prompt engineering). Self-hosted and BYOC are Enterprise. A hybrid option keeps traces and evaluations on SaaS while agent workloads stay in your infrastructure. — [Set up LangSmith](https://docs.langchain.com/langsmith/platform-setup)
- Langfuse’s docs overview: “Langfuse is an open-source AI engineering platform … that helps teams collaboratively debug, analyze, and iterate on their AI agent applications.” It is “open, self-hostable, and extensible.” The page’s “AI Engineering Loop” is Trace → Monitor (dashboards, LLM-as-judge, feedback) → Build datasets → Experiment (prompts, models, code variants) → Evaluate (judges, custom evals, annotation). Traces cover LLM and non-LLM calls, sessions, and agent graphs, via SDKs, “100+” integrations, OpenTelemetry, or a gateway such as LiteLLM. — [Langfuse Overview](https://langfuse.com/docs)
- Langfuse evaluation page: “Evals give you a repeatable check of your LLM application’s behavior. You replace guesswork with data, and catch regressions before you ship a change.” Online scoring is on live traces; offline experiments compare changes before ship. Concrete loop pieces include annotation queues, user feedback, datasets, side-by-side experiments, code evaluators, managed LLM-as-a-judge, and a GitHub Action (`langfuse/experiment-action`) that fails a pull request when a score violates a threshold, on Cloud or self-hosted. It also documents checking that an LLM judge agrees with human labels. — [Langfuse Evaluation Overview](https://langfuse.com/docs/evaluation/overview)
- Langfuse self-host page (v4): “Langfuse is open source and can be self-hosted using Docker on your own infrastructure.” Options are Cloud, Docker Compose “for local use and testing” (single VM, no HA), and production Kubernetes/AWS/Azure/GCP. “Langfuse only depends on open source components and can be deployed locally, on cloud infrastructure, or on-premises.” “Internet access is optional.” Observability data is stored in ClickHouse; raw events in S3/blob; Postgres for transactional data. Vendor scale claim on that page: “Langfuse processes 90B+ observations per month and is trusted by 21 of the Fortune 50. Its Docker images have been pulled 38M+ times.” Some features still call an LLM API (playground, evaluations). Some add-ons need a license key. — [Self-host Langfuse](https://langfuse.com/self-hosting)
- Braintrust’s evaluate page promise: “Measure AI application quality, detect regressions before they reach production, and build confidence that your system is improving over time.” Anatomy is Data, Task, and Evaluators (scorers and classifiers; autoevals, LLM-as-a-judge, or custom code). The cycle is: iterate in playgrounds → promote an immutable experiment → automate in CI/CD → score production traces → “Feed back — Pull interesting production traces into datasets.” On online scoring it says, in its own words, “Because there’s no ground truth for live requests, it relies on LLM-as-a-judge scorers.” — [Braintrust Evaluate](https://docs.braintrust.dev/evaluate/index.md)
- Arize Phoenix tracing overview: “Phoenix traces AI applications, via OpenTelemetry and has first-class integrations with LlamaIndex, LangChain, OpenAI, and others.” It accepts OTLP and lists DSPy among instrumented frameworks. Features named on that page: projects, sessions, annotations (“feedback, labels, and scores”), and metrics (latency, tokens, errors). Next step offered is “Run Evaluations — Score your traces with LLM-as-a-judge evaluators.” The quickstart says you need “a running Phoenix” and then `register(...)` so spans (prompt, response, tokens, latency) show up in a project. It also points at a CLI/MCP path and an in-product assistant (“why did this trace fail?”). Who it is for: anyone instrumenting an LLM app, not tied to one model vendor. — [Phoenix tracing overview](https://arize.com/docs/phoenix/tracing/llm-traces); [Phoenix observe quickstart](https://arize.com/docs/phoenix/get-started/get-started-tracing)
- W&B Weave, now documented on CoreWeave: “W&B Weave is an observability and evaluation platform for building reliable agents and LLM applications. Weave helps you understand what your AI application is doing, measure how well it performs, and systematically improve it over time.” Capabilities: agent-session visibility, systematic evaluation, version tracking of prompts/models/data, playground experiments, human feedback, and “Monitoring in production using guardrails and scorers.” Agent tracing is OpenTelemetry plus GenAI semantic conventions; Claude Code and the OpenAI Agent SDK are named as auto-instrumented harnesses. The same page says agent-tracing workflows “are also available in CoreWeave Agent Lens, the successor to Weights & Biases Weave,” and that “Both services already receive your agent tracing data, so there is nothing to migrate.” Getting started requires a CoreWeave Forge account and API key. — [What is Weave?](https://docs.coreweave.com/weave/concepts/what-is-weave)
- Inspect (UK AI Security Institute and Meridian Labs), opened 2026-10-31 via the current docs index: “Inspect is a framework for frontier AI evaluations.” One-line shape: a Task is a dataset, a solver (from one `generate()` call up to an agent), and a scorer. It ships “over 200 pre-built evaluations,” a local `inspect view` log UI, and can run external agents “like Claude Code, Codex CLI, and Gemini CLI.” The built-in `react()` agent is a reason-act-observe loop “until it submits an answer,” with an `attempts` cap (the CTF example uses 3) and `sandbox="docker"`. Local model paths exist (Hugging Face, vLLM, SGLang) as well as hosted APIs. This is a harness-eval tool, not a production trace SaaS. — [Inspect welcome](https://inspect.aisi.org.uk/index.html.md)

### Inferences
- “The loop” these observability vendors sell is a human-or-CI development loop over traces, not an agent that gets better weights overnight. The compounding step is always the same: a scored failure becomes a regression test. Without that dataset write-back, tracing is a debugger.
- Online scores are explicitly reference-free on Braintrust and are LLM-judged on LangSmith and Langfuse. That closes a monitoring loop only as well as the judge matches a human. Langfuse is the one of these pages that also documents calibrating the judge against human labels and failing CI on a threshold.
- Weave’s docs now treat Agent Lens as the successor while still documenting Weave. Comparing “Weave” in late 2026 means checking whether a team is on the CoreWeave product, not the 2024 W&B brand alone.
- Inspect closes a different loop (task, attempt, score, log) that can wrap Claude Code or Codex. It is the harness METR itself moved onto (see the METR section below), so it is load-bearing for public agent evals, not a niche library.

### Gaps
- Phoenix deployment was not confirmed on a page opened here. The quickstart says “a running Phoenix” and points at a Start Phoenix page that was not fetched. Do not treat Phoenix as verified local-only or verified cloud-only from this pass.
- Braintrust self-hosting appeared in search (Enterprise data plane in the customer’s cloud, Braintrust-hosted control plane; SDK traffic to the data plane) but that architecture page was not fetched. Not used as a finding.
- Homepages were not opened separately from docs, so the “one-line promise” above is the docs’ own lede, not an ad headline.
- Other products often named in this category (Helicone, LangWatch, Maxim, Patronus, Humanloop, Galileo, Promptfoo, DeepEval) were not opened.

## What coding-agent feedback loops are documented?

### Takeaway
Documented coding loops that can compound are outer loops with an external oracle: hidden tests (SWE-bench), the agent rerunning the test suite (Claude Code), or a second model that may only mark done after it sees command output (OpenHands `/goal`). The agent deciding it is finished is treated, in the OpenHands docs, as not sufficient.

### Cited Findings
- SWE-bench leaderboard page, opened 2026-10-31: each entry is “% Resolved, the percentage of task instances solved.” Splits stated on the page: original SWE-bench “2294 instances” from “12 Python repositories”; Verified “500 instances,” “A human-filtered subset of SWE-bench”; Bash Only “500 instances,” “every model in the same mini-SWE-agent environment”; Lite 300; Multilingual 300 across “42 repositories” and “9 programming languages”; Multimodal “480 instances.” News on that page: “Jul 2025 mini-SWE-agent scores 65% on SWE-bench Verified in 100 lines of Python.” Also listed: ProgramBench (May 2026), CodeClash (Nov 2025), SWE-smith (May 2025). The rendered page did not include a current model ranking; it is a checkbox UI (“No models selected”). — [SWE-bench Leaderboards](https://www.swebench.com/)
- Claude Code docs: “When you give Claude a task, it works through three phases: gather context, take action, and verify results.” The documented bug-fix cycle is run the tests, read the error, search and read source, edit, “Run the tests again to verify.” “Claude Code is the layer around the model that provides the tools and manages the context the model sees. This surrounding layer is what the term agentic harness refers to.” The user “can interrupt at any point.” Default execution is local, with the project, terminal, and git state. Cloud runs on “Anthropic-managed VMs, or self-hosted environments your organization operates.” Remote Control keeps execution on the user’s machine. — [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)
- Same Claude Code page, on what persists: “Each new session starts with a fresh context window, without the conversation history from previous sessions.” Auto memory: “The first 200 lines or 25KB of MEMORY.md, whichever comes first, load at the start of each session.” CLAUDE.md is the user-written persistent instruction file. Compaction “keeps your requests and key code snippets, but detailed instructions from early in the conversation may be lost.” Sessions are local JSONL under `~/.claude/projects/`. Checkpoints snapshot files before edits; “Actions that affect remote systems (databases, APIs, deployments) can’t be checkpointed.” — [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)
- OpenHands goal-completion docs: “A plain `conversation.run()` stops as soon as the agent thinks it is done.” `/goal` “asks a second judge LLM to audit the transcript for authoritative evidence — file contents, command output, test results — that the objective is provably complete.” If not, it “re-prompts the agent with the judge’s feedback.” The worked example is complete only when `python -m pytest -q` passes: “the agent cannot finish just by claiming success — the judge has to see the green output first.” Default `max_iterations` is 10. If the judge’s JSON cannot be parsed, “the verdict falls back to `score=0.0, complete=False` so the loop keeps working rather than falsely finishing.” A critic refines inside one `run()`; `/goal` decides whether another run happens. The loop does not fork a sidecar conversation. — [OpenHands Goal Completion Loop](https://docs.openhands.dev/sdk/guides/convo-goal.md)
- METR, 29 January 2026, is a benchmark-author note on the outer loop’s infrastructure, not a coding product: they moved time-horizon evals “from Vivaria to Inspect” and changed the task suite partly because some tasks were “easy to reward-hack, or the scoring function had errors.” They removed 15 tasks and updated 53. Suite size went from 170 to 228 tasks; tasks estimated at 8 hours or more went from 14 to 31. They write that “we measured human baseline times for only 5 of our 31 long (8h+) tasks. The remainder use estimated times.” — [METR Time Horizon 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)

### Inferences
- SWE-bench’s loop is pass/fail against tests the agent is not supposed to see as the grader. The July 2025 mini-SWE-agent note is the benchmark authors saying a short agent loop plus that oracle is enough to reach the number they printed (65% resolved on Verified). That number is a 2025 news line on the homepage, not a late-2026 leaderboard.
- Claude Code’s verify step is real but model-chosen: nothing on the opened page forces the test command to pass before the model stops. OpenHands `/goal` is the explicit correction to that failure mode.
- Memory write-back in Claude Code is capped and session-local. A loop that “remembers how we fixed this” only compounds if someone put it in CLAUDE.md or it survived the 200-line / 25KB auto-memory window. Conversation traces do not automatically become the next session’s policy.

### Gaps
- Official pages for Codex, Cursor, Devin, and Factory review-and-iterate loops were not opened. Do not describe their loops from memory.
- The SWE-bench page did not render current scores. Third-party leaderboards found in search disagreed with each other by a wide margin (one board’s top figure was not another’s). None of those boards were fetched, and none are cited.
- The OpenAI SWE-bench Verified announcement linked from swebench.com was not opened.
- Claude Code hooks, PR bots, and CI review bots were not fetched. The Claude Code page only names hooks as an extension point.
- OpenHands stuck-detector and hooks pages showed up in search and were not fetched.

## What does the literature say a loop needs in order to compound?

### Takeaway
2023 papers showed gains from verbal self-critique, episodic text memory, and compiling a pipeline against a metric. A July 2026 paper on small open models finds those self-inspection loops lose to repeated sampling once token cost is equal, and that a self-judge can silently turn the loop off. Separately, METR’s 2026 task cleanup says outer-loop scores compound only if the scorer is not hackable and is not wrong.

### Cited Findings
- Reflexion (submitted 20 March 2023, revised 10 October 2023): agents “reinforce language agents not by updating weights, but instead through linguistic feedback.” They “verbally reflect on task feedback signals, then maintain their own reflective text in an episodic memory buffer” for the next trial. Feedback can be “scalar values or free-form language” and “external or internally simulated.” The abstract’s coding claim: “Reflexion achieves a 91% pass@1 accuracy on the HumanEval coding benchmark, surpassing the previous state-of-the-art GPT-4 that achieves 80%.” — [Reflexion](https://arxiv.org/abs/2303.11366)
- Self-Refine (submitted 30 March 2023, revised 25 May 2023): “generate an initial output using an LLM; then, the same LLM provides feedback for its output and uses it to refine itself, iteratively.” “Self-Refine does not require any supervised training data, additional training, or reinforcement learning, and instead uses a single LLM as the generator, refiner, and feedback provider.” Across 7 tasks with GPT-3.5, ChatGPT, and GPT-4, the abstract says outputs were preferred “improving by ~20% absolute on average in task performance.” — [Self-Refine](https://arxiv.org/abs/2303.17651)
- DSPy (submitted 5 October 2023): pipelines are “text transformation graphs” whose modules “can learn (by creating and collecting demonstrations) how to apply compositions of prompting, finetuning, augmentation, and reasoning techniques.” “We design a compiler that will optimize any DSPy pipeline to maximize a given metric.” The abstract’s case-study claim: within minutes, “a few lines of DSPy allow GPT-3.5 and llama2-13b-chat to self-bootstrap pipelines that outperform standard few-shot prompting (generally by over 25% and 65%, respectively) and pipelines with expert-created demonstrations (by up to 5–46% and 16–40%, respectively).” It also says the programs “control agent loops.” — [DSPy](https://arxiv.org/abs/2310.03714)
- Mirzaei, submitted 30 July 2026, “Sample More, Reflect Less”: methods that plan, criticise, rewrite, reflect, pick, or debate “nearly all make it generate far more text than a single chain of thought,” so a gain over one chain of thought “does not show the method’s idea is what helped.” Experiment: seven methods, open models of 1.5B, 3B, and 7B, two math benchmarks, 150 questions each, every token counted, 36 paired comparisons. “No method is reliably better than repeated sampling at equal cost anywhere. Ten are reliably worse, all of them methods where the model inspects its own output, and all 18 self-inspection comparisons are negative.” “Self-Refine and a forced Reflexion stay 3.6 to 10.1 points below baseline at 7B.” “Reflexion as published never triggered its own retry on the smallest model. It judged itself correct every time and silently became a single chain of thought.” — [Sample More, Reflect Less](https://arxiv.org/abs/2607.28576)
- METR, 29 January 2026, on what breaks an outer loop: task descriptions that were confusing, tasks “easy to reward-hack,” and scoring functions that “had errors” were modified or removed. Post-2023 50% time-horizon doubling time is stated as “130.8 days [107, 161]” under TH1.1 versus “165.3 days [129, 211]” under TH1. Since 2024, “108.9 days” under TH1 and “88.6 days” under TH1.1. Full-period stitched doubling time is “196.5 days,” described as the same 7-month doubling as TH1’s “195.8 days [162, 223].” Model table, in minutes: Claude Opus 4.5 moved from “289 [110,1268]” to “320 [170,729]” (+11%); GPT-5 from “138 [68,281]” to “214 [117,480]” (+55%). These are capability measurements on software and research tasks, not a product feedback loop. — [METR Time Horizon 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)
- Braintrust, on the missing oracle for production loops: “Because there’s no ground truth for live requests, it relies on LLM-as-a-judge scorers to assess quality.” — [Braintrust Evaluate](https://docs.braintrust.dev/evaluate/index.md)
- OpenHands documents one engineering response to false completion: require “authoritative evidence,” and if the judge output is unparsable, do not treat the goal as done. — [OpenHands Goal Completion Loop](https://docs.openhands.dev/sdk/guides/convo-goal.md)

### Inferences
- A loop compounds in these sources only when the feedback is not the actor grading itself and the metric cannot be satisfied by a shortcut. External signals that qualify: unit tests, a held-out scorer, a metric DSPy can optimize, or a second model reading command output. Reflexion’s 2023 HumanEval gain used task feedback; the 2026 result says a self-check of “am I correct?” can refuse to fire.
- The 2023 absolute gains (about 20 points; 91% vs 80% on HumanEval; DSPy’s “over 25% and 65%”) are the papers’ own averages on the models of that year. They are not a 2026 product claim. The 2026 counter-result is narrow: open models at 1.5B–7B, math questions, equal token budget. It does not by itself refute test-based coding loops, which spend tokens on tool output rather than on self-critique.
- DSPy is the paper that makes the metric a compiler target. That is a different write-back from Reflexion’s text memory: the artifact that improves is the pipeline’s demonstrations or weights, and only if the metric is the thing you actually care about.
- Stale or dropped memory is documented as a product behavior, not only a paper risk: Claude Code drops prior-session transcripts and compacts early instructions. METR’s reward-hacking note is the analogous failure for test-based outer loops: if the score can be gamed, “improvement” is fake.
- Human review is a required calibrator on the Langfuse and Hamel pages (next section), and a bottleneck only in the sense that those pages treat uncalibrated judges as unsafe. No opened source gave a measured review-queue wait time.

### Gaps
- DSPy Assertions / runtime self-refine constraints were not opened (a 2024–2026 paper mentioning them appeared in search only).
- No opened paper directly measures “memory write-back” quality decay (stale or contradictory notes) on a 2025–2026 coding agent. The Claude Code caps are the closest primary product evidence.
- The original Wang et al. (2024) sampling-baseline paper cited by Mirzaei was not opened.

## Which loops are local or private, and which send prompts and traces off-machine?

### Takeaway
“Local” splits in two. The agent harness and the repo can stay on the machine (Claude Code default, Inspect, OpenHands workspace, a self-hosted Langfuse). The model call still leaves the machine unless a local model is used. Trace platforms default to a vendor cloud; LangSmith and Langfuse document a path where the trace store stays in the user’s infrastructure, and LangSmith says that path is Enterprise for self-host and BYOC.

### Cited Findings
- LangSmith: Cloud stores sensitive data in “LangChain’s cloud.” BYOC keeps it in “Your VPC” while LangChain runs the control plane. Self-hosted is “Full control … in your infrastructure.” Self-hosted and BYOC “are available on the Enterprise plan.” Hybrid can keep “Traces and evaluations” on SaaS while agents stay in the VPC. The evaluation quickstart path is an account and API key at smith.langchain.com, so the default loop sends traces off-machine. — [Set up LangSmith](https://docs.langchain.com/langsmith/platform-setup); [LangSmith Evaluation](https://docs.langchain.com/langsmith/evaluation)
- Langfuse: Docker Compose for local use, or Kubernetes/on-prem. “Internet access is optional.” Traces go to ClickHouse and blob storage the operator runs. Evaluations and the playground can still call an LLM API. — [Self-host Langfuse](https://langfuse.com/self-hosting)
- Weave: setup is a CoreWeave Forge account and `weave.init('<your-team>/<your-project>')`. The page states Agent Lens and Weave “already receive your agent tracing data.” No self-host option was on the page opened. — [What is Weave?](https://docs.coreweave.com/weave/concepts/what-is-weave)
- Inspect: `pip install inspect-ai`, logs opened with `inspect view` on the machine running the eval. Sandboxes include Docker and Kubernetes. Model calls use provider API keys, or local inference “with HuggingFace, vLLM, and SGLang.” External agents (Claude Code, Codex CLI, Gemini CLI) run inside that harness, so where the prompt goes depends on which model those agents call. — [Inspect welcome](https://inspect.aisi.org.uk/index.html.md)
- Claude Code: local is “Default. Full access to your files, tools, and environment.” Session transcripts are plaintext JSONL on the machine. Cloud tasks run on Anthropic-managed VMs or org-operated self-hosted environments. The opened page does not say model prompts stay on-machine in local mode; it says code execution does. Auto memory and CLAUDE.md are local files. — [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)
- OpenHands `/goal`: the example workspace is a local temp directory; the agent and the judge are separate LLM clients. Tool evidence (pytest output) is in the conversation on that workspace. The judge call is still a model API call. — [OpenHands Goal Completion Loop](https://docs.openhands.dev/sdk/guides/convo-goal.md)
- SWE-bench, as described on its leaderboard: resolution is computed by the benchmark harness (bash-only runs everyone in mini-SWE-agent). That is an offline, repo-and-test loop. Where model traffic goes is not stated on the page opened. — [SWE-bench Leaderboards](https://www.swebench.com/)
- METR’s 2026 eval stack is Inspect, which they adopted as “a widely-adopted open-source framework,” replacing their in-house Vivaria. That is a local-or-self-hosted harness story for a public benchmark, not a trace SaaS. — [METR Time Horizon 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)

### Inferences
- A private sidecar that keeps context, messages, and audit on the user’s side is closer to self-hosted Langfuse plus a local harness (Claude Code local, Inspect, OpenHands) than to default LangSmith Cloud or Weave. The gap those cloud products fill is the dataset/experiment/CI loop, not storage locality.
- “Traces stay local” does not imply “the prompt never left.” Every hosted-model agent still sends the working context to the model API. Only Inspect’s local-inference path, and Langfuse’s optional air-gapped deploy, are documented as ways to avoid that for the eval or trace system itself.
- Braintrust and Phoenix locality are unresolved in this pass (see Gaps).

### Gaps
- Phoenix Cloud versus local Docker was not established from a fetched page.
- Braintrust’s data-plane self-host docs were not fetched. Search excerpts describe an Enterprise split (SaaS control plane, customer data plane). Treat that as unverified here.
- No opened page audits whether Claude Code local mode redacts secrets before the model call. Checkpoints explicitly do not cover remote side effects.
- Encryption-at-rest and customer-managed keys were not compared across vendors.

## What do practitioners say, in 2025–2026, about why pilots fail to compound?

### Takeaway
The opened 2026 practitioner and lab sources do not blame the model first. They blame a metric that is not the real failure, a judge the team has not checked against humans, a self-check that never fires, and a score the agent can satisfy without doing the work. The loop stalls when the next run is not forced to face a harder, specific, external test built from the last failure.

### Cited Findings
- Hamel Husain, 3 March 2026: coding agents can instrument apps and run experiments, but “an agent with an eval platform still needs to know what to do with it.” His example is two different failures both called “hallucination” (“your plan includes free returns” versus “I’ve canceled your order”). “If you lump them together in a generic ‘hallucination score’ real problems will likely go undetected.” He says the useful work is error analysis, binary pass/fail judges, validating judges against human labels with TPR/TNR, and a human review interface. He distinguishes product evals from “foundation model benchmarks like MMLU or HELM.” He points at vendor MCP servers (Braintrust, LangSmith, Phoenix) as access to traces, not as the eval design. — [Evals Skills for Coding Agents](https://hamelhusain.substack.com/p/evals-skills-for-coding-agents)
- A comment on that post dated 14 October 2026, by Rafael Ibayev, states a coding-agent failure mode in the commenter’s own words: the useful signal is “process-level, not just pass/fail on the output: did it stay in scope, did it run the tests or just claim it did. A green final result can hide a pretty messy path.” That is a reader of the post, not Hamel’s measurement. — [Evals Skills for Coding Agents](https://hamelhusain.substack.com/p/evals-skills-for-coding-agents)
- Hamel attributes to an OpenAI “Harness Engineering” article the claim that “improving the infrastructure around the agent yielded better returns than improving the model,” and that agents “queried distributed traces to verify their own work against runtime evidence.” The article’s headline numbers as Hamel prints them (“~1 million lines of code, 1,500 PRs, three engineers, five months”) were not checked against the OpenAI page. Do not treat those figures as verified. The infrastructure-over-model claim is his summary of a page this pass did not open. — [Evals Skills for Coding Agents](https://hamelhusain.substack.com/p/evals-skills-for-coding-agents)
- METR, 29 January 2026, is a primary lab writeup of a loop that stopped meaning what it measured: they removed or rewrote tasks that were reward-hackable or whose scorers were wrong, and they warn that only 5 of 31 long tasks have measured human times. Doubling-time estimates move when the task set moves (post-2023 doubling 165 days versus 131 days). A pilot that “compounds” on a dirty scorer is the failure they spent the post correcting. — [METR Time Horizon 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)
- Mirzaei, 30 July 2026, is the research version of “the retry never happens”: Reflexion “judged itself correct every time and silently became a single chain of thought” on the smallest model, and self-rewrite stayed below equal-cost sampling at 7B. — [Sample More, Reflect Less](https://arxiv.org/abs/2607.28576)
- Vendor docs agree the production loop has no answer key. Braintrust: “there’s no ground truth for live requests.” Langfuse’s remedy on the page opened is human calibration of the judge plus a CI threshold, not another automatic score. — [Braintrust Evaluate](https://docs.braintrust.dev/evaluate/index.md); [Langfuse Evaluation Overview](https://langfuse.com/docs/evaluation/overview)
- Claude Code’s own docs are a product description of why a session does not compound: new session, empty transcript; compaction drops early instructions; auto memory loads at most “200 lines or 25KB.” Persistent behavior is whatever was written into CLAUDE.md or survived that cap. — [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)

### Inferences
- “Pilots fail to compound” in these sources is not mainly “the model is weak.” It is that the feedback is generic, self-graded, or gameable, so the next run is not trained or tested on the last real miss. The vendor loop (trace → dataset → experiment → CI) is the proposed fix, and Hamel’s point is that the dataset labels have to name the actual failure or the CI gate protects the wrong thing.
- Human review is the ground truth these 2026 sources still require for judge calibration. That is a bottleneck whenever the team will not label, which Hamel treats as an eval-design problem. No opened source quantified how often review queues stall a rollout.
