# Incumbent bundling of agent infrastructure, 2025–2026 (state as of 31 Oct 2026)

Scope note: this covers platform moves that overlap the URnetwork agent sidecar's seven designed jobs: (J1) encrypted storage with a git front end for shared context and memory; (J2) IP and port forwarding for local services; (J3) a public TLS edge; (J4) an email inbox and group inbox or messaging shared by people and agents; (J5) auth and team management; (J6) an admin audit trail; (J7) running as a userspace subprocess of any harness, driven by a text protocol. Earlier rounds already covered the basics of Mem0, Letta, Zep, ngrok, Cloudflare Tunnel, Tailscale Funnel/Serve, dev tunnels, AgentMail/Resend, the audit-log basics of each vendor, MCP/ACP/A2A basics, and the Copilot Memory GA. Those are not repeated here.

Source conventions: "(search summary)" means the claim came from a search-engine summary of the named page, and I did not fetch the page myself. "(secondary)" means a non-vendor source used for a date or a claim the vendor's own pages did not confirm. Vendor statements about their own products are labelled "vendor claim" where they are promotional or unverifiable. openai.com/business/frontier returned HTTP 403 when fetched, so OpenAI Frontier details come from search summaries of openai.com pages and from InfoQ.

## Q1. GitHub: what it shipped and announced in 2025–2026, including Universe 2026 (28–29 Oct 2026)

### Takeaway
GitHub has built the most complete governance plane for multiple agents that sits next to a code host. Agent HQ ran Claude and Codex in public preview from February 2026, an enterprise "agent control plane" went GA on 26 Feb 2026, partner "agent apps" (GitHub Apps) arrived on 2 Jun 2026, and managed agent permissions went GA on 9 Sep 2026. All of it runs on GitHub's own runtime, billing and surfaces. Universe 2026 itself was about the Copilot app, Fusion, projects, automations and Enterprise licence bundling. The main Universe post did not mention third-party agents, identity, audit or networking.

**Firewall and private networking for the cloud/coding agent**
- The agent firewall is on by default and limits internet access to a default allowlist of GitHub and dependency hosts. Admins can add hosts in the repository's Copilot agent settings. GitHub warns that disabling it "will allow Copilot to connect to any host, increasing risks of exfiltration" — [GitHub Docs, firewall](https://help.github.com/en/copilot/customizing-copilot/customizing-or-disabling-the-firewall-for-copilot-coding-agent) (search summary)
- Private network reach exists through runner choice. The agent can run on self-hosted runners or on larger runners with Azure private networking, selected via `runs-on` in `.github/workflows/copilot-setup-steps.yml`. A change announced 13 Feb 2026 and effective 27 Feb 2026 routes inference by plan to `api.business.githubcopilot.com`, `api.enterprise.githubcopilot.com` or `api.individual.githubcopilot.com`, and those hosts must be reachable from such runners — [GitHub Changelog](https://github.blog/changelog/2026-02-13-network-configuration-changes-for-copilot-coding-agent/)

### Inferences
- GitHub's neutrality is limited to choosing which agent runs. Claude and Codex run as sessions GitHub hosts, bills (premium requests, now AI credits) and audits. Partner agents are GitHub Apps "powered by Copilot cloud agent". Managed permissions are documented only for Copilot surfaces. A Claude Code or Codex CLI session on a developer laptop is outside GitHub's control plane, except that usage metrics may count Copilot-model usage from tools like OpenCode.
- GitHub's agent identity is a GitHub App plus an `actor_is_agent` flag in the audit log, with a GitHub-issued JWT assertion for partner MCP servers. That is identity inside GitHub, not a portable identity an agent could use with email, other SaaS, or another harness.
- In this period GitHub shipped no messaging between agents and humans beyond issue and PR comments, @mentions and session continuity, no email, and no general port forwarding or public edge. Private network reach comes only through Actions runners the customer hosts or runs on Azure private networking.
- The control plane's own "looking ahead" list (VS Code and CLI session activity, programmatic access to agent activity) shows that, as of Feb 2026, audit of local agent sessions was still a gap even for Copilot's own harnesses.

## Q2. Anthropic: 2026 status of agent teams, Remote Control, cloud sandbox and network controls, Cowork, Claude Tag, the Compliance API, MCP tunnels and admin features

### Takeaway
Anthropic now bundles memory (Claude Tag channel memory, Projects), messaging (agent teams, cross-session messaging, Claude Tag in Slack), reach (Remote Control relay, self-hosted runners, MCP tunnels), team auth (custom roles, Claude Tag identities) and content-level audit (Compliance API session transcripts). Every piece works only for Claude sessions, and the coordination and audit paths run through Anthropic's own API. Organizations on zero data retention, HIPAA or customer-managed keys are excluded from most of the network-reach features.

### Cited Findings
**Coordinating multiple agents (Claude Code)**
- Claude Code offers five parallel-work modes. Subagents. Agent view ("Research preview"). Agent teams, described as "Multiple coordinated sessions with a shared task list and inter-agent messaging, managed by a lead. Experimental and disabled by default". Projects, described as "Public beta on Pro, Max, and Ultra", with threads in the cloud or on your computer through Remote Control. Dynamic workflows. The docs state: "In every approach the workers are Claude sessions. To involve a different tool, expose it to Claude as an MCP server." — [Claude Code Docs, Run agents in parallel](https://code.claude.com/docs/en/agents)
- In cloud sessions, agent teams are enabled with `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` — [Claude Code Docs, cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- Cross-session messaging lets Claude message "your other Claude Code sessions". On the same machine it uses a per-session Unix socket or named pipe, "never through Anthropic servers". To another of your machines it goes "Through Anthropic servers, arriving over that machine's Remote Control connection". To a cloud session it goes "Through Anthropic servers". Messages are plain text only. Reaching beyond the machine requires a claude.ai sign-in and is unavailable with an API key or on Bedrock, Claude Platform on AWS, Google Cloud's Agent Platform or Microsoft Foundry. Admins can disable it org-wide with managed settings (`deny: SendMessage, ListAgents` and `crossSessionInbound: refuse`). It requires Claude Code v2.1.224+. The page gives no launch date — [Claude Code Docs, cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging.md)

**Remote Control**
- Remote Control was announced around 24–25 Feb 2026 as a research preview ([Simon Willison, 25 Feb 2026](https://simonwillison.net/2026/Feb/25/claude-code-remote-control/); [DevOps.com](https://devops.com/claude-code-remote-control-keeps-your-agent-local-and-puts-it-in-your-pocket)) (secondary, dates)
- Current docs: available on Pro, Max, Ultra, Team and Enterprise. API keys are not supported. On Team and Enterprise an Owner must enable it. "Your local Claude Code session makes outbound HTTPS requests only and never opens inbound ports on your machine… All traffic travels through the Anthropic API over TLS." It is unavailable when a session uses Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, or an `ANTHROPIC_BASE_URL` pointing at "an LLM gateway or proxy". Orgs with zero data retention (ZDR) or the HIPAA configuration "can't enable Remote Control". There is an optional "Trusted Devices" requirement — [Claude Code Docs, Remote Control](https://code.claude.com/docs/en/remote-control.md)

**Claude Code cloud sessions (Claude Code on the web) and network controls**
- Claude Code on the web launched in Oct 2025 as a research preview for Pro and Max — [Gigazine, 21 Oct 2025](https://gigazine.net/gsc_news/en/20251021-anthropic-claude-code-web-app/) (secondary, date)
- Cloud sessions are now available on Pro, Max, Ultra and Team, and for Enterprise premium or Chat + Claude Code seats. "Organizations that use customer-managed encryption keys (CMEK) can't start cloud sessions". ZDR and HIPAA orgs cannot use cloud session features. The docs warn that "When running with network access disabled, Claude Code can still communicate with the Anthropic API, which may allow data to exit the VM" — [Claude Code Docs, cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- Network access levels per environment are **None**, **Trusted** (the default: package registries, GitHub, cloud SDKs), **Full** and **Custom** (your own allowlist). MCP connector traffic "travels through Anthropic's servers rather than the session's network". "Network secrets" are attached by an agent proxy, so the session never sees them, and CMEK orgs cannot save them — [Claude Code Docs, cloud environments](https://code.claude.com/docs/en/cloud-environments.md)
- **Self-hosted environments** are in public beta on Team and Enterprise, off by default. Runners inside the customer network poll `api.anthropic.com` outbound ("Anthropic never connects into your network"), and sessions "can reach internal services, databases, and registries without exposing them to the public internet". However, "The conversation itself, including prompts, responses, and tool results, goes to `api.anthropic.com`, and Anthropic stores the session transcript", and "the control plane remains Anthropic-hosted". This is unavailable to ZDR and HIPAA orgs — [Claude Code Docs, self-hosted environments](https://code.claude.com/docs/en/self-hosted-environments.md)

**MCP tunnels**
- Status: research preview, "as-is" with no uptime, support or continuity commitment, and access by request. They are available for the Claude API (Messages API and Managed Agents). "MCP tunnels created through the Console are not available as connectors in claude.ai." Not eligible for ZDR or HIPAA. Architecture: cloudflared plus Anthropic's proxy inside the customer network, outbound-only, one hostname per MCP server under a `*.tunnel.anthropic.com` domain. Inner TLS runs "from Anthropic's back end to your proxy" with a certificate only the customer holds, so "Cloudflare cannot read request or response payloads". Cloudflare does see the egress IP, a host fingerprint, timing, byte volume and the subdomain, and is a subprocessor. The tunnel "does not authenticate" to MCP servers, so each server needs its own OAuth — [Claude Platform Docs, MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview)
- A claude.com connectors version of the docs reportedly describes MCP tunnels as available to Claude Enterprise organizations by request through the account team — [claude.com docs](https://claude.com/docs/connectors/mcp-tunnels/overview) (search summary). One third-party site gives a release date of 19 May 2026 ([BibiGPT](https://bibigpt.co/features/claude-mcp-tunnels-explained)). This is unverified.

**Cowork and Dispatch**
- Cowork launched 12 Jan 2026 as a research preview for Max subscribers on macOS. Dispatch (texting tasks from a phone to the desktop agent) followed in Mar 2026 — [DataCamp](https://www.datacamp.com/tutorial/claude-cowork-dispatch) (secondary, dates)
- Cowork became generally available on all paid plans on macOS and Windows on 9 Apr 2026, with Enterprise RBAC, group spend limits, usage analytics and expanded OpenTelemetry — [Claude blog, Cowork for enterprise](https://claude.com/blog/cowork-for-enterprise); [The New Stack](https://thenewstack.io/anthropic-takes-claude-cowork-out-of-preview-and-straight-into-the-enterprise/) (search summaries). Anthropic later announced a unified chat-plus-Cowork Claude Enterprise as GA (date not found) — [Claude blog](https://claude.com/blog/unified-claude-enterprise) (search summary)
- Cowork scheduled tasks run only while the computer is awake and the desktop app is open — [DataCamp](https://www.datacamp.com/tutorial/claude-cowork-dispatch) (secondary)

**Claude Tag (Slack)**
- 23 Jun 2026, **beta**, for Enterprise and Team. Claude joins a Slack workspace "as a team member", and admins grant channels, tools, data and codebases. Claude "builds context by remembering relevant information from the channels it's in". Admins can create "separate Claude identities for different uses", each with memories scoped to its channels. Admin controls cover tools and information per channel, token spend limits per org and per channel, and "a log of Claude's actions along with who requested each task". An optional "ambient mode" lets Claude act without a new request. It is Slack-only at launch and replaces the Claude in Slack app. Vendor claim: Anthropic's internal version creates 65% of its product team's code — [Anthropic, Introducing Claude Tag](https://www.anthropic.com/news/introducing-claude-tag)
- Claude Tag runs on the same cloud infrastructure as Claude Code cloud sessions ([Claude Code Docs](https://code.claude.com/docs/en/claude-code-on-the-web.md)). Its channel sessions can run in self-hosted environments, where "the owner is the Claude Tag agent", an agent identity rather than a user account ([Claude Code Docs, self-hosted](https://code.claude.com/docs/en/self-hosted-environments.md))

**Compliance API and audit**
- Enterprise organizations get full access (Activity Feed plus chats, files, projects, sessions, users and org settings) with a Compliance Access Key. Standalone Console organizations get the Activity Feed only. The Activity Feed keeps 6 years of activity, is queryable within 1 minute, and "does not capture the prompt text or model responses" — [Claude Platform Docs, Compliance API FAQ](https://platform.claude.com/docs/en/manage-claude/compliance-faq)
- New beyond the earlier round's "no chat content" finding: the session endpoints return **transcripts** (user prompts, assistant responses, tool calls and results, truncated to 10,000 bytes by default) for Claude Code sessions in the terminal, Desktop or IDE and for Cowork sessions, both local and cloud, while users are signed in with an Enterprise account. Local sessions "are captured as their requests reach the Claude API, so nothing is installed on the device, and on-device activity that never reaches the API is not captured". Not captured: Claude Code with a Console API key, Claude Code on Bedrock, Google Cloud or Foundry, Claude Code cloud sessions, and cloud routines. "No Compliance API endpoint lists an organization's Cowork scheduled tasks or Claude Code routines." — [Claude Platform Docs, Compliance API FAQ](https://platform.claude.com/docs/en/manage-claude/compliance-faq)
- In May 2026 the Compliance API gained audit-log events and 28 security-tool integrations (21 May), later reported as more than 100 partners — [Let's Data Science](https://letsdatascience.com/news/anthropic-introduces-claude-compliance-api-monitoring-f36c1048) (secondary); [Claude blog](https://claude.com/blog/compliance-api-security-partners) (search summary)

### Inferences
- Anthropic covers J1 (scoped memory in Claude Tag, Projects), J4 (Slack teammate, messaging between sessions and within teams), J5 (custom roles, Claude Tag identities, Trusted Devices), J6 (content-level transcripts) and part of J2 (outbound relay and runners). It has no general port forwarding, no public edge (J3) and no email. Its stated design ("the workers are Claude sessions") rules out J7.
- Every path that leaves a single machine (Remote Control, cross-machine messaging, cloud sessions, self-hosted runner event streams, MCP tunnels) passes plaintext content through Anthropic. MCP tunnels show Anthropic will engineer "the transport provider can't read" but not "Anthropic can't read".
- The reach features are not available on Anthropic's own third-party channels (Bedrock, Google Cloud, Foundry) or behind LLM gateways. A team that routes Claude Code through Coder's AI Gateway or Tailscale Aperture loses Remote Control and cross-machine messaging. A harness-neutral sidecar does not have that conflict.
- Content-level audit stops at what reaches Anthropic's API, and cloud sessions and routines are excluded. Local actions are therefore not audited at the source: what ran on the device, which ports were opened, what was sent elsewhere.

### Gaps
- No launch dates were found for cross-session messaging, Projects (public beta), self-hosted environments (public beta), agent view or agent teams.
- The MCP tunnels launch date and the scope of the claude.ai connector variant are unverified.
- No GA date for Claude Tag was found. It is beta as of the 23 Jun 2026 post.
- I did not research 2026 changes to SSO, SCIM or IP allowlisting beyond what these pages mention.

## Q3. OpenAI: Frontier, AgentKit/Agent Builder, Codex cloud network access, connectors, and admin and compliance APIs

### Takeaway
OpenAI's bundling bet is Frontier (launched about Feb 2026), a sales-led enterprise agent platform that claims to govern agents "regardless of their origin". It has agent identities, permissions, shared business context and auditing, and AWS is its exclusive third-party cloud distributor. Agent Builder is being shut down. Codex and ChatGPT "Work" add allowlisted egress and cloud-coordinated access to a connected computer, with Compliance API records and OpenTelemetry for local actions.

### Cited Findings
- Fetching openai.com/business/frontier returned **HTTP 403**, so the details below come from search summaries and InfoQ.
- Frontier is "an enterprise platform for building, deploying, and managing AI agents". It was initially offered to a limited set of customers, with broader availability planned in later months. Its layers are business context (data warehouses, CRM, internal apps), agent execution, evaluation and optimization, and security and governance (access controls, auditing, traceable agent actions) — [OpenAI, Introducing OpenAI Frontier](https://openai.com/index/introducing-openai-frontier/); [OpenAI Frontier page](https://openai.com/business/frontier/) (search summaries)
- Launch date: most secondary sources give 5 Feb 2026, and one says Mar 2026 — [The Rundown](https://www.therundown.ai/tools/openai-frontier) (secondary). InfoQ covered it on 20 Feb 2026 and reports that it applies to agents "regardless of their origin", gives each agent "permissions, boundaries, and auditability", and connects data "through open standards". Commenters raised lock-in concerns, and one argued for a control plane neutral across LLM vendors — [InfoQ](https://www.infoq.com/news/2026/02/openai-frontier-agent-platform)
- Distribution and partners: Frontier Alliance partners McKinsey, BCG, Accenture and Capgemini. "AWS is the exclusive third-party cloud distribution provider for Frontier". A planned Promptfoo acquisition will fold red-teaming into Frontier. HP began testing in Feb 2026 — [OpenAI, Frontier Alliance Partners](https://openai.com/index/frontier-alliance-partners/); [OpenAI–Amazon partnership](https://openai.com/index/amazon-partnership/); [OpenAI to acquire Promptfoo](https://openai.com/index/openai-to-acquire-promptfoo/); [HP partnership](https://openai.com/index/hp-frontier-partnership/) (search summaries)
- Secondary claims, not seen on OpenAI pages: runtime options are local, enterprise cloud and OpenAI-hosted, and pricing is custom and undisclosed — [The Rundown](https://www.therundown.ai/tools/openai-frontier) (secondary)
- AgentKit (Oct 2025): ChatKit and Evals GA, Agent Builder beta ([VentureBeat](https://venturebeat.com/ai/openai-unveils-agentkit-that-lets-developers-drag-and-drop-to-build-ai), secondary). The AgentKit page now carries a notice that OpenAI is "winding down the Agent Builder and Evals products" ([OpenAI, Introducing AgentKit](https://openai.com/index/introducing-agentkit/), search summary). Secondary sources date the wind-down notice to 3 Jun 2026, with shutdown on 30 Nov 2026 and the Agents SDK recommended instead. I did not verify this against OpenAI's deprecations page.
- Codex cloud internet access is off by default for the agent phase. It can be turned On with a domain allowlist and an HTTP-method allowlist, using a "None" or "Common dependencies" preset. Setup scripts run with full internet access, and secrets are removed before the agent phase — [OpenAI Developers, Agent internet access](https://developers.openai.com/codex/cloud/agent-internet) (search summary)
- ChatGPT "Work" and "dots" with **local computer access**: they "can use permitted files and tools on a connected computer while OpenAI's cloud coordinates the task", and the computer must stay online. This is managed in "Agent Security" in the Admin Console, separately from Codex Local. ## Q9. Where incumbents are structurally unlikely to go

### Takeaway
The open space is the intersection that the incumbents' business models discourage. That means a component that sits locally under any harness and coordinates Claude Code, Codex, Copilot and Cursor sessions together. It would give a team shared memory, a shared inbox with email-native identities, and network reach, encrypted so that the operator cannot read the content. Each incumbent covers one corner. The evidence shows that model vendors route content through their own APIs, gateway vendors monetize inspection, and identity-rich suites stay inside their own tenants.

### Cited Findings
- **Neutrality across harnesses at the runtime layer.** Anthropic designs every coordination mode around Claude sessions ([Claude Code Docs](https://code.claude.com/docs/en/agents)), limits cross-machine messaging to the user's own sessions over claude.ai sign-in ([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging.md)), and disables Remote Control behind an LLM gateway or on Bedrock, Google Cloud or Foundry ([Remote Control](https://code.claude.com/docs/en/remote-control.md)). GitHub admits rival agents but runs and bills them itself ([GitHub Blog](https://github.blog/news-insights/company-news/pick-your-agent-use-claude-and-codex-on-agent-hq/)), and its managed permissions name only Copilot surfaces ([GitHub Changelog](https://github.blog/changelog/2026-09-09-enterprise-managed-permissions-for-github-copilot-agent-operations/))
- **Customer-held keys and operator-blind content.** Anthropic's tunnel design blinds the transport (Cloudflare) but not Anthropic ([MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview)). Self-hosted runners still send "prompts, responses, and tool results" to Anthropic ([self-hosted](https://code.claude.com/docs/en/self-hosted-environments.md)). CMEK orgs cannot start cloud sessions or save network secrets ([cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web.md); [cloud environments](https://code.claude.com/docs/en/cloud-environments.md)). ZDR and HIPAA orgs cannot use Remote Control ([Remote Control](https://code.claude.com/docs/en/remote-control.md)). Anthropic's audit product returns session transcripts that Anthropic stores ([Compliance FAQ](https://platform.claude.com/docs/en/manage-claude/compliance-faq)). Cloudflare's portals log prompt activity and run DLP ([Cloudflare Changelog](https://developers.cloudflare.com/changelog/post/2026-09-24-mcp-portals-ga/))
- **Local-first.** Anthropic keeps same-machine messaging local ("never through Anthropic servers"), but anything across machines goes through Anthropic ([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging.md)). OpenAI's local computer access is coordinated by OpenAI's cloud ([learn.chatgpt.com](https://learn.chatgpt.com/docs/enterprise/cloud-local-access), search summary). OpenAI concedes that "Conversation visibility alone does not establish a complete record of local actions" ([OpenAI governance](https://learn.chatgpt.com/docs/enterprise/governance)). Anthropic's Compliance API does not capture "on-device activity that never reaches the API" ([Compliance FAQ](https://platform.claude.com/docs/en/manage-claude/compliance-faq)). GitHub listed VS Code and CLI session activity as future work ([GitHub Changelog](https://github.blog/changelog/2026-02-26-enterprise-ai-controls-agent-control-plane-now-generally-available/))
- **Email-native identities.** Only Microsoft gives agents real mailboxes, inside M365, behind licences and its Frontier preview ([Agent 365 Identity](https://learn.microsoft.com/en-us/microsoft-agent-365/developer/identity), search summary). Cloudflare offers per-address agent inboxes for agents built on Workers ([Cloudflare Blog](https://blog.cloudflare.com/email-for-agents/), search summary). Anthropic's shared teammate lives in Slack only ([Anthropic](https://www.anthropic.com/news/introducing-claude-tag)), and GitHub's lives in issues and PRs ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/agent-apps))
- **Network reach combined with memory.** Reach vendors (Tailscale, ngrok) have no memory product ([Tailscale](https://tailscale.com/tailscaleup-date-week-26); [ngrok](https://ngrok.com/blog/ai-gateways-2026)). Memory and messaging vendors (GitHub, Anthropic) offer only narrow reach: runners, an MCP-only tunnel, an outbound relay ([GitHub Changelog](https://github.blog/changelog/2026-02-13-network-configuration-changes-for-copilot-coding-agent/); [MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview)). Cloudflare combines both, but for Workers-hosted agents ([Cloudflare Blog, Artifacts](https://blog.cloudflare.com/artifacts-git-for-agents-beta); [Cloudflare press release](https://www.cloudflare.com/press/press-releases/2026/cloudflare-expands-its-agent-cloud-to-power-the-next-generation-of-agents/))

### Inferences
- **Most defensible: neutral coordination at the runtime layer.** Anthropic, OpenAI and GitHub each make money when the work runs on their own agent and API path. A component that lets a Claude Code session message a Codex session and a Copilot session, share a memory repo with them, and appear in one audit trail undermines that. The precedent is that Anthropic disables its own reach features behind third-party gateways. Neutrality at the identity layer is contested (Entra Agent ID federates non-Microsoft agents, and Frontier claims to cover any agent), so URnetwork should not claim neutral identity as unique. Neutral runtime coordination and messaging is the claim to make.
- **Most defensible: operator-blind encryption.** Every incumbent's audit and compliance value comes from content the vendor holds or inspects: Anthropic transcripts, OpenAI `conversation_message`/`codex_log`, Cloudflare prompt logs and DLP, Coder prompt audit. Vendors already exclude ZDR, HIPAA and CMEK customers from reach features. Real-time storage encrypted with customer-held keys, which URnetwork cannot read, fits customers the incumbents are turning away. The trade-off: URnetwork's audit trail (J6) must then be produced and held on the customer's side to stay consistent with this pitch.
- **Defensible: auditing local actions at the source.** All three agent vendors document that their logs miss on-device actions. A sidecar that sees the harness's actual network, port and storage actions can fill that gap, whichever harness is running.
- **Moderately defensible: email-native identity shared by people and agents across organizations.** Microsoft will do it, but only inside M365 tenants. Cloudflare provides the building blocks. GitHub and Anthropic prefer Slack, GitHub and Teams surfaces. A cross-harness, cross-tenant inbox with group addressing is less likely to come from the large vendors, though Cloudflare's Agentic Inbox reference app lowers the barrier for competitors.
- **Least defensible: reach alone or git-backed memory alone.** Reach alone is commoditized and neutral (Tailscale MCP endpoints and tsnet, ngrok, Cloudflare Tunnel). Git-backed agent memory alone is now a Cloudflare primitive (Artifacts plus Agent Memory). The defensible offer is the bundle: reach, memory, inbox and audit together, operator-blind and inside the harness. Cloudflare is the incumbent most able to build that bundle, and its business model (Workers-hosted, inspection-based security) points it elsewhere.
- **Naming and positioning risks.** Microsoft already documents an agent-authentication "sidecar" (Entra Auth SDK). "Frontier" means two different programs (OpenAI's platform and Microsoft's preview program). GitHub uses "agent apps" and "Agent HQ", Anthropic uses "agent teams" and "Projects", and ngrok's "agent endpoints" means the ngrok CLI.

### Gaps
- These conclusions are inferences from product designs and docs. I found no vendor statement ruling out neutral or operator-blind products, and roadmaps could change, especially Cloudflare's, given Artifacts and Agent Memory.
- I found no pricing for any incumbent bundle that would let a cost comparison be made against a sidecar.
