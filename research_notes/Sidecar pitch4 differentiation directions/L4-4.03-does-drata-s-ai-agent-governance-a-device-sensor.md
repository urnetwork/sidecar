## 1. Does it capture local coding-agent sessions and actions (Claude Code, Codex, Cursor, Copilot) on developer machines?

### Takeaway
- **No public Drata source names any coding harness or IDE.** I checked the product pages, the data sheet, nine learn pages, both releases, the help center and trade press:
  - Claude Code, Codex, Cursor and GitHub Copilot appear nowhere.
  - The early-access form lists "Microsoft Copilot" as an AI platform, not GitHub Copilot.
- **Capture runs through three components:**
  - a "Drata Sensor", described in two ways: as sitting "inline with the AI platforms", and as a background service on managed devices that watches "desktop and browser AI and local models";
  - an **MCP Proxy** that evaluates agent tool calls;
  - telemetry that is reduced and masked on the device.
- **Fields monitored:** "every command, prompt, and tool call". Each inventory entry holds owner, identity, permissions and scope.
- **The product is built around agents that call business systems through MCP proxies.** The data sheet screenshot shows agents such as "Marketing Ops Agent · Sonnet 4.5 · proxy aws-mcp-proxy-prod" connected to HubSpot, Salesforce, Slack, GitHub and Notion. Nothing shows developer sessions on laptops.
- **Drata's "Anthropic" coverage does not come from Claude Code session transcripts:**
  - Drata is **not** on Anthropic's list of more than 100 Compliance API partners.
  - Its existing Anthropic connector syncs users and roles for access reviews.

### Inferences
- **Drata governs "agents" as standing entities, not developer sessions.** In Drata's model an agent has an owner, a model, a proxy and a trust score, and acts on SaaS through MCP. The screenshot's "Code Review Agent" and "PR Summarizer" are agents of that kind: they reach GitHub through a proxy. They are not harness sessions on a laptop.
- **The device sensor may notice Claude Code or Cursor as "desktop AI", but nothing says it records their sessions.** Specifically, nothing says it records prompts with outcomes, shell commands, file edits, diffs or approvals per action.
- **An MCP proxy cannot see most of what a coding agent does.**
  - A coding harness's built-in tools (shell, edit, write) are not MCP calls; Claude Code names MCP tools `mcp__<server>__<tool>` and built-ins `Bash`, `Edit`, `Write`.
  - So even if a developer's Claude Code were pointed at Drata's MCP proxy, the proxy would see only MCP traffic: not commands, not edits, not commits.
  - This is my inference from the harness design. Drata does not say it.
- **Drata does not keep whole sessions.** Its release says activity is reduced and masked on the device before transfer. Even where Drata captures, it does not offer what pitch4 promises developers (session vault, restore, handoffs).
- **The Anthropic route goes around Claude Code transcripts.**
  - Drata is not a Compliance API partner, and its Anthropic connector syncs users only.
  - "First and deepest for Anthropic" probably means agents built on the Anthropic API or Agent SDK whose tool calls go through Drata's MCP proxy, plus device-level observation.
  - This is unverified.

## 2. Does it link agent actions to commits or pull requests, and map them to SOC 2 change-management controls (CC8.1)?

### Takeaway
- **No.** No Drata source links agent activity to commits, pull requests or merges, or names CC8.1 or change management.
- **Framework mappings are stated only at framework level:** "SOC 2, ISO 27001, ISO 42001, the NIST AI RMF, the EU AI Act, and AIUC-1". The only SOC 2 criterion I found cited anywhere in the AI Agent Governance material is CC6.2, given as a generic access-review example.
- **Drata's code-change tests read only forge settings and permissions.** They inspect branch settings and who can merge, not individual pull requests. So nothing ties an agent run to a code change.

## 3. Who can read the "tamper-evident" record, and can a customer verify it independently?

### Takeaway
- **The record is Drata-hosted SaaS evidence.**
  - Drata says it is for "the board, auditors, customers, and regulators".
  - Auditors reach Drata evidence through Audit Hub's "read-only, structured access".
- **The mechanism is undocumented.** No Drata source on AI Agent Governance says how the "tamper-evident" record is made: no hash chain, signatures, checkpoints, key holder, published format, export format or verifier.
  - Drata's general page on auditor-grade evidence describes tamper evidence as cryptographic hashing and write-once storage. This is the fetch tool's paraphrase, not a quote.
- **No self-hosted or customer-key option was found.**
  - Data is reduced and masked on the device before it reaches Drata.
  - Whatever does reach Drata is held by Drata, under Drata's control.
- **Independent verification by a customer is not offered in any public material.**

### Cited Findings
**Who the record is for, and how it is described**
- **Audience:** "a single, verified evidence trail for all stakeholders to review"; the record is for "the board, auditors, customers, and regulators." — [Drata product page](https://drata.com/products/agent-governance) [opened; undated]
- **The only description, across every agent-governance source read, is "tamper-evident":**
  - "Chain of Custody: See every decision logged in a tamper-evident record, mapped to existing frameworks." — [Data sheet](https://tfm5idqp2axdd32z.public.blob.vercel-storage.com/AI%20Agent%20Governance%20-%20Why%20Drata.pdf) [downloaded]
  - "Drata logs every decision in a tamper-evident record." — [Data sheet](https://tfm5idqp2axdd32z.public.blob.vercel-storage.com/AI%20Agent%20Governance%20-%20Why%20Drata.pdf) [downloaded]
  - The [launch blog](https://drata.com/blog/introducing-ai-agent-governance) [opened] does not explain how the record is made tamper-evident. Its only listed readers are board, auditors and customers.

**Drata's general account of auditor-grade evidence** — [Drata learn, 13 Aug 2026](https://drata.com/learn/agent-gov/auditor-grade-evidence) [opened]
- Tamper evidence is described as cryptographic hashing and write-once storage, with access logging (the fetch tool's paraphrase; not a direct quote).
- "every artifact links back to its source system with timestamps, actor identity, and provenance"
- Evidence is "stored in a controlled repository auditors can access without modification."
- Audit Hub gives auditors "read-only, structured access to organized evidence packages."
- The page does not mention key holders, signatures, independent verification by customers, export or retention.

**What reaches Drata**
- "Reduces and masks activity on-device before it flows into a durable, tamper-evident evidence feed." — [Drata news, 4 Aug 2026](https://drata.com/about/news/drata-extends-trust-management-platform-to-continuously-monitor-and-govern-ai-agents) [opened]

**Deployment**
- Drata's pricing page lists only hosted plans (Foundation, Advanced, Enterprise). No price is published, and there is no self-hosted or on-premises option. — [Drata pricing](https://drata.com/pricing) [opened]
- A search for Drata BYOK, customer-managed keys or self-hosting returned nothing specific to Drata. — [search summary](https://www.kiteworks.com/gdpr-compliance/customer-owned-encryption-key-control-data-privacy-compliance/) (generic results only)

**For contrast, an independently verifiable record.** Earlier notes found that Anthropic's Access Transparency log is "an append-only, cryptographically signed record". It uses a Merkle tree with signed checkpoints, inclusion and consistency proofs, and an `axt-verify` tool. — `Agent work record gaps and features/record_feature_benchmark.md`, citing [Anthropic docs](https://platform.claude.com/docs/en/manage-claude/access-transparency-log)

### Inferences
- **On this axis pitch4's competitor-table cell survives against Drata.** The cell reads "A record of agent work you can read and we cannot: No one".
  - Drata's record is a vendor-hosted SaaS store, with no published integrity mechanism, no customer-held keys, no self-hosting and no external verifier.
  - Drata, as operator, can presumably read whatever its masked telemetry delivers. Its pages make no end-to-end encryption claim.
- **"Tamper-evident" is no longer a differentiating phrase.** Drata, an 8,500-customer compliance brand, uses it in every asset. Pitch4 should claim what Drata does not:
  - "verifiable by your auditor without trusting us";
  - an open verifier, signed checkpoints and keys only the team holds;
  - a self-hosted or air-gapped option.
- **Masking cuts both ways.** It helps Drata's privacy story, but it means the record cannot answer "what exactly did the agent run or change", which is the question CC8.1 and incident review ask.

### Gaps
- **Not documented:**
  - Drata's actual Chain of Custody design (hashing, signing, anchoring), who holds the keys, retention, and export format.
  - Whether Chain of Custody records flow into Audit Hub as samples.
- **Not found:** whether Drata offers customer-managed encryption keys for any product. The trust center was not checked.

## 6. What this means for pitch4's differentiation and offering

### Takeaway
- **Drata's AI Agent Governance covers agents on API platforms that call SaaS through MCP proxies.** As of 1 Nov 2026 it does not, in any public source, cover local coding harnesses. It does not link to commits, pull requests or CC8.1, offer a customer-verifiable record, or serve 5–150-engineer buyers. Pitch4 therefore does not need to reposition against Drata today.
- **Pitch4 should sharpen its claims where Drata uses the same words:**
  - "tamper-evident" and "auditor-grade" are now Drata's vocabulary;
  - "approvals" exist in Drata's Mission Control.
- **Watch the GRC platforms, Vanta first.** Vanta's Claude Code session ingestion (GA planned January 2027) is the nearer bundling route for Claude Enterprise shops. Drata's GA packaging is the watch item for the Assured tier.

### Cited Findings
- This section synthesizes Sections 1–5.
- Pitch4's admin promise and competitor-table cell ("A record of agent work you can read and we cannot: No one") are summarized in the task brief and in `/Users/brien/urnetwork/sidecar/pitch4.html` (read in earlier rounds).

### Inferences
1. **Keep "No one" in the competitor table, but say what "can read and we cannot" means.** Name the mechanism: signed checkpoints, an open verifier, keys only the team holds, and self-hosting. Drata claims "tamper-evident" with no published mechanism and holds the data itself.
2. **Position the sidecar as the coding-agent feed Drata's inventory lacks.** Pitch line: "Drata governs the agents that call your SaaS; the sidecar records the agents that change your code, in every harness."
   - Drata's agent inventory has no public third-party API, so the practical routes are the ones L3-3.10 found:
     - custom connections and tests (Advanced plan);
     - signed exports through the Evidence API.
   - Do not promise "appears in Drata's agent inventory" until Drata documents an intake.
3. **Lead the compliance story with run → commit → PR → approver, mapped to CC8.1.** Drata, Vanta and the endpoint vendors leave this unclaimed. Drata's approvals record "who approved it, when, and against which policy", but are not bound to a diff or command hash.
4. **Tell buyers that MCP proxies miss most coding-agent actions.** Proxies see MCP calls only, while shell commands and file edits run as built-in tools. Pitch4's capture beside the harness covers both. This needs a test against real Claude Code, Codex and Cursor sessions before it goes in the pitch.
5. **Do not lean on "Drata is enterprise-only" for long.**
   - Today Drata is not sold to 5–150-engineer companies.
   - Drata's own data shows rising agent-governance questions in questionnaires, and the platform already costs those companies about $12k–$50k a year. A bundled GA would put an "agent inventory" in front of them.
   - Pitch4's Team tier should therefore stand on what Drata cannot do: developer continuity (vault, restore, handoffs) and cross-harness coordination, not on compliance alone.

### Gaps
- **No buyer evidence** on whether 5–150-engineer SOC 2 buyers would accept a GRC-hosted "tamper-evident" log as sufficient, or would pay for independent verifiability.
