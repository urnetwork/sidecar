# Does coordinating parallel coding agents save work, and what do developers use today? (research as of 1 Nov 2026)

Scope: this tests pitch4's claim that "claims and leases across harnesses, so two agents don't edit the same files" save work. It adds new evidence to the earlier landscape notes (`Sidecar positioning and market gaps/coordination_alternatives.md`, `Agent sidecar message landscape/coordination_tools.md`). Those notes already cover tool launches, the Vibe Kanban shutdown, Claude Code agent teams, Codex message boards, Copilot /fleet, and Gas Town/Beads. They are only referenced here, not repeated.

Method and reading key:
- **Hacker News counts:** I queried the HN Algolia API for comments created on or after 1 Jan 2026. Comment queries were: "parallel agents merge conflicts", "agents overwrite each other", "multiple agents same file", "worktrees port", "agents duplicate work", "agents stepping on each other", "running agents in parallel", "worktree node_modules", "parallel agents review bottleneck", "agents in parallel worktrees", plus four cross-harness review queries listed under Q4. I also pulled the full comment trees of 17 stories by id. I read the matches by hand and count distinct usernames per pain. Product authors promoting their own tool are labeled "(vendor)" and left out of the pain counts. The counts measure how often a pain is voiced in one forum. They are not prevalence.
- **GitHub:** issue searches ran through the GitHub REST API (`gh api search/issues`, created on or after 1 Jan 2026). Star counts were read through `gh api repos/...` on 1 Nov 2026.
- **Quotes** are exact substrings of the pages or API text I opened. Vendor statements are labeled as vendor claims. "Earlier notes" means a fact taken from this project's 31 Oct 2026 research that I did not re-open today.

## 1. How common is running several agents in parallel in late 2026, and what breaks?

### Takeaway
About a third of developers who use agents run more than one, and those who do use them daily. Agent-written pull requests now overlap in time in about 40% of repositories that have them.

What breaks most often in what people write is not two agents claiming the same task:
- **Shared local environment (most voiced):** ports, databases, dependencies, disk, and builds. 14 people describe it directly and 6 more built workarounds.
- **Conflicting or semantically incompatible edits:** about 20 people, with at least 5 saying agents now fix conflicts fine.
- **The human review bottleneck:** about 10 people.

Duplicate work is reported mostly as harness bugs, for example agent teams spawning duplicate teammates, and rarely as two people's agents doing the same task.

### Cited Findings

**How common parallel agents are**
- Stack Overflow pulse survey (late April 2026, about 1,100 "developers and working professionals"):
  - "69% use a single agent, 17% use multiple specialized agents, and 16% use multiple overlapping or coordinated agents".
  - "68% prefer predictable, single-agent setups over complex, multi-agent configurations."
  - Daily use is 85% for users of multiple specialized agents and 77% for users of overlapping or coordinated agents, against 54% for single-agent users.
  - Among daily multi-agent users, Claude Code is the most used tool (70%).
  - The article has no data on conflicts or coordination failures.
  - Source: [Stack Overflow blog, Erin Yepis, 27 May 2026](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work/)
- Jellyfish platform telemetry (H1 2026, vendor data): "84% of active users run one or two agents at once." Taken from earlier notes; not re-opened today. — [Jellyfish State of AI in Software Engineering H1 2026](https://jellyfish.co/state-of-ai-software-engineering/)
- Concurrency in public repos, from the AIDev-pop dataset (33,596 agent-authored PRs in 2,807 repositories):
  - 40.2% of repositories contain co-active agent-authored PR pairs (exact temporal overlap), and those pairs account for 79.4% of agent PRs.
  - With a one-week window, the figures are 53.4% of repositories and 95.0% of PRs.
  - Source: [arXiv 2607.04697, Xu, Subramanian, Karthik, v1 6 Jul 2026](https://arxiv.org/abs/2607.04697)
- Merge volume at a frontier lab (vendor's own report): "In May 2026, Anthropic averaged around 2,500 code changes merged per day; as of September, we merged over 30,000 per day." — [Anthropic Engineering, "Redesigning source control at Anthropic", 13 Oct 2026](https://www.anthropic.com/engineering/redesigning-source-control). The HN thread drew 900 points and about 1,012 comments ([HN 50073633](https://news.ycombinator.com/item?id=50073633)).
- Merged PRs to the Claude Code repo "more than doubled" from June to September 2026 "while the share that had to be reverted fell by more than 40 percent" (vendor). — [claude.dev, "How the Claude Code team does code review", 15 Oct 2026](https://claude.dev/blog/solving-code-review-at-anthropic/)
- AgenticFlict: of 107K+ agent PRs replayed by deterministic merge simulation (from 142K+ PRs in 59K+ repos), 29K+ had textual merge conflicts, an overall rate of 27.67%. — [arXiv 2604.03551, Ogenrwot and Businge, 4 Apr 2026, v2 12 May 2026](https://arxiv.org/abs/2604.03551)

### Inferences
- Parallel agents are mainstream among heavy users: about a third of agent users, and 40% of repositories that have agent PRs. The pain people describe most is the shared local environment, not overlapping intent. Worktrees isolate files but not ports, databases, secrets, dependencies, or disk. Users and at least six products patch this by hand.
- Pitch4's "a private IP address per agent" is aimed at security buyers, yet it maps directly onto this developer pain. Every agent could run its dev server and database on default ports at its own address. No harness vendor documents a fix. Claude Code #34385 asked for one in March 2026 and is closed, but I did not confirm what shipped.
- Human-reported duplicate work is mostly a single operator's swarm, or a harness bug inside one vendor's team feature. Two developers' agents duplicating each other's task, which is pitch4's "teammate's agent starts on the same module" story, appears rarely in public text.

### Gaps
- No survey measures how often parallel agents collide, by pain type. The JetBrains 2026 agent-adoption post ([blog.jetbrains.com, Aug 2026](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/)) returned HTTP 403, so its parallel-use figures, if any, were not read.
- Reddit and Discord were not mined; earlier work found old.reddit.com does not render.
- One Cursor forum claim, that "half of the agents quickly forget that they are working in their own worktree", appeared only in a search summary. The thread I opened did not contain it, so it is not used.
- No data separates conflicts between one developer's agents from conflicts between different developers' agents.

## 2. Which coordination tools have real adoption, and which failed or shut down, and why?

### Takeaway
Adoption goes to two kinds of tools:
- **Parallel workspace managers** (worktree, terminal, review UI): cmux, Vibe Kanban, Paradev (formerly Superset), Conductor, Claude Squad.
- **A vendor-built cross-harness review bridge:** OpenAI's codex-plugin-cc has 34,787 stars, more than any coordination tool.

Dedicated coordination layers have 10 to 100 times fewer stars: agent mail, intent claims, semantic merge. The money is in cloud workspaces, multiplayer, mobile, and admin, not in claims. Conductor's free tier already includes local parallel agents. Vibe Kanban shut down its hosted service because almost all users were free.

## 3. Is there evidence that coordination features reduce duplicate work, conflicts, or review time?

### Takeaway
Some evidence exists, but it is mixed and depends on the task. No study measures advisory claims or leases across harnesses.

Against simple locks and claims:
- At scale, locks cut throughput: Cursor's "Twenty agents would slow down to the effective throughput of two or three."
- File-claim locks did not stop 16 agents converging on one bug (Anthropic).
- Anthropic's monorepo dropped the global merge lock and lets Claude fix textual conflicts.

For coordination before editing:
- Up-front decomposition into disjoint scopes took merge conflicts from 13 to 0 in a benchmark.
- Telling an agent about a concurrent interface change recovered 82% of failures in constructed tasks. Such semantic failures were rare in mined real pairs (1 in 834 runs).
- Cross-vendor PR pairs conflict about twice as often as same-vendor pairs (41.7% against 19.8%).
- Centralized coordination contains error amplification at 4.4x, against 17.2x for independent agents.

### Cited Findings
- **Locks failed at scale** — [Cursor blog, "Scaling long-running autonomous coding", Wilson Lin, 14 Jan 2026](https://cursor.com/blog/scaling-agents):
  - Cursor first let agents "self-coordinate through a shared file" with "a locking mechanism". Agents "would hold locks for too long, or forget to release them entirely". "Twenty agents would slow down to the effective throughput of two or three, with most time spent waiting." Agents could also "fail while holding locks, try to acquire locks they already held."
  - Optimistic concurrency was "simpler and more robust", but without hierarchy "No agent took responsibility for hard problems or end-to-end implementation".
  - What worked was planners that create tasks and workers that do not coordinate with each other: "Hundreds of workers run concurrently, pushing to the same branch with minimal conflicts." An integrator role "created more bottlenecks than it solved" because "Workers were already capable of handling conflicts themselves."
  - Scale: a browser of "over 1 million lines of code across 1,000 files" in "close to a week", and "trillions of tokens".
- **Task claims worked for distinct tasks but not for a shared bug** — [Anthropic Engineering, Carlini, 5 Feb 2026](https://www.anthropic.com/engineering/building-c-compiler):
  - "Claude takes a "lock" on a task by writing a text file to current_tasks/". "If two agents try to claim the same task, git's synchronization forces the second agent to pick a different one." "Merge conflicts are frequent, but Claude is smart enough to figure that out."
  - On the Linux kernel, all agents hit the same bug and overwrote each other's fixes. "The fix was to use GCC as an online known-good compiler oracle", which "let each agent work in parallel, fixing different bugs in different files".
  - Totals: "nearly 2,000 Claude Code sessions and $20,000 in API costs" for a 100,000-line compiler. "LLM-written code frequently re-implements existing functionality, so I tasked one agent with coalescing any duplicate code it found."
- **Agents fix textual conflicts at monorepo scale** — [Anthropic Engineering, 13 Oct 2026](https://www.anthropic.com/engineering/redesigning-source-control):
  - "A proper merge queue, for example, doesn't make much sense at agent scale." "We haven't been able to effectively replicate the industry standard of a global repository lock on the merge queue, so instead, we've invested in post-merge and pre-deploy automated testing. This does mean that concurrent changes can conflict, but Claude can typically fix these conflicts faster than humans can even identify them."
  - Author nickg-anthropic, 14 Oct 2026: "We never allow textual conflicts, but semantic conflicts (for example, if someone adds changes the logic of a function and cleans up all affected callsites concurrently with a new call being added) are an unavoidable fact of very large repos unless you completely serialize merging with running extensive validation at the proposed batch tip, which isn't practical at a certain commit rate." — [HN 50082255](https://news.ycombinator.com/item?id=50082255)
- **Conflict rates between concurrent agent PRs** — [arXiv 2607.04697, 6 Jul 2026](https://arxiv.org/abs/2607.04697):
  - Replaying 747 co-active pairs (one per repository) as three-way git merges gave a textual conflict rate of 41.7% for cross-agent pairs against 19.8% for same-agent pairs, with non-overlapping 95% confidence intervals.
  - 84.4% of conflicted files were source code, and nearly 42% of conflicts were structural (modify/delete or add/add).
  - Only 0.5% of co-active pairs were cross-agent, in 122 of 2,807 repositories (about 4.3%).
- **Semantic interference: rare in the wild, recoverable by messaging** — [arXiv 2609.25396, Xia, Wu, Park, 21 Sep 2026](https://arxiv.org/abs/2609.25396):
  - "Among 834 runs on 417 mined Django pairs, only one showed interference after correcting the grading procedure."
  - "On constructed tasks using 12 Django helpers, interference occurred in 97% of runs." A message describing the completed concurrent change recovered 82% of runs. The fetched summary does not give the denominator.
  - The authors warn: "The constructed failure rates do not estimate how often these problems occur in practice."
- **Up-front scope planning** — [arXiv 2610.07261, Muku, 5 Oct 2026](https://arxiv.org/abs/2610.07261):
  - A planner that partitions work into disjoint scopes and orders merges lifts clean integration from 1/9 to 9/9 scenarios and cuts merge conflicts from 13 to 0. The abstract does not say whether this was simulated or live.
  - In live agents with a breaking contract change, clean integration was 0 for no coordination and for reactive detection. The planner scored 1.0 with a frontier model and 0.6 with a small model. Scope leakage was 0 of 5.
  - A separate cross-session memory result cut the repeated-mistake rate from 1.00 to 0.00. Locks and leases were not tested as their own arm.
  - Single author, not peer reviewed.
- **Coordination topology** — [Google Research blog, Kim and Liu, 28 Jan 2026](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/); paper [arXiv 2512.08296](https://arxiv.org/abs/2512.08296v2):
  - 180 configurations across 4 benchmarks and 3 model families. Not coding-specific.
  - Centralized coordination improved a parallelizable task by 80.9%. On PlanCraft (sequential), "every multi-agent variant degraded performance by 39–70%."
  - "Independent multi-agent systems amplified errors by 17.2x". Centralized systems held this to 4.4x.
  - As tools increase ("16+ for a coding agent"), coordination costs rise disproportionately.
- **AgenticFlict:** a 27.67% textual conflict rate across 107K+ replayed agent PRs, varying by agent. Per-agent rates were not on the abstract page. — [arXiv 2604.03551](https://arxiv.org/abs/2604.03551)
- **Review loops between agents need caps** (vendor) — [claude.dev, 15 Oct 2026](https://claude.dev/blog/solving-code-review-at-anthropic/):
  - "An agent author and an agent reviewer can keep each other busy indefinitely." "One CLI PR went through more than fifty rounds of review and fixes overnight before its author stopped it."
  - Fixes include "A round cap. After three rounds, the reviewer asks the author to step back". After the changes, PRs passing after one round rose from 65% to 78%, PRs needing five or more rounds fell from 8.9% to 1.5%, and mean reviews to pass fell from 2.08 to 1.32.
  - Substantive review comments rose from 16% to 54% of internal PRs at the research-preview launch.
- **Cross-model review results depend on direction** — [arXiv 2607.21656, Xiang, Zhang, Zhang, Xu, 22 Jul 2026](https://arxiv.org/abs/2607.21656), on 116 hard and medium LiveCodeBench ("lcb") tasks:
  - "Claude review raises Codex drafts from 71.6% to 89.7%". Codex self-review reaches 84.5%.
  - "Codex reviewing Claude drafts drops the pass rate from 91.4% to 82.8%". Claude self-review leaves 91.4% unchanged.
- **Vendor merge benchmark (Weave):** on 31 hand-crafted scenarios, Weave had 29/29 clean merges and 31/31 correct outcomes, Mergiraf 26/29 and 28/31, and Git 15/29 and 17/31. — [Weave README](https://github.com/Ataraxy-Labs/weave)
- **Anecdotes with numbers:**
  - jjmarr, 2 Mar 2026: "I just avoided $1.8 million/year in review time w/ parallel agents for a code review workflow" (at $125/hr). sarchertech replied: "you have so many assumptions built in to this that are your number is worthless." — [HN 47224764](https://news.ycombinator.com/item?id=47224764); [HN 47227405](https://news.ycombinator.com/item?id=47227405)
  - cjk, 28 Jul 2026, on a Claude-writes, Codex-reviews loop: "a trivial feature go for 13 rounds of review/fix before I stopped it". — [HN 49082442](https://news.ycombinator.com/item?id=49082442)
- **Opinions about claims** (no data):
  - DylanMerigaud: "Intent conflicts caught early save a lot of rework." — [HN 49797440](https://news.ycombinator.com/item?id=49797440)
  - Skeptic ttoinou: "we don't know in advance what we will need to change in our current task." — [HN 49795378](https://news.ycombinator.com/item?id=49795378)
  - laalshaitaan: "The root problem is parallel agents have no coordination primitives before edits happen." — [HN 47253997](https://news.ycombinator.com/item?id=47253997)

### Inferences
- **Mandatory locks backfire.** Hard file leases and locks reduce throughput at scale and fail when agents crash: Cursor's measured experience, and Foremerge's reason for advisory claims. If pitch4 keeps "leases", they should be advisory with expiry, never blocking.
- **Textual conflicts are cheap.** The frontier labs report agents resolve them, so claims that only prevent textual overlap save little.
- **The open problem is semantic.** The costly failures are interface or contract changes, a shared bug many agents converge on, and cross-vendor pairs. For those, three mechanisms have numbers behind them: up-front decomposition, broadcasting "I changed contract X" after the change, and an oracle that splits work.
- **Rewrite the claim.** "Claims save work" should become "announcements of intent and contract changes save rework". Pitch4's ledger is a natural carrier, since every entry is signed and readable by all agents and harnesses.
- **The best measurement target is cross-vendor pairs.** Their conflict rate is double the same-vendor rate. Today they are rare: about 4% of repositories have one.
- **Review coordination is measurable, and the vendor has measured it.** Round caps, no repeats, and convergence rates are numbers a sidecar could record across harnesses.

### Gaps
- No experiment compares advisory claims or leases with no coordination, using real agents from different vendors. Foremerge states it has no published benchmark. NP-Bench does not test leases as a separate arm. The fetched summary of the stale benchmark gives no rates for locks or shared plans.
- No public data measures review time saved by coordination features. Anthropic gives review-convergence numbers but no wait times.
- The 82% recovery figure's denominator is unclear from the abstract summary.

## 4. What would make cross-harness coordination a selling point rather than a free feature?

### Takeaway
The cross-harness job developers already do in large numbers is sequential review and handoff, not parallel editing of the same module:
- About 61 distinct HN users in 2026 describe having Codex review Claude's work, or the reverse.
- OpenAI's own Claude Code plugin for this has 34,787 stars.

Cross-vendor parallel editing is rare (4.3% of repositories) but conflicts at twice the same-vendor rate. Harness lock-in blocks some teams from adopting managers. Vendor messaging stays inside one vendor's account and relay, and the closest open-source tool stops at one machine.

Cross-harness coordination could become a selling point when bundled as:
1. the record and gate for cross-vendor review (who wrote, who reviewed, with which model, how many rounds, with what verdict);
2. team-wide, cross-machine notices of intent and contract changes;
3. per-agent network isolation.

It should be sold to teams and admins, not as file claims.

### Cited Findings
- **Cross-harness review is a mass behavior.** Method:
  - Four HN Algolia comment queries ("codex review claude code", "claude writes codex reviews", "switch between claude code and codex", "claude and codex same repo"), on or after 1 Jan 2026, up to 100 hits each, filtered by a regex for one vendor's agent reviewing another's.
  - The filter matched 81 comments by 70 distinct authors. Reading them, I excluded 9 that do not describe cross-vendor review (CVs, product listings, sarcasm, same-model review). That leaves about 61 distinct people.
  - Examples:
    - linsomniac, 16 Jan 2026: "After Claude writes and commits some code, have Codex review that code and have Claude go back and address what Codex finds." — [HN 46647478](https://news.ycombinator.com/item?id=46647478)
    - petesergeant, 13 Feb 2026: "\"Claude writes, Codex reviews\" has shown huge promise as a pattern for me" — [HN 46999229](https://news.ycombinator.com/item?id=46999229)
    - ChadNauseam, 8 Apr 2026: "It's very important in my opinion to have Codex review Claude's work. They make different types of errors and both get tunnel-vision." — [HN 47697604](https://news.ycombinator.com/item?id=47697604)
    - saberience, 3 Jul 2026: "get Codex to review the code and it will find 2-5 actual correctness bugs" — [HN 48773472](https://news.ycombinator.com/item?id=48773472)
    - ramshanker, 22 Sep 2026: "Claude does coding, Codex do code review, and if developer did 5 round of this before pull request, we could very well just let CI merge." — [HN 49795995](https://news.ycombinator.com/item?id=49795995)
    - enraged_camel, 22 May 2026: Codex "was a lot more adversarial and thorough in its review when given Claude-authored code" — [HN 48236654](https://news.ycombinator.com/item?id=48236654)
    - Skeptic mikeocool, 17 Jun 2026: "I don’t think I’ve ever seen it catch a major issue." — [HN 48569066](https://news.ycombinator.com/item?id=48569066)
    - Cost: linsomniac, 9 Jul 2026: "uses tons of tokens but the result is really good." — [HN 48850353](https://news.ycombinator.com/item?id=48850353)
- **The vendor bridge.** OpenAI's codex-plugin-cc ("Use Codex from Claude Code to review code or delegate tasks") was created 30 Mar 2026 and has 34,787 stars. — [openai/codex-plugin-cc](https://github.com/openai/codex-plugin-cc)
- **The measured effect depends on direction:** Claude reviewing Codex helps (71.6% to 89.7%), and Codex reviewing Claude hurts (91.4% to 82.8%). — [arXiv 2607.21656](https://arxiv.org/abs/2607.21656)
- **Cross-vendor parallel editing is rare but conflict-prone:** 0.5% of co-active pairs, in 4.3% of repositories, with a 41.7% textual conflict rate against 19.8% within one agent. — [arXiv 2607.04697](https://arxiv.org/abs/2607.04697)
- **Pain moving between runtimes:** haoranchg (26 May 2026) copy-pasted prompts between Codex and Claude Code, then built OACP (15 stars). Foremerge's author (23 Sep 2026): "Where Foremerge really shines is if you bounce back and forth between claude and codex". — [HN 48283162](https://news.ycombinator.com/item?id=48283162); [HN 49819493](https://news.ycombinator.com/item?id=49819493)
- **Harness lock-in blocks managers at work.** jamie_ca (22 Apr 2026) cannot use Conductor at work "because we only have Copilot and they're locked to a Claude/Codex backend." — [HN 47867353](https://news.ycombinator.com/item?id=47867353)
- **Vendor coordination stays inside one vendor** (earlier notes):
  - Claude Code cross-session `SendMessage` reaches other machines "Through Anthropic servers". It needs a claude.ai sign-in and does not work with API keys, Bedrock, Vertex, or Foundry. "A session inside a container and a session on the host can't reach each other". — [Claude Code docs](https://code.claude.com/docs/en/cross-session-messaging)
  - Two seats of one Claude Team cannot coordinate sessions across the desktop app's SSH connection. — [#103760](https://github.com/anthropics/claude-code/issues/103760)
- **The open-source analog stops at one machine.** Foremerge: "coordination between machines is outside this project's scope." — [Foremerge README](https://github.com/naw103/foremerge)
- **Survey context:** 17% use multiple specialized agents and 16% use overlapping or coordinated agents. The survey does not ask whether these come from different vendors. — [Stack Overflow, 27 May 2026](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work/)
- **Teams are where it breaks, per theptip:** "As soon as you have many engineers using agents in the same codebase, the process breaks down". — [HN 50232454](https://news.ycombinator.com/item?id=50232454)
- **Paid features cluster on teams and admin:** Conductor charges for multiplayer, admin portal, SSO and SCIM, and DPA, and stores chat on its servers. — [conductor.build/pricing](https://www.conductor.build/pricing)

### Inferences
- **Recast cross-harness.** It should mean "a model from another vendor checks this agent's work, and the check is on the record", not "two agents from different vendors don't edit the same file". The first job is common (about 61 people describing it, a 34.8k-star vendor plugin), measurable (pass-rate changes, rounds to converge), and has failure modes worth governing: runaway loops (13 and 50+ rounds), token cost, and directions that make code worse.
- **This joins pitch4's two halves.** A signed entry that says "Codex reviewed Claude's change set X at round N with verdict Y, under the team's keys" is useful to developers (handoff and continuation) and to security buyers (independent review evidence). That makes it sellable to admins rather than a free developer feature.
- **Cross-machine, cross-developer scope is the structural gap.** Vendors route it through their own relay and accounts. Foremerge excludes it. Claude Team seats cannot even coordinate over SSH. Pitch4's relay plus team-keyed ledger fits this gap. Demand evidence is thin, though: theptip, materielle, and jamie_ca are individual voices.
- **Bundling with reach:** per-agent addresses (fixing port, database, and service collisions) plus a cross-vendor review record plus advisory intent notices, all under customer keys. That bundle is a differentiated offering no single tool reviewed here ships. Each part alone is free somewhere: portless and Coasts, codex-plugin-cc, Foremerge.

### Gaps
- No survey measures the share of developers who use two or more vendors' agents on the same repository or the same task.
- No data shows whether buyers value a review record that is independent of the vendor. Security and compliance demand for "different-model review" evidence is untested.
- I did not find whether Anthropic has shipped a counterpart bridge (a Claude reviewer inside Codex), or whether A2A or ACP is used for cross-vendor coding-agent review in practice.
