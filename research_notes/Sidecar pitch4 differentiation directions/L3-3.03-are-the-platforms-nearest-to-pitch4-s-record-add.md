## 1. GitLab AI Governance: how is the "immutable copy" made, what do ECA events carry, what is the 19.6 Anthropic Compliance integration, and can outside tools write records in?

### Takeaway
GitLab now takes records from outside tools. An ingestion API for external agents shipped in 19.5 (beta; the endpoints are labelled "experiment" and Premium). It is self-reported: the developer's own token, a session that must belong to that developer, timestamps the client chooses (up to 90 days back), and an agent type fixed to four values. It has no tamper evidence. The "immutable copy" is a JSON file rebuilt from database rows at each download, with no hash or signature. `glab` sends a SHA-256 of the transcript when a session completes; the API accepts that value, and the server then discards it. ECA events carry prompts, tool names and arguments, outcomes, the model and token counts. They carry no approval or permission decision, and GitLab deliberately keeps full content for external sessions, readable by group Owners.

The Anthropic Compliance integration is a pull from Anthropic's Claude Enterprise Compliance API. It runs every 6 hours, matches users by email and drops sessions it cannot match. Its session-list part is merged for 19.6 behind a work-in-progress flag that is off by default. Its transcript part is still an open MR.

**The "immutable copy" is regenerated JSON, not a sealed artifact (code and MRs)**
- MR !266536 (open, 30 Oct 2026, milestone 19.6) describes how the "Download" in the session drawer works today: "`download` (Duo sessions) and `download_session` (external agent sessions) in `Security::AgentArtifactsDownloadable` build the whole file with `Gitlab::Json.dump` and `send_data`. Its `session_summary` holds id, source, agent_type, flow_type, timestamps and project, and its events come from `AuditEvents::AiAuditEvents::ClickHouseFinder`. There is no hash, digest or signature step in it or in its Duo parent class (searched for sha, hash, sign, digest, checksum, immutable) — [governance export service](https://gitlab.com/gitlab-org/gitlab/-/blob/master/ee/app/services/ai/governance/session_artifact_export_service.rb); [Duo export service](https://gitlab.com/gitlab-org/gitlab/-/blob/master/ee/app/services/ai/duo_workflows/session_artifact_export_service.rb) (code)

**The transcript checksum is sent and dropped (code and docs)**
- The ECA doc lists, among the data sent: "When a session completes, a checksum of the transcript file." — [externally-connected-agents.md (master)](https://gitlab.com/gitlab-org/gitlab/-/blob/master/doc/user/ai-governance/externally-connected-agents.md)

The service it calls sets only `session_finished_at` and `status` and never reads the hash — [complete_service.rb](https://gitlab.com/gitlab-org/gitlab/-/blob/master/ee/app/services/ai/external_agents/sessions/complete_service.rb). **What ECA events carry (docs, issue and `glab` code)**
- Docs, "Data that is sent" (master, 1 Nov 2026):
  - "The prompts you type. Prompts over 8 KB are truncated. The first prompt also becomes the session's goal."
  - "Each tool call with its arguments, such as commands, file paths, and edits. Arguments over 8 KB are replaced with a marker."
  - "Each tool call's outcome, duration, and error message. Error messages are cut at 255 characters."
  - "The model and token usage of each response."
  - "Tool output and the text of responses are not sent, except the first 255 characters of a failed tool call's output are sent as an error message."
  - "To identify the computer, `glab` sends a hashed machine ID."
  - Per agent: OpenCode sends no prompts, model or tokens; Codex records every outcome "as completed, with no error message"; Cursor sends "Only prompts and tool calls ... because Cursor records no results, token usage, or timestamps."
  - Source: [externally-connected-agents.md](https://gitlab.com/gitlab-org/gitlab/-/blob/master/doc/user/ai-governance/externally-connected-agents.md)

The comment says "Event names and detail keys follow the audit events GitLab's own MCP server records". ### Inferences
- **Intake has arrived; integrity has not.** A sidecar can post its sessions and entries into GitLab today: a developer token, Premium, Developer role, beta. It must label each session as one of four agent types, which mislabels Goose, Copilot CLI or a self-hosted harness. The events a sidecar posts are no more trustworthy to GitLab than `glab`'s: GitLab checks neither origin nor completeness, and the client sets timestamps within a 90-day window.
- **GitLab's "immutable copy" is a convenience, not evidence.** A file rebuilt from mutable rows at download time proves only what the database holds at that moment. The transcript checksum `glab` already computes is the cheapest integrity hook in the system, and GitLab drops it. Persisting it is a plausible small upstream contribution.
- **GitLab's own design concedes the two weaknesses pitch4 can fix.** Capture is "best-effort" with no alert when a machine stops syncing, and data lost while the integration is off goes unreported. A signed, sequence-numbered ledger makes gaps visible.
- **Approvals are the clearest open field.** No ECA event carries an approval. Duo's "approve for session" hash is a matching cache the session owner can write, local Duo sessions are "ungoverned" by default, and enforcement for external agents is a Stage 1 non-goal.
- **The Anthropic pull widens GitLab's reach for Claude Enterprise customers only.** It also makes GitLab hold a key that reads every Claude Code transcript in the organization. GitLab's own design calls out push as "GitLab never holds the key", which is pitch4's posture.

### Gaps
- What GAIG Stage 2 ("later stages") will add: enforcement for external agents, approval events, retention, any integrity work. No Stage 2 design doc was found in the handbook's `ai_governance` folder (only `gaig` and `claude_compliance_api`).
- The confidential internal epic named in #633489 was not readable.
- Retention of `ai_audit_events` and of ingested transcripts (work item 623181) is unknown; only the 180-day listing window and the 30-day walk-state pruning are documented.

## 6. Across the platforms: the four properties, and what this means for pitch4

### Takeaway
Of the four properties, only intake of outside records has shipped, and only at GitLab (beta) and, loosely, at Buzz (NIP-AR artifacts). No platform ships tamper evidence a customer or third party can check. Anthropic's server-side provenance and Buzz's signed events are the nearest relatives. No platform records approvals durably for agents from other vendors. None keeps content from admins: every record is readable by the operator's admins by design, and the privacy controls that exist are admin-chosen minimization (GitHub capture classes, GitLab's hidden Slack DMs, Duo metadata retention).

So pitch4's claim narrows less than the brief feared. It must concede intake (GitLab) and a vendor-witnessed Claude Enterprise transcript (Anthropic). It keeps:
- tamper evidence that can be checked without trusting the operator, and gaps that can be detected;
- approvals bound to the action they allowed;
- content readable by the developer and the team, not by admins or the host;
- weights binding;
- coverage beyond GitLab's four agent types, beyond Claude Enterprise, and below Enterprise plans.

The sidecar should feed GitLab and Buzz rather than compete with them, and check itself against Anthropic's record where one exists.

### Inferences (directions for pitch4)
1. **Restate the record claim around what no platform ships** (differentiation; confidence high). Suggested: "Signed when written, chained so gaps show, readable by your developers and team, and not by your admins, your host or us. Every approval names who allowed what." Concede in the competitor table:
   - GitLab now ingests Claude Code, Cursor, Codex and OpenCode sessions, and takes records from outside tools (beta).
   - Anthropic keeps verified Claude Code transcripts for Enterprise.
   - Change "Vendor record ... Each vendor's, for its own product" to name GitLab as a cross-vendor recorder that is admin-readable and unverifiable.
2. **Feed GitLab AI Governance instead of building another dashboard** (offering; confidence medium).
   - Post sidecar sessions and events through the ECA API. Put each entry's digest, signature and sequence number in `details` (the 10 KB cap fits) and send `jsonl_sha256`. GitLab's dashboard and SIEM stream then show the work, and the sidecar proves the rows were not altered or dropped.
   - Offer two small upstream MRs: persist the transcript checksum, and accept more agent types or a generic source.
   - Risks: the API is labelled "experiment"; it is project-scoped, per developer and limited to four agent types; and GitLab's push alternative is "rejected for now".
3. **Lead the security story with durable, bound approvals** (differentiation; confidence high). None of the seven rows records approvals durably for outside agents. Claude Code now emits `permission_mode` and `classifier_verdict` in OTel, and GitLab's ECA events have no place for them. The sidecar can capture approvals from hooks and OTel on any plan, sign them and bind them to the tool call's arguments. Hashing canonical arguments, as GitLab's !265658 does for matching, avoids the serializer mismatch GitLab hit.
4. **Make completeness checkable** (differentiation; confidence medium). GitLab's design says capture is "best-effort" and "Nothing alerts the developer or an admin when a machine stops syncing". Its Anthropic pull accepts silent loss when the integration is off. Anthropic lists sessions whose content was not captured. Per-session sequence numbers, heartbeats and signed "session closed" entries let a reader tell "no activity" from "no record", which no platform offers.
5. **For Claude Enterprise customers, reconcile with Anthropic's record rather than duplicate it** (both; confidence medium).
   - Store Anthropic's `clls_` session ID and message IDs in sidecar entries. Report where the vendor-witnessed transcript and the developer-held record disagree, for example `client_asserted` turns or missing calls.
   - Pitch "two witnesses": Anthropic saw the request; the sidecar saw the approval, the effect on the device and the other harnesses.
   - Do not lead with Claude-only capture for Enterprise buyers.
6. **Partner with Buzz through NIP-AR, not new kinds** (offering; confidence low to medium). Write entries and approval decisions as kind-45010 artifacts with a namespaced `type`. Persist, under team keys, the NIP-AO frames the owner key can read. The team-keyed ledger stays the evidence and Buzz holds a readable, signed mirror. Nothing waits on WF-08 or #7797.
7. **Price the Team tier into the gap below Enterprise and outside GitLab** (offering; confidence medium). Per-session records are EMU-only at GitHub and Enterprise-only at Anthropic and Cursor. JetBrains returns metadata only, on Business and Enterprise. GitLab's ECA needs "GitLab Premium or Ultimate with GitLab Duo Agent Platform for the top-level group". The sidecar's $8–25 Team tier is the only cross-harness session and approval record for teams that are not on GitLab Premium and below every vendor's Enterprise plan. This is consistent with 2.08: demand below Enterprise is mainly for attribution.
