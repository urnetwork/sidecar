# Open-source harness and local-model users: unmet needs, and how pitch4 meets them (L1-1.01)

Research date: 1 November 2026. Scope: OpenCode, Goose, Cline, Roo Code, Kilo Code, Aider, Continue, OpenHands, Codex CLI, Gemini CLI, Qwen Code, and Crush, plus the local inference servers (Ollama, vLLM, llama.cpp, LM Studio) these users run. Earlier research covered Claude Code, Codex, and Cursor users in depth, so Codex is shown separately where it would dominate counts.

## 1. Which requests and complaints recur about sessions, export, search, sync, sharing, approvals, team use, and parallel agents?

### Takeaway
In open-harness issue trackers, the most common session complaints are about losing, exporting, searching, and sharing sessions (roughly 110 to 190 distinct people per theme, excluding Codex). Requests for approval or audit logs (19 people, 0 votes) and for sync across machines (13 people) are thin. On Hacker News, the session-tool space has become crowded: at least eight cross-harness session archive, search, and share tools launched between August and October 2026. OpenCode, the largest open harness, shut down its session-sharing backend on 15 October 2026.

### Inferences
- Among open-harness users, the session needs with real pull are: do not lose sessions across upgrades, moves, crashes, and concurrent agents; export the full session; search session contents; and undo file edits. Approval and audit logs come from a few regulated users, not from developers broadly. That fits pitch4's split (developers install for the vault, admins pay for the ledger), but the audit side will not drive installs.
- Sync across machines is a strong theme for Codex (32 strict items) and in prior Claude Code research. It is weak in open-harness trackers. One reason may be that OpenCode's client/server model already lets people reach a remote host ([afruitpie, HN 50095797](https://news.ycombinator.com/item?id=50095797)).
- OpenCode retiring `/share` on 15 Oct 2026 leaves its large user base without built-in sharing just as several startups offer it. That is an opening, but a contested one (see sections 3 and 5).
- Storage fragility is a recurring failure: SQLite stores corrupting under concurrent agents, VS Code globalState resets, and V1-to-V2 migrations. This argues for a vault that copies sessions out of the harness's own store, append-only, rather than indexing in place.

### Gaps
- Reddit was not reachable. The JSON API returned HTTP 403, and web search for r/LocalLLaMA threads returned only blogs. No Reddit quotes or counts are included.
- The counts are title-based and limited to each query's top 50 results, so long-tail reports in small repos (Aider, Goose, Crush) are undercounted. Discussions were searched only for a subset of themes.
- I did not check whether OpenCode's maintainers explained why they retired sharing (cost, abuse, or the October security incident). The PR text gives no reason.

## 2. What do people running local or self-hosted models struggle with?

### Takeaway
The biggest pain is not network reach. It is getting harnesses to work with local models: model discovery, tool-call formats, and timeouts. Reaching a home GPU box is mostly solved for individuals with Tailscale, and LM Studio ships Tailscale-based LM Link. The open problems are team-level: inference servers have weak or missing authentication, there is no per-user or per-agent identity, and request logs are scarce. Nobody can show which weights or quantization served a request; users distrust hosted open-weight providers on this point and are asking for checkpoint disclosure.

### Inferences
- For individual local-model users, pitch4's reach story competes with free tools that work well (Tailscale, LM Link). Its value for them is not reach. The team-level gaps are real: no authentication on Ollama, `--api-key` bypasses in vLLM, no per-agent identity, no content-free request receipts. A model-server sidecar that enforces identity and writes receipts fills that gap, but Tailscale Aperture targets the same spot.
- "Signs which weights it serves" has direct user evidence. Demand is strongest where users do not control serving (hosted open-weight plans, OpenRouter). Self-hosters already know their weights; for them the value is recording, per change, which weights, quantization, and runtime were used. The harnesses do not record this today.
- A signed model manifest from the server (weights digest, quantization, runtime and flags, context length, chat template, tool-call parser) could answer the largest local-model request (discovery, 248 👍) and the provenance record at once. This is my inference; no harness maintainer has endorsed such a format.

### Gaps
- No survey data was found on how many developers run coding harnesses against self-hosted models at work, as opposed to as a hobby.
- LM Link, Tailscale's LM Link blog post, the Inlets guide, and the SentinelLABS report were seen through search results only, not read in full.
- I found no first-person reports of a cloud agent (OpenHands Cloud, Kilo Cloud Agents, Codex cloud) reaching a self-hosted model on a home or office network. The need is plausible, but this pass did not find user evidence for it.

## 4. What do these users say about privacy, telemetry, and trusting hosted services, and what would make them adopt or reject a sidecar?

### Takeaway
Privacy and offline operation is one of the largest themes in open-harness trackers: 123 items and 284 people excluding Codex, with 489 votes. In 2026, local-model users found OpenCode sending session titles to a cloud model and contacting remote hosts while configured for local use. OpenCode then leaked provider keys stored on its servers (October 2026). The lesson users draw is that open source is necessary but not enough. They want proof of what leaves the machine, no phone-home by default, no self-updating daemons, and providers' keys kept out of agents' reach. A sidecar would be rejected if it sits in the request path as a single point of failure, depends on a cloud service by default, or is supply-chain fragile, as LiteLLM proved to be.

#### Licensing and hosting signals
- All the leading open harnesses use permissive licenses (MIT or Apache-2.0). The exceptions are Crush, under "Functional Source License, Version 1.1, MIT Future License", and Open WebUI, whose license adds a branding clause. — [Crush LICENSE.md](https://github.com/charmbracelet/crush/blob/main/LICENSE.md); [Open WebUI LICENSE](https://github.com/open-webui/open-webui/blob/main/LICENSE)
- The bar for a hosted service, as users state it: Vibivibi says "We cannot read your sessions. Not on any plan." (vendor) — [vibivibi.com](https://vibivibi.com/). OpenCode Enterprise sells "code and data never leaves their infrastructure" through a central config and an internal gateway — [enterprise.mdx](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/enterprise.mdx)

### Inferences
- For local-model users, the main leak is the harness's own traffic (title generation, model catalogs, share pages, telemetry, update checks), not the model vendor. A sidecar that enforces a local-only egress allowlist for the harness and gives a receipt of every blocked attempt answers the most-voted privacy complaints. These are complaints harness maintainers have declined to fix by default ("cannot be the default"). This is a more specific and better-evidenced promise than pitch4's current "nothing has to leave your control".
- The adoption conditions follow from the trust events:
  - permissive open source with reproducible builds and signed, pinned releases (LiteLLM)
  - no auto-updating background daemon (Codex)
  - fully functional offline (OpenCode, Crush)
  - capture that fails open and is not a required hop for model traffic (CharlieDigital's objection)
  - hosted parts that hold only ciphertext (Vibivibi sets the expectation)
  - no long-lived provider keys stored by the vendor (OpenCode leak)
- Rejection risks for pitch4: the model-access forward puts the sidecar in the path of model calls, which is the "single point of failure" objection. URnetwork's network and token association could also read as "cloud stuff" to this audience.

### Gaps
- I found no direct evidence on license preference (AGPL versus MIT versus FSL) for a sidecar or infrastructure tool among these users. Reactions to Crush's FSL or Open WebUI's branding clause were not researched.
- There is no quantitative data on how many harness users run egress blockers (Little Snitch, OpenSnitch, LuLu) or sandboxes.

## 5. Which needs pitch4 already meets, which it misses, and which would make it more compelling

### Takeaway
Pitch4 matches several evidenced needs: a vault that survives the harness, restore of file edits, approval history, weight-level provenance, and self-hosting. It misses or mis-sequences the ones open-harness and local-model users raise most: a provable local-only mode, offline and air-gapped operation on day one (pitch4 schedules it last), compatibility help for local models (discovery and templates), coverage of Pi, Cline, Kilo, and Continue, and the fact that encrypted session sharing is already sold. It overstates uniqueness on "sessions under keys" and on reach for individuals.

### Cited Findings
- Pitch4's claims tested here — [pitch4.html](/Users/brien/urnetwork/sidecar/pitch4.html):
  - "Local models leave no log. No vendor keeps one."
  - Session vault: "Archived instead of deleted, searchable on the developer's machine, secrets redacted before saving."
  - Model access: "The sidecar beside the model server signs which weights it serves."
  - Open harnesses named: "OpenCode · Goose".
  - "Sessions and actions under separate keys… Span keeps sessions private by access control, not keys. Ours."
  - "Last: inbox and assurance… an air-gapped install."
- Evidence pitch4 meets:
  - Session loss and export demand (section 1 table; for example [OpenCode #29703](https://github.com/anomalyco/opencode/issues/29703), [#9387](https://github.com/anomalyco/opencode/issues/9387))
  - Undo of file edits ([OpenCode #4704](https://github.com/anomalyco/opencode/issues/4704), [#5474](https://github.com/anomalyco/opencode/issues/5474))
  - Approval history ([OpenCode #32190](https://github.com/anomalyco/opencode/issues/32190); [Cline #9952](https://github.com/cline/cline/issues/9952))

### Inferences (directions, in order of evidence strength)
1. **Local-only proof.** Per harness, the sidecar enforces "model server only" egress and records every blocked attempt (title generation, models.dev, share pages, telemetry, update checks), with a "what left this machine" report. This turns pitch4's privacy promise from a description into a verifiable claim. Harness vendors have declined to make it the default ([OpenCode #10416](https://github.com/anomalyco/opencode/issues/10416)).
2. **Signed model manifest at the model server.** Extend "signs which weights it serves" to a manifest: weights digest, quantization, runtime version and flags, context length, chat template, and tool-call parser. Harnesses could use it for auto-discovery and configuration ([#6231](https://github.com/anomalyco/opencode/issues/6231)), and the ledger could stamp every change with it ([#41969](https://github.com/anomalyco/opencode/issues/41969), [#40544](https://github.com/anomalyco/opencode/issues/40544)). That gives provenance a daily use, which fits "one write, three readers".
3. **Offline single-user mode in the first release, plus trust hygiene.** Move air-gapped operation out of "Last". No phone-home and no auto-update daemon by default. Reproducible builds, signed and pinned releases. Capture fails open and is never a required hop.
4. **Reposition the vault as table stakes plus harness exit.** Full-content search, export that survives compaction, resilience to path moves, upgrades, and database migrations, and import from retired harnesses (Roo, OpenCode share links). Sharing should be end-to-end encrypted, revocable, expiring, and team-scoped, never public by default. Price against Vibivibi. Replace "Ours" on sessions-under-keys with the combination of sessions, signed action ledger, and governed reach.
5. **Inference-server guard for teams.** Identity at the front door of Ollama, vLLM, and llama.cpp; per-agent grants; content-free receipts that correlate request IDs; and queue visibility. Differentiate from Aperture and LM Link through per-agent grants, receipts, and the manifest, and partner with them where possible (run over Tailscale).
6. **Attribution recorded outside the commit.** Record model and weights per change in git notes or the ledger. Generate Assisted-by trailers on request from observed facts, never from the model's self-report.
7. **Harness coverage.** Name Pi (119k stars, 1.72M npm downloads a month, favored by local-model users), Cline (5.8M installs), Kilo, Continue, Crush, Aider, Qwen Code, and Gemini CLI. Lead the open side with OpenCode and Pi rather than OpenCode and Goose.

### Gaps
- Willingness to pay for local-only proof or a model manifest is untested. The evidence shows demand for privacy and provenance, not budgets.
- Whether harness maintainers (OpenCode, Pi, Kilo) would accept a manifest from the model server or an egress-receipt format is unknown.
- The installed base of company teams that run open harnesses on self-hosted weights is unmeasured. Pitch4's "best fit" segment is therefore unsized beyond Menlo's 11% of enterprise LLM spend (cited in pitch4).
