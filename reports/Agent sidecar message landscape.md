# Sell the trace between agent runs

The line this sidecar can support is **“Keep what the last run changed, and let the next one reach the machine.”** Companies that already run AI are not waiting for another coding agent, and they are not asking, in the sentences that were opened, for more value from AI. They describe tools that forget corrections, fail to plug into the systems people already use, and never become something a CEO can defend, while October 2026 homepages already sell an autonomous worker that keeps going and leaves a human to review. The seven capabilities in the brief — real-time encrypted storage with a git front end, port forwarding, a public TLS edge, an email and group inbox, team auth, an admin audit trail, and a userspace subprocess any harness can drive over a text protocol — are the user’s product description, not facts checked against a URnetwork page. URnetwork was not researched. On the primary pages that were opened, each of those jobs is claimed by at least one product, and no page describes them as one private process. Loops that have evidence compound only when something outside the actor grades the work. A sidecar can hold the trace, the route, the inbox, and the admin record. It is not an eval product, and it does not make the next run smarter by existing. **“Get more value from AI”** is absent from the heroes in this sample, sits badly against measured results that are small or self-reported, and was never shown here to be a phrase a message test has killed.

## Memory, mail, and reach are sold as separate products

As of 31 October 2026 the adjacent work is a set of categories, not one competitive set. A buyer comparing a memory API with a tunnel, or an agent inbox with a team-policy file, is comparing different jobs. No opened page describes one product that does all of them.

What vendors call memory is not one object. Mem0’s docs say it “gives your AI agents long-term memory that persists across sessions, tools, and runs,” as a managed platform or as the same engine “on your own infrastructure,” and the platform “distills them into facts” rather than committing a repo ([Mem0 introduction](https://docs.mem0.ai/introduction), [Mem0 Platform overview](https://docs.mem0.ai/platform/overview)). Letta’s MemFS is the verified git-shaped store: context “is git-tracked through MemFS,” each agent has its own repo, edits stay local until committed and pushed, and a local-only agent commits on the current machine ([Letta Agent](https://www.letta.com/agent), [MemFS](https://docs.letta.com/concepts/memfs)). The MemFS page does not mention encryption of that repo, an audit log, email, or port forwarding. Zep is the other pole: a temporal context graph of facts and changes, with customer-managed keys, VPC deployment, SSO, per-agent authorization, and both audit logs and API logs, and it is not described as git or as a laptop subprocess ([Zep concepts](https://help.getzep.com/concepts), [Zep security](https://help.getzep.com/security-compliance), [Zep governance](https://help.getzep.com/governance)). LangGraph remembers by checkpointing graph state to a database the application runs, scoped by thread, with a separate store for cross-thread memory. Nothing on that page says git ([LangGraph memory](https://docs.langchain.com/oss/python/langgraph/add-memory)).

Coding tools persist instructions, not a memory database. Claude Code starts every session with a fresh context window; project `CLAUDE.md` is shared by committing it, and auto memory loads at most the first **200 lines or 25KB** ([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works), [Claude Code memory](https://code.claude.com/docs/en/memory)). Cursor’s own rules page says models “don’t retain memory between completions,” and project rules are version-controlled files while Team Rules live in a dashboard ([Cursor Rules](https://cursor.com/docs/rules)). AgentMemory is the closest verified local text protocol: plain markdown on the machine, spawned as an MCP server with “one message per line on stdin/stdout,” with credential redaction and no account ([agentmemory README](https://github.com/jayzeng/agentmemory)). Its README does not say writes are git commits or that the files are encrypted. The Claude Agent SDK does run as a subprocess, but it runs the Claude Code binary, or the Claude CLI for other languages, not an arbitrary harness ([Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)). The OpenAI Agents SDK and LangGraph are libraries inside the caller’s application. Google’s Agent Development Kit can run locally or as a container the user operates; authentication and Cloud Trace show up in the docs when it is deployed on Google Cloud ([ADK](https://adk.dev/)).

Messaging is a different stack again. The Model Context Protocol, spec revision 28 July 2026, connects a host to tools, resources, and prompts. It does not store memory, and the spec says it cannot itself enforce the consent it requires ([MCP specification](https://modelcontextprotocol.io/specification/2026-07-28)). Agent2Agent, under the Linux Foundation, is explicit about what it is not: “Not an interactive messaging app,” and not a way for agents to share internal memory ([A2A Protocol](https://a2a-protocol.org/latest/)). Real email is a live category in the same month as this audit. AgentMail’s docs say it “gives agents their own inboxes” so they can use “the universal protocol of email,” with a free tier of **3 inboxes and 100 emails per day** ([AgentMail](https://www.agentmail.to/docs/welcome)). Resend’s 22 October 2026 launch post, nine days before the audit, leads with “The inbox for agents” and “The same inbox can be worked by people and agents side by side,” on the customer’s domain, attached to Claude Code, Cursor, Codex, and others through MCP or skills ([Announcing Inboxes](https://resend.com/blog/announcing-inboxes)). Letta’s channels are Slack, Discord, Telegram, or custom, not email. Neither inbox page that was opened describes git memory, a tunnel, or an admin audit trail.

Local reachability is a third category, already named for agents. ngrok documents exposing `localhost` through an encrypted tunnel, including so ChatGPT and Claude can call a local MCP server ([What is ngrok?](https://ngrok.com/docs/about)). Cloudflare Tunnel maps a public hostname to a local port with `cloudflared` making the outbound connection, “no public IPs required,” and calls the tunnels post-quantum encrypted ([Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/)). Tailscale Funnel, still marked beta on a page last validated 20 January 2026, publishes `https://<machine>.<tailnet>.ts.net` to a local port on 443, 8443, or 10000, and says the relay cannot decrypt the proxied bytes. The same page warns that anyone with the URL can reach the service. Tailscale Serve is the private, tailnet-only alternative ([Tailscale Funnel](https://tailscale.com/kb/1223/funnel)). None of those pages is a memory product or an inbox.

Admin control is documented, then usually buried. Zep is the clearest context product: human RBAC and enterprise SSO on one side, attribute-based policies for agents on the other, plus audit logs of membership, keys, and data operations. Mem0 says audit logs and workspace governance “ship by default” on the managed platform, and a request audit log on the self-hosted server; an SSO or key-management page was not opened ([Mem0 Platform overview](https://docs.mem0.ai/platform/overview)). Cursor can enforce Team Rules so members cannot turn them off, and Claude Code can deploy an organization-wide `CLAUDE.md`. Those are policy texts, not a trail of what the agent did. The pages opened for Anthropic’s console, Claude Enterprise, OpenAI organization logs, LangSmith admin, and Cursor’s audit log were not part of this pass, so absence here is not evidence those consoles lack logs.

The gap the pages support is composition. **Encrypted git-shaped storage is split:** Letta has the git repo and does not state encryption; Zep has customer-managed keys and does not state git. **A local text protocol is split from the network and the mailbox:** AgentMemory and the Claude CLI are subprocesses, and neither page adds a public tunnel or an inbox. **Inbox, forwarding, and audit are three vendors:** AgentMail or Resend, then ngrok or Cloudflare or Tailscale, then Zep or Mem0’s log claim. A developer who wants every job in the brief today assembles at least a memory or instruction store, a tunnel if a remote caller must hit a laptop port, and a separate inbox if the agent must send and receive mail. That is a boundary in the docs that were opened. It is not a finding that the combination is absent from the market, and it is not a finding that URnetwork is the only system that could offer it. Products that were not opened — Honcho, cognee, Supermemory, Microsoft Dev Tunnels, and others named only in search — might bundle more. “Real-time” sync, beyond Letta’s commit-and-push, was not specified on the pages opened. Whether any tunnel vendor keeps an admin-visible log of each forwarded request was not opened either.

## A sidecar can store the loop and cannot grade it

The loops with evidence are outer loops. Something that is not the acting model decides whether the work is done, and the miss is written down as a test the next run has to face.

LangSmith, Langfuse, and Braintrust sell the same engineering cycle: capture a trace, score it with code, an LLM judge, or a person, put the failure in a dataset, rerun the experiment, and gate the regression. LangSmith’s own step is to add the failing production trace to the dataset so “a failure you saw once becomes a test you run every time” ([LangSmith Evaluation](https://docs.langchain.com/langsmith/evaluation)). Langfuse documents the same loop and a GitHub Action that fails a pull request when a score crosses a threshold, on Cloud or self-hosted ([Langfuse Evaluation](https://langfuse.com/docs/evaluation/overview)). Braintrust says the production half of that loop has no answer key: “Because there’s no ground truth for live requests, it relies on LLM-as-a-judge scorers” ([Braintrust Evaluate](https://docs.braintrust.dev/evaluate/index.md)). None of these pages say the platform writes improved weights or durable agent memory by itself. The compounding step is the dataset write-back. Without it, tracing is a debugger. Langfuse is the page in this set that also says to check the judge against human labels. Weave, now documented on CoreWeave, receives traces into a vendor account; no self-host option was on the page opened ([What is Weave?](https://docs.coreweave.com/weave/concepts/what-is-weave)).

Coding loops that can compound use an oracle the agent does not grade. SWE-bench scores “% Resolved” against tests; a July 2025 news line on the leaderboard says mini-SWE-agent hit **65%** on the 500-instance Verified split “in 100 lines of Python.” The rendered page did not include a current ranking, so that figure is a 2025 note on the site, not a late-2026 leaderboard ([SWE-bench](https://www.swebench.com/)). Claude Code’s documented cycle is gather context, act, and verify, including running the tests again. The user can interrupt. Nothing on the opened page forces the test command to pass before the model stops ([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)). OpenHands treats that gap as the bug: a plain `conversation.run()` “stops as soon as the agent thinks it is done,” while `/goal` asks a second model to find “authoritative evidence” in command output, and “the agent cannot finish just by claiming success — the judge has to see the green output first.” If the judge’s JSON will not parse, the verdict stays not-done ([OpenHands goal completion](https://docs.openhands.dev/sdk/guides/convo-goal.md)). Inspect, the framework METR moved its time-horizon evals onto, wraps a task, a solver, and a scorer, and can run Claude Code, Codex CLI, or Gemini CLI inside that harness. It is how public agent evals are run, not a production memory sidecar ([Inspect](https://inspect.aisi.org.uk/index.html.md), [METR Time Horizon 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)).

Older papers showed gains from self-critique and are the wrong citation for a 2026 product claim. Reflexion, revised October 2023, stored verbal feedback in an episodic buffer and reported **91% pass@1** on HumanEval against a prior **80%** for GPT-4 ([Reflexion](https://arxiv.org/abs/2303.11366)). Self-Refine, May 2023, reported about a **20-point** absolute preference gain from the same model critiquing itself ([Self-Refine](https://arxiv.org/abs/2303.17651)). DSPy, October 2023, compiled a pipeline against a metric and reported GPT-3.5 and Llama-2 gains, generally **over 25% and 65%** against standard few-shot ([DSPy](https://arxiv.org/abs/2310.03714)). A July 2026 paper on small open models, 1.5B to 7B, on math, with every token counted, finds that story does not survive an equal budget. “No method is reliably better than repeated sampling at equal cost.” All 18 self-inspection comparisons were negative. On the smallest model, Reflexion “judged itself correct every time and silently became a single chain of thought” ([Sample More, Reflect Less](https://arxiv.org/abs/2607.28576)). That result does not refute a test-based coding loop, which spends tokens on tool output rather than on the model talking to itself. It does refute leading with “the agent reflects and gets better.”

Practitioners describe the stall in the same shape. Hamel Husain, 3 March 2026, writes that “an agent with an eval platform still needs to know what to do with it,” and that two unlike failures both labeled “hallucination” will hide the real miss. His remedy is binary judges checked against human labels, not another vendor dashboard ([Evals Skills for Coding Agents](https://hamelhusain.substack.com/p/evals-skills-for-coding-agents)). The headline numbers he attributes to an OpenAI harness-engineering post were not checked against that post and are not used here. METR’s 29 January 2026 note is a lab admitting a loop had stopped meaning what it measured: tasks that were easy to reward-hack, and scoring functions that were wrong, were removed or rewritten, and only **5 of 31** long tasks had measured human times. Doubling-time estimates moved when the suite moved ([METR Time Horizon 1.1](https://metr.org/blog/2026-1-29-time-horizon-1-1/)). Claude Code’s own docs are the product version of a loop that does not carry forward: new session, empty transcript, compaction that can drop early instructions, auto memory capped at 200 lines or 25KB. A fix compounds only if someone put it in `CLAUDE.md` or it survived that cap. No opened 2026 source measured stale memory as a numeric failure rate. No opened source gave a measured wait time for a human review queue.

What a sidecar can be, given this brief and these notes, is the place those artifacts sit: a git-shaped context store the next session can open, a shared inbox, a route to a service on the machine, and a record an admin can read. That is adjacent to the artifacts Anthropic tells engineers to leave for the next session — a progress log, a feature list, git commits — and adjacent to the practice Every calls compound engineering, where the lesson from a review is written back so the next agent and the next hire inherit it ([Every, 11 Dec 2025](https://every.to/chain-of-thought/compound-engineering-how-every-codes-with-agents)). Every is describing five of its own products, not a survey, and the write-back is a step people do. The sidecar does not perform it.

What a sidecar cannot be, on these notes, is the loop. It does not score a trace, build a dataset, fail a pull request, or stop a model that declares itself done. It does not update weights. “Local” also splits in two, and the brief does not close both halves. Claude Code’s default execution stays on the machine; the opened page does not say the model prompt stays there. LangSmith’s default is an account at smith.langchain.com, with self-host and bring-your-own-cloud marked Enterprise ([LangSmith platform setup](https://docs.langchain.com/langsmith/platform-setup)). Langfuse can run with internet access optional, and its evaluations can still call a model API ([Langfuse self-hosting](https://langfuse.com/self-hosting)). A private store for context, mail, and audit is closer to that self-hosted trace box plus a local harness than it is to LangSmith Cloud. The dataset-and-CI loop those products sell is a different job, and selling the sidecar as if it were that loop would claim an eval product the notes do not support.

## Buyers say the tool does not learn, not that they need more AI

The buyer document that was actually opened is a third-party rehost, not an mit.edu original. The PDF’s title page reads “The GenAI Divide / STATE OF AI IN BUSINESS 2025,” authors Aditya Challapally, Chris Pease, Ramesh Raskar, and Pradyumna Chari, July 2025, hosted at Cloudelligent ([NANDA v0.1 PDF](https://cloudelligent.com/wp-content/uploads/2026/02/v0.1_State_of_AI_in_Business_2025_Report.pdf)). Page 2 calls it preliminary findings, research period January–June 2025, authors’ views only: a review of over 300 public initiatives, interviews with 52 organizations, and 153 senior leaders at four conferences. Several exhibits are labeled directional, not official company reporting. The same PDF uses “95%” for more than one denominator. Those are not one fact, and the viral sentence “95% of AI projects fail” is not how to quote them.

What the interviews say, in the buyers’ words, is that the tool does not keep the work. A corporate lawyer: “It’s excellent for brainstorming and first drafts, but it doesn’t retain knowledge of client preferences or learn from previous edits. It repeats the same mistakes and requires extensive context input for each session.” Exhibit labels on that spread include “Too much manual context required each time” and “It doesn’t learn from our feedback.” Another line: “It’s useful the first week, but then it just repeats the same mistakes. Why would I use that?” The report’s own summary: “The core barrier to scaling is not infrastructure, regulation, or talent. It is learning. Most GenAI systems do not retain feedback, adapt to context, or improve over time.” Reach is a separate sentence, just as blunt: “If it doesn’t plug into Salesforce or our internal systems, no one’s going to use it.” Beside it: “I can’t risk client data mixing with someone else’s model, even if the vendor says it’s fine.” The procurement wish list in that PDF is learning from feedback (**66%** of executives in their coding), retaining context (**63%**), a deep fit to the workflow, minimal disruption, clear data boundaries, and flexibility when the process changes. The dividing line they draw on a forced choice — AI or a junior colleague — is not intelligence. For complex multi-week work, **10%** preferred AI and **90%** a person. For quick tasks, **70%** preferred AI. The authors’ gloss: “The dividing line isn’t intelligence, it’s memory, adaptability, and learning capability.”

The same PDF is where “shadow AI economy” is named. “While only **40%** of companies say they purchased an official LLM subscription, workers from over **90%** of the companies we surveyed reported regular use of personal AI tools for work tasks,” often without IT approval. Generic chat is the part that is deployed and liked: over 80% explored or piloted ChatGPT or Copilot, nearly 40% report deployment, and the authors say the pilot-to-implementation rate for generic chatbots is about 83%, which “masks a deeper split” because those tools “primarily enhance individual productivity, not P&L performance.” Task-specific tools are the harsh exhibit: about **60%** evaluated, **20%** piloted, **5%** reached a bar the authors define as someone remarking a “marked and sustained productivity and/or P&L impact.” “Internal builds fail twice as often.” A CIO: “We’ve seen dozens of demos this year. Maybe one or two are genuinely useful. The rest are wrappers or science projects.” Top performers in their interviews reported about **90 days** from pilot to full implementation; enterprises took nine months or longer. The PDF says those deployment figures are directionally accurate from interviews, not official reporting. A Fortune 1000 pharma procurement lead asks the question a value slogan does not answer: “If I buy a tool to help my team work faster, how do I quantify that impact? How do I justify it to my CEO when it won’t directly move revenue or decrease measurable costs?”

The executive-summary “95%” is this sentence: “Despite **$30–40 billion** in enterprise investment into GenAI, this report uncovers a surprising result in that **95% of organizations are getting zero return**.” A later section uses “the 95% failure rate for enterprise AI solutions” for a different cut. Do not merge those with the 5% production figure, and do not cite “67% of purchased solutions succeed.” That number was in secondary coverage and was not on the PDF pages read. The budget split also contradicts itself: one sentence puts about 70% of a hypothetical AI dollar on sales and marketing, and the research note on the next page says about 50%. Neither number is used here as a finding. Back-office is where the authors say ROI shows up. “Tools with low setup burden and fast time-to-value outperform heavy enterprise builds” is their takeaway, not a measured distribution. It is the nearest support, still only a takeaway, for talking about a userspace process that a team can start without a nine-month platform build.

Other opened studies do not rescue a single ROI sentence. Stanford’s 2025 economy chapter says organizational AI use jumped to **78%** from 55%, and generative AI in at least one function to **71%** from 33%. “Most companies that report financial impacts from using AI within a business function estimate the benefits as being at low levels.” Where service-operations respondents report cost savings, most of those reports are **under 10%**. Where marketing and sales respondents report revenue gains, the most common increase is **under 5%**. The same report also says research “confirms that AI boosts productivity and, in most cases, helps narrow skill gaps.” Both sentences are on the opened pages. They are not the same claim ([Stanford HAI 2025 economy chapter](https://hai.stanford.edu/ai-index/2025-ai-index-report/economy)). The 2026 Index overview says organizational adoption reached **88%** and that U.S. consumer value of generative tools “reached **$172 billion** annually by early 2026,” and that OSWorld agents “still fail roughly 1 in 3 attempts” ([Stanford HAI 2026 overview](https://hai.stanford.edu/ai-index/2026-ai-index-report)). The economy-chapter body was not opened. A secondary “14% to 26% productivity” line was not on the overview and is omitted.

METR is the warning against leading with felt speed. In a July 2025 randomized study, 16 experienced developers on repositories they knew took **19% longer** with early-2025 tools, had expected to be **24% faster**, and after the slowdown still believed they had been **20% faster**. The authors say this does not show that AI fails to speed up most developers. The page now says the results are out of date; the February 2026 update was not opened ([METR RCT](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). A March 2025 time-horizon post, also flagged on the page as partly out of date, said models succeed almost always on tasks under about four minutes and **under 10%** of the time on tasks over about four hours ([METR, 19 March 2025](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/)). The later 1.1 rewrite was opened in the loops pass and is the one to cite for scoring problems, not as a license to keep the March doubling time. METR’s May 2026 survey of 349 technical workers, a convenience sample with about a **2%** email response rate, found a median self-reported **1.4–2x** change in the value of their work and a median **3x** self-reported speed change. The author says there are “tentative reasons to be skeptical of the magnitude,” and that public survey estimates have run hotter than field experiments ([METR survey](https://metr.org/blog/2026-05-11-ai-usage-survey/)).

Operator essays use a different dialect for the same break, and they are not surveys. Anthropic’s long-running-agents post, whose fetched body has no byline date: “each new session begins with no memory of what came before.” “Compaction isn’t sufficient.” The failure modes they name are a half-finished feature, and a later session that sees progress and declares the job done ([Anthropic, long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). Chroma’s July 2025 study of 18 models: performance “degrades as input length increases” even when task difficulty is held fixed, and on one memory eval focused prompts around **300 tokens** beat full histories around **113k** ([Chroma](https://www.trychroma.com/research/context-rot)). Anthropic names that “context rot” and treats context engineering as the successor to prompt engineering ([Anthropic, context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). LangChain, 2 July 2025, calls it “filling the context window with just the right information at each step,” citing Karpathy, and splits scratchpads inside one session from memories across sessions ([LangChain](https://www.langchain.com/blog/context-engineering-for-agents)). Cognition, in a 2025 post with no calendar byline in the fetched body, says “running multiple agents in collaboration only results in fragile systems” when context is not shared, and states the principle as “Share context, and share full agent traces, not just individual messages” ([Cognition](https://cognition.com/blog/dont-build-multi-agents)). “Context engineering” is crowded among those builder pages. It is shop talk to the NANDA buyer, who says “it doesn’t learn” and “it doesn’t plug into Salesforce.”

Angie Jones, in a 5 December 2025 essay on The New Stack, not on block.xyz, says Block has **60%** of a workforce of about 6,000 using goose weekly, connected to Slack, Drive, Snowflake, Databricks, and Jira. She describes handoffs as the thing that protects quality and slows the work, and she describes legal approval, curated extension lists, and a split between what users can read and what they can modify as “design choices that let teams move fast.” No P&L figure is in the essay ([The New Stack](https://thenewstack.io/ai-agents-are-morphing-into-the-enterprise-operating-system/)). Every, 11 December 2025, names “compound engineering” for a loop whose last step writes the bug, the failed test, or the insight back into the system. No other opened source uses that phrase. “One developer can do the work of five” is explicitly their experience. Jones’s “enterprise operating system” and “central conductor” are her framing for an agent that already reaches internal tools. They are not a description of a sidecar.

Phrases that were not on any opened page, and should not be written as if buyers already say them: “institutional memory,” “private-by-default,” “non-human identity,” and any line that agents need an office, an inbox of their own, or a colleague identity. Anthropic’s “inboxes” are an analogy for how humans keep pointers. NANDA’s “junior colleague” is a survey prompt. Search hits on identity and institutional knowledge were not opened. No conjoint, win/loss, or message test was opened, so the split between table stakes and a new job is an inference from what these sources call already deployed versus what they still call the barrier. Table stakes, on that reading, are a chat tool people will use, some reach into systems of record, a permission boundary so security will allow the reach, and in-session tricks such as compaction. The job they still call open is accumulation: less re-explaining, fewer repeated mistakes, a trace the next person or agent can pick up, and a path from individual use to something that shows up beyond a feeling of speed.

## Lead with a trace the next session can use

**Recommended line: “Keep what the last run changed, and let the next one reach the machine.”** It is the one sentence that joins the two pains buyers actually voiced — the tool forgets the correction, and a tool that cannot plug into the systems people use will not be used — and it points at two features in the brief, the git-shaped store and port forwarding plus a public TLS edge, without a productivity multiple or a claim that nobody else is nearby.

That line fails in three rooms. It fails with someone shopping for an autonomous engineer, because Cursor, Devin, Codex, Amp, and Copilot are selling the worker, and a side process sounds like infrastructure they did not come to buy. It fails with a buyer whose “internal systems” are Salesforce and a warehouse API rather than a port on a machine they control; the NANDA sentence is about systems of record, and ngrok, Cloudflare Tunnel, and Tailscale already answer the laptop-port version. It fails with a team that wants Letta’s “machines that learn” or Mem0’s persisted facts, if the next sentence does not say this is a record the team writes, in a process the harness they already run can drive, with the inbox, the auth, and the admin trail in that same process. Left alone, the line is a memory ad in a category that already has heroes.

**“Get more value from AI” should not be the lead.** It was not a hero in the sample. The nearest owned line is Glean’s “More value from every query.” The opened buyer document does not ask for more value. It says the individual chatbot already provides it, and that this is not the P&L outcome. Stanford’s 2025 chapter says that where companies report dollars, those dollars are usually small, at the same time as adoption is already high. METR showed experienced developers slower while certain they were faster, and a year later showed a broader sample reporting 1.4–2x value with an author warning not to treat the larger number as ground truth. Yale and HR Dive, in the week of this audit, say the payoff is not showing up as cost saved or as time reused, with the caveats above on who actually published those studies. The pharma lead’s question is how to justify a tool that only helps the team work faster. The line blurs three facts that can all be true: personal chat feels productive, function-level money is usually a few percent where it is reported, and task-specific systems rarely clear a sustained bar in that preliminary sample. It fails with the operator who has already bought Copilot and cannot defend the next seat, and with the engineer who has read that self-reported speed can be wrong. It does not fail because a slogan test proved fatigue. No such test was opened. Vendors are still saying “move faster” in the same week the commentary says the handoff is absent. Draw the distinction in public between a speed claim and a continuity claim. Do not pretend the speed claim has been retired.

Five alternates, each tied to one pain and one feature in the brief.

**“The correction from last session is already in the repo.”** The pain is the lawyer’s: extensive context every session, the same mistakes again, “too much manual context required each time.” The feature is the brief’s encrypted store with a git front end. It fails with teams who will not write the correction down. Claude Code’s cap and Every’s essay say the same thing from opposite sides: the store does not create the lesson. It also fails against Mem0, which sells facts distilled for you, and with anyone who hears “repo” and thinks this is another place to host application source. Do not add “real-time” to the line unless the product’s sync is something you are willing to contrast with Letta’s commit-and-push. The opened pages did not establish a real-time git memory product to beat, and they also did not establish that the brief’s sync behaves as advertised.

**“The agent calls the service on the machine, through a TLS name you control.”** The pain is “if it doesn’t plug into Salesforce or our internal systems, no one’s going to use it,” plus the shadow pattern of personal tools that never touch those systems. The features are port forwarding and the public TLS edge. It fails with teams that already publish localhost through ngrok, Cloudflare, or Funnel, who will hear a commodity tunnel, and with security readers who know Funnel’s own warning that possession of the URL is access. It fails hardest with the buyer whose system of record is not a local port. Pair it with the data-boundary sentence only if you can say who holds the keys. Zep already says the customer controls the key that encrypts data at rest. A public edge is an exposure decision, not a privacy headline.

**“One inbox the person and the agent both work, on your domain.”** The pain is handoffs — Jones’s account of work waiting on the next function — and shadow chat that never becomes a shared thread. The feature is the email inbox and group inbox in the brief. It fails with engineering teams whose homepages already name Slack, not mail, as the place work is handed to an agent. It fails as a category claim because Resend’s 22 October 2026 post already says “The inbox for agents” and that people and agents work the same inbox, and AgentMail already sells agent inboxes. The line is usable only as a piece of the process, next to the store and the trail. A2A’s own page says it is not that inbox, so do not describe email as the agent-to-agent protocol.

**“See what the agent read, and what it was allowed to change.”** The nearest pains are Jones’s read-versus-modify boundary and the NANDA line about client data mixing with someone else’s model. The features are the admin audit trail and team auth. It fails with the economic buyer in that PDF, who did not say “audit trail,” “non-human identity,” or “review bottleneck.” Those words were not in the opened interviews, and a message that leads with audit is ahead of the sentences those buyers used. It also fails with a security team that already checks SSO, SCIM, and audit logs on Devin, Dust, Zep, or Sourcegraph and will file the claim under table stakes. “Easy auth” is how those enterprise blocks already read. Use this line for the admin who has to allow the reach, after the continuity line has earned the meeting, not as the homepage.

**“Drive it from the harness you have. Don’t move the work to a new agent.”** The pain is the CIO’s “wrappers or science projects,” the shadow split between official subscriptions and personal accounts, and internal builds that the NANDA authors say fail twice as often as external ones. The feature is the brief’s userspace subprocess and text protocol, driven by whatever harness is already in use. It fails with buyers who want Dust’s “multiplayer” workspace or Jones’s “central conductor,” a hosted place where the agent is the product. It fails with a team standardized on one cloud agent who does not feel harness lock-in. The Claude Agent SDK already runs as a subprocess of Claude Code, and AgentMemory already speaks a line-oriented protocol to MCP clients. The distinction to state, without a uniqueness claim, is that those opened pages do not also include the encrypted git store, the tunnel, the inbox, and the admin trail.

### What not to say

Do not say “get more value from AI,” “10x developers,” “AI workforce,” or that the product replaces headcount. The first was missing from the heroes, the second was missing entirely, the third appeared only as docs metadata, and Copilot’s own FAQ refuses the replacement reading. Do not say “95% of AI projects fail,” and do not pick one of the PDF’s 95% figures and drop the denominator. The file is a preliminary, third-party rehost, the exhibits are directional, and the budget pages disagree with each other. Do not import the McKinsey snippet figures that were never fetched, the “67% of purchased solutions succeed” line that was not on the pages read, the Stanford “14% to 26%” productivity line that was not on the overview, or the July 2025 slowdown and the March 2025 doubling time as if they were METR’s latest word.

Do not say URnetwork is the only product that does this, or that the combination was proven absent from the market. Say that the opened primary pages split the jobs, and stop. Do not say the model never sees the data, or that buyers are asking for “private-by-default.” Hosted-model agents still send the working context to an API. The opened buyer sentence is about client data mixing into someone else’s model, which is a boundary complaint on top of shadow SaaS, not an air-gap pitch. Do not headline “context engineering” or “agent harness.” The first is the mid-2025 builder cluster of Anthropic, LangChain, and Cognition. The second is Anthropic’s name for the shell around Claude Code, and crowding of “harness” across 2026 blogs was not established because those pages were not opened. Do not say the product learns, compounds, or evaluates. Learning is the wish in the interviews and the practice in Every’s essay. Evaluation is LangSmith, Langfuse, Braintrust, and Inspect. A store that the team does not write back into will still repeat the mistake, which is the failure those sources describe. Do not say “software factory,” “office for agents,” or “institutional memory.” The first is already two companies’ H1. The other two were not found on the pages opened.

## Conclusion

The company that already runs AI is living on two clocks, and the slogan welds them together. On the personal clock, chat is deployed, shadow accounts are widespread, and self-reported speed runs hot, including in the study where experienced developers were actually slower. On the organizational clock, the opened measurements are small function-level percentages, a preliminary sample in which task-specific tools rarely clear a sustained bar, and a week of commentary saying saved time is not being reused. A sidecar cannot move the second clock by holding bytes. It can serve that clock only if the team uses it as the surface where an external check — a test, a review, a judge someone has compared to human labels — gets written down for the next session.

That is a narrower job than the heroes on offer, and it is the job the interviews keep describing. The agent products are selling a worker that does not stop. The memory products are selling persistence. The tunnel and inbox products are selling one channel each. The eval products are selling the grade. The brief sits in the crack between those pages: a private process the current harness can drive, where the last change, the route to the machine, the shared thread, and an admin’s view are the same system. Whether that crack is large enough to buy is not something these sources measure. What they do measure is the cost of claiming the wrong clock. A continuity line can be checked against the next session. A value line asks the buyer to relitigate a feeling they already have.
