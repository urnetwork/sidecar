URnetwork · Sidecar1 / 6 · The idea

One write, three readers

Every agent leaves a trail. Only your team can read it.

The problem

Teams now run several coding agents, such as Claude Code, Codex, Cursor, and Copilot, and switch between them often. Each harness keeps a partial record, and most tools an agent uses belong to vendors that can read them.

  • Sessions vanish. Claude Code deletes them after 30 days.
  • Edits escape. Shell and subagent edits skip checkpoints.
  • Handoffs break. Work rarely follows you across harnesses.
  • Approvals go dark. Nothing records who clicked "Allow."
  • Tools read everything. Their vendors hold the keys.

The idea

Sidecar is a small local process that runs beside any harness. It gives each agent six tools: storage, email, a TLS edge, inter-agent messaging, port forwarding, and an IP address. It captures each action once, from those tools, the harness's hooks, and the filesystem, and writes it once: the raw session to the developer's vault, a signed entry to the team's ledger. Agents, developers, and admins all read that one write.

Private

Nothing is public until you publish it. Each agent has its own identity and grants. URnetwork cannot read your data.

Anywhere

The sidecar dials out, so every tool works behind NAT and firewalls, on laptops, CI runners, and cloud sandboxes.

End-to-end encrypted

Keys are made and kept on your devices. Everything is encrypted before it leaves, so relays hold only ciphertext.

Why the tools feed the record

Each tool exists elsewhere on its own. Here, using a tool writes the entry, so the record stays complete in whichever harness the agent runs.

Private from us. Actions and approvals complete for your admins. Sessions stay with their author unless shared.

Private, anywhere, end to end

Privacy rests on keys you hold, not on whose network the bytes cross.

The model provider still sees whatever the harness sends it. Search and summarization run on members' machines. The full list of what our servers can see ships with the threat model.

Anywhere, no open ports

  • Outbound only. The sidecar dials out: no inbound ports, router changes, or static IPs.
  • Userspace. It runs as a subprocess of the harness, so it works in CI runners and cloud sandboxes.
  • Stable identities. The address, the TLS name, and the private IP follow the agent across networks.

Today Codex cloud supports only Tailscale, Cursor's private route is Enterprise-only, and no harness vendor documents a cloud agent reaching a developer's own machine.

Safe by default

The sidecar holds all three legs of the lethal trifecta: private data, untrusted input, and a way out. It keeps them apart.

  • Untrusted mail cuts off send, forward, and publish until a person approves.
  • Public names are authenticated and short-lived; agent control panels are refused.
  • Edits to CLAUDE.md, hooks, and .mcp.json go to review.
  • Shared writes are scanned for secrets.

Knostic found 1,862 MCP servers open to the internet. None of 119 it checked required authentication to list tools.

Proof before the claim

Before the first public use of "end-to-end encrypted":

  • The sidecar client ships as open source.
  • An independent audit covers the client and the protocol.
  • A threat model assumes a malicious server and lists all metadata we see.
  • A dated warrant canary and current transparency reports return.

The network gives reach, nothing else

  • The sidecar has no token. It uses URnetwork's network only for worldwide reach.
  • The network carries only ciphertext. Storage and mail run outside it.
  • The inbox and the edge default to your own domain.
  • Agents leave only through exits you run, so sign-ins never come from addresses Okta or Entra flag as anonymizing.
