URnetwork · recURd1 / 6 · The idea

One write, three readers

Every agent leaves a trail. Only your team can read it, and anyone can read the code.

The problem

Teams run several coding agents — Claude Code, Codex, OpenCode, Goose — some on open-weight models they host. Each keeps a partial record, and none controls how its agents reach the world outside.

  • Sessions scatter. The CLI clears them at 30 days; each vendor keeps only its own.
  • Edits escape. Shell and subagent edits skip checkpoints.
  • Handoffs break. Work rarely follows across harnesses.
  • Approvals don't travel. Each vendor's, unsigned and unbound to the action.
  • Reach is shared, not scoped. One grant covers every session and run.
  • Local runs go unrecorded. No vendor keeps a record you control.
For developers

Never lose a session or an edit, whichever harness made it.

Every session goes to a vault under the developer's own keys, and every change gets a restore point, whatever tool path or model made it.

For security buyers

Every way your agents reach the outside world is private, approved, and on a record only your team can read.

Forwards, private addresses, and model servers first, then public names, then mail. Each is a scoped grant with a signed receipt; every run lists what it could not see.

How it works

recURd runs a small open-source sidecar beside any harness. It captures each action once — from the harness's hooks, the filesystem, and its own traffic — and writes it once: the raw session to the developer's vault, a signed entry to the team's ledger. Agents coordinate, developers continue, admins answer.

Why one write matters

Audit-only logs are overhead, so they get bypassed. Here agents need the entries to coordinate and developers need them to recover, so the record fills itself.

Open source

You don't have to trust us. recURd, its relay, and the entry format are open; self-host any part, air-gapped if needed. It is plain git underneath.

Private from us. Actions and approvals complete for your admins. Session contents stay with their author unless shared; in teams, run titles are visible by default.

Session vault Why they install

Every session from every harness and model, under the developer's own keys. Kept on your retention policy, not a vendor's timer; searchable on the developer's machine; secrets redacted before saving.

Change set and restore Why it stays on

Every file a run changed by any tool path, including shell commands, subagents, and reverts. Restore previews first, stays inside the run's own changes, and is recorded.

Pick up anywhere

Continue a run on another machine, in another harness or model, or as a teammate. Handoff notes record decisions, not transcripts.

Context that loads

Team context written into each harness's own files, such as AGENTS.md and CLAUDE.md, with a warning before a harness truncates it.

Agents that find each other's work

Claims and leases across harnesses, so two agents don't edit the same files, and the next run starts where the last one stopped.

Admins see actions and approvals, not transcripts. Session contents open only when the developer shares them, and every admin read is visible to the developer. In teams, run titles are visible to teammates by default.

Reach is shared, not scoped, today

Codex cloud supports only Tailscale, which warns Codex "could reach nearly everything in your tailnet." No vendor scopes a hosted run to one service on a developer's machine, with an approver and expiry.

Easy exposure has already gone wrong

Knostic found 1,862 MCP servers open to the internet; none of 119 checked required auth to list tools. And 68% of organizations cannot tell agent activity from human (CSA, Aembit-sponsored).

What admins can answer

  • Which agents, harnesses, and models touched which repos, for which sponsor.
  • Who approved each action: one action ID, SSH-signed for high-risk steps.
  • Proof for a client that a person approved a change, without the code.
  • One switch revokes an agent's forwards, addresses, names, and mail.

Safe by default

recURd holds the three legs of the lethal trifecta — private data, untrusted input, the way out — apart.

  • Untrusted mail cuts off send, forward, and publish until a person approves.
  • Edits to CLAUDE.md, hooks, and .mcp.json go to review.
  • Shared writes are scanned for secrets, and recURd keeps no long-lived ones.

What encryption changes, and what it doesn't

With customer-managed keys the vendor still decrypts and may keep records outside your key. recURd's relay and storage hold no key, so a subpoena or breach yields only ciphertext and the metadata listed here; blindness shortens the review but a DPA, subprocessor list, and breach notice remain. Where it ends: a hosted model sees what the harness sends unless you run it; outside mail is ordinary SMTP; signed membership stops a breached server adding a reader.

URnetwork · recURd6 / 6 · The plan

Proof before scale

One open-source capture engine, ten to fifteen design partners, and published trust documents come before the rest of the build.

What ships, in order

First release, open source

The vault, change sets and restore, approval receipts, run inventory and agent identity, handoffs and claims, commit-to-run links, and the instruction-file writer.

Reach: port forwarding, private IP addresses (Linux and WSL2 first), and access to model servers you run.

Next: the team layer

The shared signed ledger, SSO and SCIM, SIEM export, retention, the verifiable log, client packets, reach receipts, and a supported self-hosted install.

Reach: the TLS edge, and approval by email reply.

Last: inbox and assurance

The visible audit member, key-escrow options, legal hold, compliance mappings, and an air-gapped install.

Reach: mail with the outside world on your domain, and group inboxes.

Each stage ships whole. Reach comes first, built on code URnetwork already runs; email, the heaviest build, comes last.

Ten to fifteen design partners

Teams of 5 to 150 engineers on two or more harnesses, drawn from the beachhead, including two or three that run open weights. Each question has a measure, and a decision if the answer is no.

Trust documents first

Before "end-to-end encrypted" appears in public:

  • recURd, the admin app, relay, and entry format ship open source, with reproducible builds.
  • An independent audit covers the client and the protocol.
  • A threat model assumes a malicious server and lists all metadata our servers see.
  • A data-flow diagram and subprocessor list, a self-service DPA, and a dated warrant canary.
  • A plain statement: recURd has no token, and uses URnetwork's network only for worldwide reach.

Risks we manage

  • Scope. One capture engine and one entry format; each stage ships whole.
  • Completeness. Hook behavior differs by harness (some fail closed, some open), so each run states what the record could not see.
  • Free built-ins and self-hosting. We sell hosting we can't read, the team layer, and support.
  • Open rivals. Block's Buzz is closest; we partner first and record Goose like any harness.
  • Reputation. Trust documents come before claims, and agents leave only through exits you run.
