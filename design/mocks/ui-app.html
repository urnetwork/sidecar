five tabs

Connect

Unchanged apart from the tab bar, which now carries five tabs with icons and titles. The connect graphic, the drawer and the split layouts on wide windows stay as mmm/DESIGNSTYLE.md has them.

Burner

A main inbox, <me>@<mynetwork>.ur.network, beside per-use categories that work like a password manager: each category is its own address with a password, a one-time code and notes. Inboxes with custom names, one unified view and a view per inbox, with search. The indexer's status sits at the top; with no indexer, a small indicator offers one in an enclave.

Sample network: ravenwood.ur.network. Sites and senders are made up.

Bot

The Harness as a CLI made for a phone. Four pills across the top: the current harness, the current model, the agent count and the compute balance. Each opens its own screen: harnesses (switch, or create a remote one), models (modes, names and cost), the agents' feed (every agent's updates, with a chat that can @mention one agent or speak to all) and where the balance went (30 days and all time). Each agent is tagged with its harness, the device or client name it runs on, and its card shows its IP, email address and public TLS names (UI-4). The person and every agent can search the web without an account, through Parallel (UI-17; Q-OB-18). A session pill shows the current session and opens every session, by recency, with the harnesses using each; a harness can switch into a session no harness is using, sessions can be shared by several harnesses, started and compacted (UI-8, UI-9).

Support

The chat with URnetwork support, where the person posts messages, attaches logs and screenshots, and gets replies. Every item the person or their agents send is one thread, in time order, each with a status. This is the one URnetwork surface that reads what people write, so it says so before the first message and above the composer.

Account

As today, with Leaderboard moved in as a row under the account card. The compute balance gets a row here too, opening the same screen as the bot's balance pill (T7). Team and Bridge, the two sections UI-3 adds under Account, follow below; in a personal network, Team's row is Create a team, the upgrade to the Team plan (A4, UI-14).

Account › Team

Managing a team, under Account: every way to bring people, devices and servers in; permissions as roles (RBAC) that follow the design, each role with its own IPv4 range for the bridge; and the team-only features, a custom domain and the team's own identity provider. The sample is the team network acme, where sam is an Admin.

Account › Bridge

The network's endpoints in one place: every device with its IP, its roles, its public TLS names, the local ports it listens on and the ip:port forwards it makes, and how each can be reached. Seen from this phone, each entry also says whether this phone may reach it, and the rule that would open it if not.

Q-UI-25"An ipv4 and ipv4 subnet" for each role (UI-3): what is it?
Decided, as recommended: One IPv4 range per role, carved from the network's /16, from which each device whose first role it is takes its address. No IPv6, since the bridge has none (owner decision 28: "no IPv6 overlay"). If an address for the role itself was meant, such as a gateway, the overlay has no use for one: every device is reached at its own address.
TM3-TM6, BR1
Q-UI-26How do roles sit on the design's model?
Decided, as recommended: People and devices may hold several roles. The seven built-in roles keep DESIGN's management rights (§7.5); a team's own roles carry network access and any management rights an admin gives them. The app writes roles into the signed policy as groups for people, tags for devices and rules between them, so enforcement stays DESIGN's (§8). An identity-provider group can map to a role through SCIM.
TM5-TM8
Q-UI-27A device with several roles: which range gives its address?
Decided, as recommended: Its first role's. Changing the first role moves the device to an address in the new range; its private name stays, and the old address is held 30 days (DESIGN §17.4's tombstone). What the device may reach is the union of all its roles' rules.

A full range holds new devices for that role until an admin grows it. This replaces DESIGN's random host address (§17.4).

Q-UI-36Several harnesses share a session (UI-9): what does sharing mean?
Decided, as recommended: One harness runs the session's agent at a time, which claims it; any other harness joins it to watch it live and add prompts, which go to the running harness (COMPUTE §7.10's attach). When the running harness lets go, the session is unclaimed and any harness can switch into it (§24.7). The other reading, several harnesses each running turns in one session, needs a way to order their turns that the design doesn't have.

Q-UI-47A team's first seat is a store subscription and its other seats are Stripe's (Q-UI-46): how do they combine?
Decided: the store bills its subscription, which covers the first three seats, and Stripe the rest; the team's seats are their sum. A person joining takes a free seat, else the inviting admin is sent to ur.io to add one. If the store subscription lapses, the Stripe seats keep the team going; if all lapse, the network drops to Pro's caps, nothing deleted.
