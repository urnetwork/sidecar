# Fact sheet: server runtime platform for new horizontally scaled sidecar services

Research date 2026-11-03. Paths are relative to `/Users/brien/urnetwork`. I read vault and config files for their structure only: no secret values, hidden route prefixes or TLS key material were opened or copied. Where a design note and the code disagree, the code wins, and §5 lists each case.

## 1. Summary

1. **What a service is.** A service is `server/cli/<svc>/{main.go,Makefile,Dockerfile}` plus a `services.<svc>` block in a new top version of `vault/<env>/services.yml`. `warpctl build` checks the binaries with govulncheck before it publishes a multi-arch image. `warpctl deploy --percent` writes a per-block version selector to DynamoDB. A run worker on each host then swaps the block's container blue/green, gated on `/status` from service port 80. Sources: `warp/README.md:265-294`, `warp/warpctl/dynamo/client.go:17`, `warp/warpctl/run.go:1453`, `:2310-2315`.
2. **Scaling and placement.** Capacity is blocks × lb hosts. By default a service runs every block on every host that has an lb interface. Each lb proxies only to blocks on its own host, weighted by block, using `least_conn` (or `hash $remote_addr consistent` when the service is `stateful`). Sources: `warp/services/services.go:518-551`, `warp/warpctl/config.go:1008`, `:1646-1665`.
3. **No SNI passthrough today.** The nginx lb config is generated by `warpctl lb create-config` and baked into the lb image at build time (`warp/lb/Makefile:58`, `warp/lb/Dockerfile:107`). The http block owns TCP 80 and 443, terminating TLS with static vault certificates. A stream block exists, but each stream server maps one port to one upstream. TCP stream servers send `proxy_protocol on` (PROXY v1) and UDP servers send `proxy_protocol v2`. The binary is built with `ssl_preread` (`warp/lb/Dockerfile:58`), but the generator never emits `ssl_preread`/SNI routing. Sources: `warp/warpctl/config.go:1225`, `:1377`, `:2477-2525`.
4. **Public ports today.** On the 10 lb interfaces: TCP 80 and 443, plus UDP 443 and 4053 (stream to connect) and UDP 53 (DNAT to 4053). The 2 transparent hosts serve alt's UDP 443, 4053 and 53, plus proxy's TCP ports. There is no SMTP port, no TCP 53 and no 853 (`vault/main/services.yml:338-347`, `:451-475`, `:776-790`, `:856-861`).
5. **Data stores.**
   - **Postgres:** a single primary on edge-2 behind PgBouncer in transaction pooling mode (`config/main/db.yml:1-6`, `xops/main/ansible/host_files/by-us-fmt-5-edge-2/pgbouncer/pgbouncer.ini.j2:159`).
   - **Redis:** a 48-node Redis Cluster on edge-6 and edge-5 (`xops/main/ansible/inventory.yml:196-226`).
   - **MinIO:** one host, edge-5, with an 8-drive EC:2 set (about 21 TiB usable) shared by blob, Loki, Mimir, logs and competition data (`xops/main/ansible/MINIO-REBUILD-8.md:1-24`).
   - **BlobStore:** the server interface has no Delete, no ranged read and no streaming put (`server/blob.go:155-185`).
6. **Connect: how the platform reaches clients.**
   - A client's resident is a Redis record, `ncr_<clientId>` (`server/model/network_client_resident_model.go:19-33`).
   - The server pushes to a client through the resident's embedded control client (`ClientId=ControlId`), using `client.Send(frame, clientId)`, triggered by Redis key events (`server/connect/resident.go:4698-4712`, `:4853-4860`).
   - Request/response control from the client goes out of band over HTTP `POST /connect/control` (`server/connect/resident_controller.go:60-63`, `server/api/api.go:345`).
7. **Server-run connect clients already exist.** Server services already run their own connect clients: probes use a platform network JWT (`server/qualityprobe/providertunnel/tunnel.go:25-41`), and proxy runs devices through the sdk (`server/proxy/proxy_device.go:1268`). Connect's subprotocol API refuses `ControlId` as a destination (`connect/subprotocol.go:903`).
8. **Existing MCP server.** The server MCP is stateless streamable HTTP and an OAuth 2.1 resource server on `modelcontextprotocol/go-sdk v1.7.0` (`server/mcp/server.go:3-13`, `server/go.mod:30`). It imports server packages, so the sidecar repo cannot reuse it directly; the sidecar can use the SDK's `StdioTransport`.
9. **Email and DNS today.**
   - **Email:** account messages only, via SES v1 `SendEmail` in us-west-1 (`server/controller/aws_controller.go:638-705`). There is no SMTP, no inbound mail and no bounce consumer (`server/EMAIL1.md:44`).
   - **DNS hosting:** bringyour.com and ur.network are on Route 53; ur.io, ur.xyz, vpn.dev, ww.dev and lag.dev are on Cloudflare (`vault/main/services.yml:3-10`).
   - **DNS automation:** `warpctl dns sync` (derived names only), `warpctl certs issue` (lego DNS-01), and taskworker writers to Route 53.
10. **TLS automation and its limits.** Lb certificates are renewed by hand about every 30 days (`xops/certs/renew.md:4-20`). The only automated per-entity ACME pipeline is the lag.dev extender measurement chain (`server/taskworker/work/extender_measurement_*.go`), which the sidecar can build on. Two limits gate per-network certificates: Let's Encrypt's 50 new certificates per registered domain per week, and ur.network not being on the Public Suffix List (https://letsencrypt.org/docs/rate-limits/).

## 2. Facts with citations

### 2.0 Direct answers

**(a) End-to-end recipe to add a service (evs, tlsedge, smtpedge, dns).**

1. **Code.**
   - Put the service logic in a sidecar-repo package that imports connect only. Add `server/cli/<svc>/main.go` in the pattern of `server/cli/api/main.go:23-50`: `server.ScrubCommandLogs()`, docopt `--port` (default 80), `signal.NotifyContext(SIGQUIT, SIGTERM)`, then `<pkg>.Run(ctx, RunOptions{Port})`.
   - Copy the lifecycle in `server/mcp/run.go:34-100`:
     - run readiness via `router.CheckStartupReadiness` (Postgres migration head ≥ binary head, then Redis PING, 300 s budget; `server/router/warp_handlers.go:201-216`);
     - latch the status with `SetWarpStatusReady`, `SetWarpStatusNotReady` or `SetWarpStatusDrainingIfReady`;
     - call `server.StartStatsPusher`;
     - call `server.HttpListenAndServeWithReusePort(serveCtx, RequireListenIpPort(80)...)` (`server/http.go:409`) with a `GET /status` route (`server/mcp/server.go:121`);
     - on cancel, drain and flush stats.
   - A failed readiness must keep serving `/status` and must not exit. The deploy poll fails on `^(?i)error(\s|:)` and reverts the deploy (`server/router/warp_handlers.go:87-97`).
2. **Build.**
   - The Makefile `all` target builds `CGO_ENABLED=0` linux arm64 and amd64 binaries into `build/linux/<arch>/`. `warp_build_image` runs a multi-arch `docker buildx` push with `SOURCE_DATE_EPOCH`, provenance and SBOM. `warp_build` must stay a fail-closed guard (`server/cli/api/Makefile:14-34`).
   - The Dockerfile uses a pinned Ubuntu digest and checksum-pinned runtime `.deb` files (`server/cli/api/Dockerfile:1-31`). Tests join "the seven Ubuntu service Dockerfiles" to `cli/runtime-packages.lock.json` (`server/cli/RUNTIME-PACKAGES.md:3-18`), so an eighth recipe needs a lock entry.
   - `warpctl build` runs govulncheck on every binary before the image target (`warp/README.md:273`).
3. **Source graph and release.**
   - Add `replace github.com/urnetwork/sidecar => ../sidecar` (existing pattern: `server/go.mod:213-236`).
   - Add a sibling entry with a full commit ref to `server/local/source-graph/lock.yml:8-40`. The gate refuses stale or dirty siblings (`server/README.md:5-22`).
   - Optionally add `./cli/<svc>` to `server/local/source-graph/service_compile_test.go:13`.
   - In the release build repo:
     - add a submodule (`build/.gitmodules`);
     - add a module-rewrite step for sidecar between connect and sdk/server (`build/all/run.sh:1826-1835` shows the glog → connect chain);
     - add a `warpctl build $BUILD_ENV server/cli/<svc>/Makefile` line (`build/all/run.sh:3343-3422`);
     - classify the service in `build/all/deploy-rollout.zsh:21-38`. An unknown service exits 64. Lb-fronted services go into the staged 25/50/75/100% waves (`:87`); host-pinned or statusless services go into the single pass (`:91`).
4. **Config.**
   - Add a new top `versions[]` entry in `vault/<env>/services.yml`. Versions are append-to-top, and port assignments are permanent (`warp/README.md:85-99`).
   - The block lists:
     - `ports: [80]` plus `tcp_stream_ports`/`udp_stream_ports` for L4 traffic;
     - `blocks` with weights;
     - `cores`, `memory_limit` and `env_vars`;
     - `mount` (the vault mount defaults to *yes*, `warp/warpctl/config.go:2697`; prefer `vault: no` plus `secret_files`);
     - `exposed`, `expose_aliases`, `streamable`/`streamable_paths`, `stateful` and `hosts` (`warp/services/services.go:675-740`).
   - For each L4 port, map it in `lb.tcp_stream_port_services` / `lb.udp_stream_port_services` (`:557-560`).
   - Add service config files under `config/<env>/`. Add per-service PgBouncer and Redis pool caps in `config/main/db.yml:20-32` and `config/main/redis.yml:5-13`.
   - Add schema as appended `newSqlMigration` entries in `server/db_migrations.go`.
5. **Names and TLS.**
   - Every exposed service gets `<env>-<svc>.<domain>` for all seven domains (`warp/services/services.go:363-440`), and those names need certificates.
   - Run `warpctl certs issue <env>` (`warp/warpctl/main.go:1788-1997`), move the output into `vault/all/tls/<ver>`, deploy the vault, then run `warpctl dns sync`.
6. **Lb and hosts.**
   - Rebuild and deploy the lb, since its config is baked in.
   - Regenerate and install the systemd units with `xops/main/ansible/run-edges.sh:62-70` (`warpctl service create-units main`).

7. **Deploy.** Run `warpctl deploy <env> <svc> <version> --percent=N`. Blocks are taken in lexicographic order with beta first, rounded up (`warp/warpctl/main.go:159`).
8. **Background work.** Use taskworker task chains: `task.ScheduleTaskInTx(..., task.RunOnce(key), task.RunAt(t), task.MaxTime(d))` (`server/task/task.go:313`, `:467`), register a target in `server/taskworker/taskworker.go`, and seed it in `InitTasks` (`:168-170`).

**(b) Can the nginx lb pass TLS through by SNI today?**

No.

What exists:
- The pinned nginx is built `--with-stream --with-stream_ssl_module --with-stream_ssl_preread_module --with-http_realip_module` (`warp/lb/Dockerfile:46-58`).
- PROXY protocol is supported to backends: TCP v1 (`proxy_protocol on`, `warp/warpctl/config.go:2510`) and UDP v2 (`:2498`).

What blocks it:
- The generator writes one `server { listen <port>; proxy_pass stream-service-block-<svc>-<port>; }` per stream port (`:2477-2525`), with no `ssl_preread` and no `map $ssl_preread_server_name`.
- TCP 443 is bound by the http block's `listen 443 ssl` servers (`:1857-1863`, `:2047-2048`).

What must change in warp:
1. Add schema for SNI routes, for example `*.ur.network → tlsedge:<port>`.
2. When SNI routes exist, emit a stream server on 443 with `ssl_preread on`, a `map $ssl_preread_server_name ... { hostnames; ... default <internal https>; }`, and `proxy_protocol on`. This follows nginx's documented pattern, https://nginx.org/en/docs/stream/ngx_stream_ssl_preread_module.html (nginx 1.11.5+).
3. Move every http `listen 443 ssl` to an internal listener with the `proxy_protocol` parameter, plus `set_real_ip_from` and `real_ip_header proxy_protocol`. Rate limits (`$binary_remote_addr`), `exclude_subnets` and `X-UR-Forwarded-For` (`warp/warpctl/config.go:2270`) all key on the client address, so they need the real one (https://docs.nginx.com/nginx/admin-guide/load-balancer/using-proxy-protocol/).
4. Exact names and longer wildcards win over `*.ur.network` in a `hostnames` map, so the existing `api.ur.network`, `*.connect.ur.network` and `*.fuji.ur.network` names stay on the http path.

Alternatives:
- A dedicated public IP or interface whose 443 is stream-only. warp has no stream-only lb interface mode.
- A transparent-host service with public TCP ports. warp supports only `external_udp_ports` (`warp/services/services.go:899-903`).

Notes:
- nginx 1.31.4+ also lets TCP send `proxy_protocol v2` (https://nginx.org/en/docs/stream/ngx_stream_proxy_module.html).
- Stream servers set `proxy_timeout 15m` (`warp/warpctl/config.go:1383`), so idle passthrough connections drop after 15 minutes. Inference: stream servers get no lb rate limiting.

**(c) Where git over HTTPS and large blobs should enter.**

Recommended path: the lb http block on TCP 443, as a new exposed http service (for example `evs`, with an alias under ur.network), with TLS terminated at the lb. Use `streamable_paths` for `/git-receive-pack` and blob PUT routes so nginx streams bodies with `proxy_request_buffering off` (`warp/warpctl/config.go:2311-2318`). Pair each with `router.NewStreamingRoute` in the service (`server/router/router.go:65`, header `X-UR-Request-Buffering`, `server/router/streaming_body.go:15`).

Required warp change: the body limit. `client_max_body_size 16m` is global with no per-service override (`warp/warpctl/config.go:1301`, the only occurrence). Chunked bodies count against it, which is how git pushes fail behind nginx (https://confluence.atlassian.com/bitbucketserverkb/git-push-fails-client-intended-to-send-too-large-chunked-body-779171802.html). Smart HTTP is `GET /info/refs?service=…` plus `POST /git-upload-pack` and `/git-receive-pack`, and servers "SHOULD support chunked encoding" (https://git-scm.com/docs/gitprotocol-http).

Other limits on the path:
- `client_body_timeout 15s` between reads (`:1305`).
- Streamable `proxy_read_timeout`/`proxy_send_timeout` of 60s (`:2314-2316`).
- No retry to a sibling once streaming has started (`:2304-2310`).
- The per-address default rate limit: 450 requests per minute, burst 150, 50 connections (`vault/main/services.yml:66-75`).

Paths to avoid or that are unavailable:
- **MinIO direct:** MinIO is LAN-only. Edge-5's public interface was withdrawn (`xops/main/ansible/inventory.yml:291-297`), and lb upstreams reach only same-host blocks, so presigned direct-to-MinIO uploads are not possible today. All bytes go client → lb → evs block on the same host → MinIO over the LAN.
- **Bulk through the connect exchange:** keep it off. Each relayed client pair needs an active contract (`server/connect/resident_contract_manager.go:1-2`, `:74`), and production forwards drop on a full queue (`server/DESIGNNOTES.md:57-73`). Use the exchange only for change notifications.

**(d) DNS and certificate automation to build on.**

- **`warpctl dns plan|sync`.** Derives records from `services.yml` and reconciles Route 53 (weighted sets with health checks) or Cloudflare (round robin; never flips proxied). It touches only derived names: "everything not derived are reported and left alone" (`warp/README.md:496-538`; `warp/warpctl/dns.go:14-41`).
- **`warpctl certs issue <env>`.** Runs lego `goacme/lego:v4.35.2` with DNS-01 via route53 or cloudflare and `ec256` keys. It issues one certificate per registered domain with every hostname as a SAN, into `vault/all/tls.pending/<Y.M.D>/` (`warp/warpctl/main.go:1786-1997`). The run is manual: the runbook says every 30 days, and the certificates are picked up in the next deployment (`xops/certs/renew.md:4-20`). The lb reads the newest semver dir under `vault/<env|all>/tls/` at config build time (`warp/warpctl/config.go:871-950`).
- **Taskworker Route 53 writers.**
  - The extender geo DNS publisher writes one atomic change batch per tick, deletes only record sets it owns, and resolves the zone id by name (`server/taskworker/work/extender_dns_publish.go:27-60`, `:526-660`).
  - The measurement DNS reconcile plus the ACME DNS-01 TXT writer (`server/taskworker/work/extender_measurement_dns.go:20-50`) use a scoped IAM policy, keep A/AAAA and TXT changes in separate batches, and wait for INSYNC.
- **ACME issuance.**
  - The client is `golang.org/x/crypto/acme` (`server/taskworker/work/extender_measurement_acme.go:29-41`, `:119`). It renews at two thirds of the lifetime because there is no ARI, applies a weekly cap, revokes on withdrawal and backs off on Retry-After (`server/taskworker/work/extender_measurement_work.go:21-49`).
  - Certificates are stored in `network_extender_measurement_cert` (`server/db_migrations.go:10322-10370`). The client holds the key and submits a CSR (`mmm/lag.dev/PLAN.md:421-489`, C4–C9).
  - Ops runbooks cover zone delegation, the scoped IAM policy, CAA with `accounturi` and `validationmethods=dns-01`, the PSL request and the Let's Encrypt limit request (`mmm/lag.dev/ops/route53.md`, `psl.md`, `letsencrypt.md`).
- **`server.TransportTls`.** SNI-selected static certificates from `vault tls/<name>/<name>.{crt,key}` or `star.<base>`, with `allowed_hosts` patterns including `**.ur.network` (`server/tls.go:58-72`, `:110-217`; `config/main/tls.yml:3-7`). It is used by connect's H3 and by proxy's HTTPS. It caches per process and never reloads (`server/tls.go:157`, `:217`).
- **xops.** xops has no DNS or ACME automation: only `xops/dns/sample.sh` (a dig loop) and the manual `xops/certs/renew.md`.

### 2.1 Modules, build graph, release
- **Toolchain:** Go 1.27.3. The canonical build command is `GOWORK=off GOTOOLCHAIN=local CGO_ENABLED=0 go build -mod=readonly` (`server/README.md:5-14`).
- **Server's local replaces:** server replaces connect, sctp (`../connect/sctp`), proxy, sdk, glog, goidenticons, userwireguard, sn and gvisor with sibling directories (`server/go.mod:213-236`). sdk replaces connect, sctp, glog, goidenticons and gvisor (`sdk/go.mod:107-115`). connect replaces glog, `./sctp` and gvisor (`connect/go.mod:98-102`).
- **Replaces in a sidecar go.mod:** replace directives apply only in the main module (https://go.dev/ref/mod#go-mod-file-replace). Inference: a sidecar `go.mod` must repeat connect's replace set to build on its own.
- **Server already imports sdk.** The proxy uses `sdk.NewPlatformDeviceLocal`/`sdk.NewPlatformNetworkSpace` (`server/proxy/proxy_device.go:18`, `:346`, `:1268`). An sdk → sidecar import is therefore also a transitive server dependency.
- **Release rewrite:** the release rewrites each module to a versioned path and a tagged `require`, in chain order glog → connect (`go_mod_fork 'api'`) → userwireguard → … (`build/all/run.sh:1545-1565`, `:1826-1840`).
- **Repo location:** `/Users/brien/urnetwork/sidecar` is not a git repo and holds docs only, but `../sidecar` is where a server `replace` and the source lock would point.

### 2.2 Configuration plumbing
- **Container environment:** each container gets `WARP_ENV`, `WARP_SERVICE`, `WARP_BLOCK`, `WARP_VERSION`, `WARP_DOMAIN`, `WARP_HOST`, `WARP_PORTS` (service:host pairs), `WARP_HOST_IPV4`/`IPV6`, `WARP_FWMARK`, `GOMEMLIMIT` (90% of `memory_limit`), `GOMAXPROCS` (`cores`), plus the vault, config and site mounts (`warp/warpctl/run.go:2025-2240`).
- **Networking:** host networking is the default (`--host_networking ... [default: yes]`, `warp/warpctl/main.go:205`). Docker socket mounts are forbidden, and `mount_data` gives a per-host persistent volume (`:175-176`).
- **Resolvers:** `server.Vault`, `server.Config` and `server.Site` resolve resources (`server/env.go:61-63`). `GetSettings` merges `config/settings.yml` (`all`, then per-host) with `site/settings.yml`, and `env_vars` are exported at init (`:78-126`).
- **Backend addresses:** `BRINGYOUR_{POSTGRES,REDIS,MINIO}_HOSTNAME` and `routes` (host → LAN address) come from settings (`config/main/settings.yml:1-19`; `server/env.go:550-565`). `RequireListenIpPort(port)` maps a service port to the allocated host port (`server/env.go:522-534`).
- **Port ranges:** main uses external `7000-7200,7443-7449,10001-12000`, internal `7201-7442,7450-10000,12001-20000`, routing tables `100-120` and `parallel_block_count: 30` (`vault/main/services.yml:333-337`).

### 2.3 Deploy, health, rollout, scaling
- **Version selector:** the deployed version per block lives in DynamoDB table `deployment-blocks` (`warp/warpctl/dynamo/client.go:17`). The run worker re-checks it before starting (`warp/warpctl/deployment_target.go:20-50`).
- **Rollout:** `deployContainerOverlap` starts the new container on fresh internal ports, polls status, flips iptables redirects and drains the old container (`warp/warpctl/run.go:1453-1597`). Optional per-host staggering uses a host drain lock (`:1406-1448`).
- **Status poll:** the poll targets the internal port of service port 80, and a block with no port 80 is treated as healthy (`warp/warpctl/run.go:2310-2315`). `status: "no"` waits 30 s instead (`:2297-2308`, used by gossip).
- **Lb status routes:** the lb exposes `/<lb prefix>/by/b/<svc>/<block>/status` per block (`warp/warpctl/config.go:1808-1832`). Route 53 health checks hit `/<lb hidden prefix>/status` on each lb interface (`warp/README.md:509-514`).
- **Release waves:** config-updater and grafana at 100%, then waves of 25/50/75/100% for `mmm lb taskworker api connect web app mcp`, then `gossip alt proxy` at 100% (`build/all/deploy-rollout.zsh:76-117`).
- **Placement:** a service is placed on every host with an lb interface, minus hosts whose `host_services` excludes it and hosts outside its `hosts` (`warp/services/services.go:518-551`). For example, 20 connect, 20 api, 20 proxy and 2 alt processes were live on 2026-11-01 (`server/blob.go:60-64`).
- **Upstreams:** each lb's upstreams are `warpservices:<externalPort>` on its own host (`warp/warpctl/config.go:1008`, `:1081`, `:1661`).

### 2.4 Load balancer details
- **Image:** the nginx source is pinned to upstream commit `11d11b5…` ("the first upstream nginx commit that can emit PROXY protocol v2 to UDP backends", `warp/lb/Dockerfile:3-7`). The `lb` Go wrapper runs nginx, converts the config to host networking and scrubs client addresses from stderr (`warp/nginx.go:33-210`).
- **http block:** TLSv1.2/1.3, `http2 on`, `http3 on`, `client_max_body_size 16m`, `proxy_buffering off`, `proxy_request_buffering on`, and 15 s header/body timeouts. Retries are `proxy_next_upstream error timeout http_503 non_idempotent` with 2 tries. The access log format omits the client IP (`warp/warpctl/config.go:1225-1330`).
- **QUIC:** QUIC listeners are emitted only when UDP 443 is not a stream port. In main it is a stream port (connect), so nginx serves no HTTP/3 (`:951-980`, `:1867-1870`).
- **Name-based routing:** `<env>-<svc>.<domain>` plus `expose_aliases`/`expose_domains` get one 443 server each with a resolved certificate (`:1996-2075`). `<env>-lb.<domain>/by/service/<svc>/…` and `/by/b/<svc>/<block>/…` are path routes (`:1940-1990`).
- **Headers set to services:** `X-UR-Forwarded-For` (`[ipv6]:port` bracketed), `Host`, and `X-UR-Request-Buffering` (`:2267-2285`). Websocket services get `proxy_read_timeout 60s` (`:2289-2300`).
- **Rate limits:** per-interface `rate_limit` (limit_req and limit_conn zones) and per-route `route_rate_limits` (`warp/services/services.go:737-790`, `vault/main/services.yml:658-661`). `default_rate_limit` is parsed so that lb-less services can apply the same limits themselves (`warp/services/services.go:32-34`).
- **Router:** the EdgeOS router in front opens exactly what warp publishes. Router-side DNAT is IPv4-only (`warp/README.md:385-408`).

### 2.5 Data stores and coordination
- **Postgres:**
  - Helpers are `server.Db`, `server.Tx` and `server.ReplicaDb` (`server/db.go:681`, `:703`, `:953`).
  - All connections go through PgBouncer behind edge-2's nginx (port 6432) with 768 servers and per-service caps (`config/main/db.yml:1-32`).
  - PgBouncer runs `pool_mode = transaction`, so code uses transaction-scoped `pg_advisory_xact_lock(hashtextextended($1,0))` (for example `server/model/subscription_model.go:5777`).
- **Redis:**
  - `server.RedisClient = redis.UniversalClient`, used through `server.Redis(ctx, fn)` (`server/redis.go:22`, `:471`), against a Redis Cluster (`xops/main/ansible/inventory.yml:188-226`). Multi-key operations need hash tags; existing keys use them, such as `{ns_<id>}eid` (`server/connect/session_notifications.go:26`).
  - Compare-and-set helpers are `RedisSetIfEqual` and `RedisRemoveIfEqual` (`server/redis.go:955`, `:964`).
  - Keyspace events are available through `SubscribeKeyEvents` (`:714`).
  - `RunRedisShardSubscription` gives slot-following SSUBSCRIBE with resync on every (re)acknowledgement (`server/redis_shard_subscription.go:1-36`, `:141`). The pattern is: durable row with a change id, then `SPublish`, then subscribers read the changes since their last id (`server/proxy/proxy_client_notification.go:24-50`, `server/model/network_client_proxy_model.go:931`).
- **Singleton work:** `task.RunOnce(key)` chains, for example `extender_measurement_dns` (`server/taskworker/work/extender_measurement_work.go:643-657`). There is no etcd, consul or raft.
- **Blob:**
  - **API:** `server.LoadBlobStore` returns the `BlobStore` interface: `Put(localPath)`, `PutIfAbsent`, `Get`, `List`, `SetLifecycle`, `Bucket`, `Prefix`, `Authority` (`server/blob.go:155-185`, `:363`). The optional capabilities are `PagedBlobStore`, `RetainedBlobStore` (compliance object lock), `ProtectedBlobStore` (WORM plus replication) and `VersionedBlobStore` (`:188-229`).
  - **Config:** the backend is selected by vault `minio.yml` (authority, bucket, prefix default `blob`, region `us-east-1`, a scoped service account created by `playbook-minio-clusters.yml`) (`server/blob.go:1-16`, `:51`, `:423-531`; `vault/main/minio.yml:1-20`).
  - **Cluster:** MinIO runs on port 23900, `minio_api_requests_max: 1024`, memory capped at 42–45 G because it shares the host with 16 Redis nodes (`xops/main/ansible/inventory.yml:249-323`). Each MinIO host is one erasure set, and a new pool or cluster is an inventory change (`:245-248`, `:312-315`).

### 2.6 Connect service internals relevant to new services
- **Process:** an exchange is per connect process (per block), built from `WARP_PORTS` service ports 5080–5090 (`server/connect/resident.go:1008-1040`; `vault/main/services.yml:703-706`).
- **Resident record:** `NetworkClientResident{ClientId, InstanceId, ResidentId, ResidentHost, ResidentService, ResidentBlock, ResidentInternalPorts}` is gob-encoded at Redis key `ncr_<clientId>` and self-nominated by SetNX or compare-and-set (`server/model/network_client_resident_model.go:19-112`).
- **Locating a resident:** transports look up the record, then attach in process or dial `NewExchangeConnection(ResidentHost, random ResidentInternalPorts[i], routes)` (`server/connect/resident.go:3795-3822`).
- **Push to a client:** the resident's internal client is constructed with `connect.ControlId` (`:4350`). Pushes such as `NetworkSessionsChanged` are triggered by Redis keyspace listeners and sent with `self.client.Send(frame, connect.Id(self.clientId), nil)` (`:4698-4712`, `:4853-4860`).
- **Control from a client:** in-band control "cannot carry replies"; responses use the API out-of-band controller (`server/connect/resident_controller.go:60-63`). `connect.NetworkClientControl` / `ApiOutOfBandControl` carry it (`connect/transfer_oob_control.go:43-91`).
- **Subprotocols:**
  - Raw messages travel as `MessageType.Subprotocol` frames (`connect/protocol/subprotocol.proto`; `connect/SUBPROTOCOL.md` §10). Ids below 1024 are reserved (`connect/subprotocol.go:50`).
  - The API is `RegisterSubprotocol`, `SendSubprotocol*` and `QuerySubprotocols` (`:553`, `:895-1000`, `:754`). Sends to `ControlId` fail (`:903`).
  - Receive dispatch does not filter by source (`:590-650`). Inference: a resident's control client could send subprotocol frames to its client.
- **Server-run clients:**
  - `providertunnel.Config{ClientId, ByJwt, ApiUrl, PlatformUrl, ClientCredentials, ClientControl, PlatformPlacement}` (`server/qualityprobe/providertunnel/tunnel.go:25-70`).
  - `localclient.Authority` runs hosted control in process (`server/localclient/authority.go:1-3`, `:61-66`).
  - The connect seams are `NetworkClientCredentials` (`connect/ip_remote_multi_client_api.go:39`), `PlatformPlacement` (`connect/platform_placement.go:38`), `ClientAuth{ByJwt, InstanceId, AppVersion, ...}` (`connect/transport.go:348-360`), `NewPlatformTransportWithDefaults` (`:1702`), and `NewClient`/`Send`/`AddReceiveCallback` (`connect/transfer.go:2267`, `:4228`, `:4414`).
- **JWT audiences:** `urnetwork:api` and `urnetwork:connect`, verified only in `server/session` (`server/session/by_jwt.go:66-67`, `:468`).

### 2.7 MCP server

## 3. Constraints the design must respect
1. **Dependency direction.** Sidecar packages may import connect (plus third-party modules and glog), never server or sdk. Server services must inject every server facility through interfaces the sidecar defines: Db/Tx, Redis, BlobStore, WarpStatus, StartStatsPusher, TransportTls, PpConn, task scheduling and JWT verification. connect's `NetworkClientControl`/`NetworkClientCredentials` seams are the pattern to copy.
2. **Release gates.** The sidecar repo must sit as a git checkout at `../sidecar`, carry a full commit ref in the source lock, use Go 1.27.3, and build `CGO_ENABLED=0` for linux amd64 and arm64. It must also join the release module chain and the rollout classification, or the release exits 64.
3. **Lb config is static.** Lb routes and certificates are fixed at lb image build time, so per-network routing (`<me>.ur.network`) cannot live in nginx. It must be one wildcard route to a service that routes dynamically.
4. **Ports are permanent.** Service-block ports are fixed forever once assigned. A new service is a new top `services.yml` version, and port-80 `/status` semantics are required for observable rollouts.
5. **Same-host upstreams.** Each lb proxies only to blocks on its own host. An lb-fronted service must run on every lb host (the default placement), and cross-host state must live in Postgres, Redis or MinIO.
6. **Postgres through PgBouncer.** PgBouncer transaction pooling rules out session advisory locks, LISTEN/NOTIFY and session state. Use `pg_advisory_xact_lock` and Redis pubsub. There is a single primary with explicit per-service connection caps.
7. **Redis Cluster.** Keys touched together in a transaction or script need the same hash tag. Pubsub hints must resync from durable state, because messages published during a gap are lost.
8. **HTTP body and timing limits.** Any HTTP upload larger than 16 MiB through the lb needs a warp change. Streamed bodies cannot be retried, and stall timeouts are 15 s for the body and 60 s for streamable proxying.
9. **Privacy.** Client IPs must not be logged: the lb log format and command logs are scrubbed. New L4 edges must follow the same rule.
10. **Contracts.** Exchange payload between non-control clients needs active contracts. Bulk data and server notifications sent from a platform client must account for this.
11. **Cert and DNS budgets.**
    - Let's Encrypt: 50 new certificates per registered domain per 7 days, 5 per exact identifier set, 300 orders per account per 3 h, and at most 100 names per certificate.
    - Renewals with the exact same identifier set skip the registered-domain limit; ARI renewals are exempt from all limits.
    - Certificate lifetimes drop to 64 days on 2027-02-10 and 45 days on 2028-02-16 (https://letsencrypt.org/2025/12/02/from-90-to-45, https://letsencrypt.org/2026/10/07/64-day-certs).
12. **Public UDP 53 is taken.** UDP 53 on all public lb and alt addresses belongs to connect WhoDis. An authoritative DNS service needs other addresses, or must keep Route 53 authoritative.

## 5. Gaps, risks, surprises
1. **No SNI or L4 routing in warp, and certificates are hand-renewed.** Implementing tlsedge on 443 means reworking how every https listener receives the client address. Manual 30-day renewal will be strained by 45-day certificates in 2028. Inference: two thirds of 45 days is 30 days.
2. **One budget for every ur.network certificate.** Every Let's Encrypt certificate under ur.network, from warpctl and from any per-network issuance, shares 50 new certificates per week. ur.network is not on the PSL. The lag.dev runbook says a PSL request needs 2,000–3,000 distinct users, registration more than two years ahead, and a non-rate-limit purpose (`mmm/lag.dev/ops/psl.md:31-46`), and ur.network expires 2027-07-02. Until it is listed, every `<me>.ur.network` page is same-site with ur.network hosts (`psl.md:48-75`).
3. **Name collisions under ur.network.** Network names are 5–50 characters of `[a-z0-9-]` with no reserved list (`server/model/network_model.go:178-206`). They can collide with existing labels (`connect`, `gossip`, `grafana`, `cosmic`, `crisp`, `honey`, `fireside`, `main-*`). They can also break DNS label rules: a leading or trailing `-` and `xn--` are allowed.
4. **Public UDP 53 belongs to WhoDis.** A `dns` service cannot answer on the existing public IPs without multiplexing with connect, and TCP 53 is unpublished.
5. **MinIO is a single host.** It is shared with Redis, at an API concurrency ceiling of 1,024 that the 2026-11-01 PUT surges hit (`xops/main/ansible/inventory.yml:283-289`). A "new file cluster" needs new hardware or drives. MinIO cannot widen an erasure set (`MINIO-REBUILD-8.md:4-8`).
6. **`BlobStore` lacks what evs needs.** It has no Delete, no range Get and no `io.Reader` put, and its retention is code-owned through lifecycle rules. Evs needs a richer interface, or minio-go directly.
7. **Docs that disagree with code (code wins).**
   - DESIGNNOTES says the exchange is "per-host" and residents are kept in "DB/redis" (`server/DESIGNNOTES.md:19`, `:26`). Code: an exchange per process (block), and the resident lives in Redis only.
   - The warp grafana README says the bundle ships container logs via alloy and the Docker API (`warp/grafana/README.md:4-5`). Config: host Fluent Bit reads journald, and Docker socket mounts are forbidden.
8. **lb details that matter for new traffic.** `ssl_stapling on` remains in the lb config (`warp/warpctl/config.go:1254`) although Let's Encrypt ended OCSP on 2025-08-06 (`mmm/lag.dev/ops/letsencrypt.md:608-611`). nginx serves no HTTP/3 for lb names in main. Stream connections idle out at 15 minutes.
9. **Vault mount default.** The vault mount defaults to the whole vault read-only. New edge services that face hostile traffic should opt out (`vault: no` plus `secret_files`).
10. **SMTP and DNS have no starting point.** There is no inbound-mail precedent, no PTR/rDNS tooling and no outbound port-25 egress design. The proxy's `cap_net_admin` plus `WARP_FWMARK` routing is the only per-interface egress pattern (`server/proxy/server.go:897`; `warp/warpctl/config.go:2685-2690`). No git server code exists in any repo.
