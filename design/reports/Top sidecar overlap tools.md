# Usage evidence splits the seven jobs

As of 31 October 2026, the tools with the best usage evidence overlap the seven jobs one or two at a time, and no opened source shows one widely used product doing the set. On people, two surveys that must not be averaged both put **Claude Code** first and **GitHub Copilot** second, then **OpenAI Codex** and **Cursor**: JetBrains’ May–July 2026 at-work figures are about **39%**, **21%**, **16%**, and **12%** of professional developers, while Stack Overflow’s past-year coding-agent table is **65.5%**, **58.7%**, **29.5%**, and **25.5%** of 12,255 respondents ([JetBrains](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/), [Stack Overflow](https://survey.stackoverflow.co/2026/ai/data/ai-code-agent)). Those shares measure agents, not memory files, tunnels, or inboxes. Among libraries whose product is memory, opened PyPI totals put **Mem0** first, about **2.6 million** downloads in 30 days with CI included, while **Letta**, the only opened git memory filesystem, has no usage figure ([pepy mem0ai](https://pepy.tech/projects/mem0ai)). For publishing a local port, **ngrok** is the only product with a large signup number, an undated vendor claim of **15.3 million** developers ([About ngrok](https://ngrok.com/about)). For an agent channel, the opened evidence is **Slack** in product docs and **AgentMail** in vendor customer stories, not a survey. For a text protocol a harness already spawns, the evidence is **MCP over stdio**, in package downloads and named clients, not in a share of developers. Admin sign-in and an audit log are documented on GitHub, Cursor, and Claude, and those logs are not a transcript of local work.

## Claude Code leads both surveys, and neither survey counts a memory file

The two people-denominators ask different questions, so the gap between them is real and should stay visible. JetBrains fielded more than **15,000** professional developers in May–July 2026, reweighted the sample, and asked about use at work: **90%** used some AI coding agent at least weekly and **68%** daily. Claude Code was about **39%** (18% in January 2026; **47%** in the United States) and the single most-used tool for **31%**. GitHub Copilot was **21%**, down from 29% a year earlier. OpenAI Codex was **16%**, up from 3% in January. Cursor was **12%**, down from 18% in January. OpenCode was **7%**, Google Antigravity **6%**, and JetBrains AI in the IDE and/or Junie about **9%** ([JetBrains](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/)). Stack Overflow’s 2026 instrument collected **30,903** responses and, on an optional multi-select, “Have you used any of the following coding agents or assistants in the past year?” with **n = 12,255**. The table is Claude Code **8,030 (65.5%)**, GitHub Copilot **7,196 (58.7%)**, OpenAI Codex **3,620 (29.5%)**, Cursor **3,127 (25.5%)**, Google Antigravity **1,956 (16.0%)**, Gemini Code Assist **1,789 (14.6%)**, Open Code **1,662 (13.6%)**, JetBrains AI **1,569 (12.8%)**, Windsurf **796 (6.5%)**, and Devin **360 (2.9%)** ([Stack Overflow survey](https://survey.stackoverflow.co/2026), [coding-agent table](https://survey.stackoverflow.co/2026/ai/data/ai-code-agent)). Shares sum past 100% because respondents could pick more than one. The narrative page rounds the leaders to 66% and 59% ([Stack Overflow AI](https://survey.stackoverflow.co/2026/ai)). Do not average 65.5% with 39%. One denominator is people who answered an optional past-year question on a self-selected community survey. The other is reweighted professionals and current use at work. JetBrains sells a competing assistant, listed at about 9%, so its levels are a second source rather than a precise census. The order of the top four matches, which is why that order is usable. Copilot can be second on a past-year question and still be losing share of use at work. Windsurf and Devin appear only on the Stack Overflow table. JetBrains’ write-up does not list them, and a vendor page confirming Windsurf still shipped on 31 October 2026 was not opened. No opened Anthropic, GitHub, or Cursor page gives a late-2026 absolute user count, and secondary estimates that conflict with each other are not used here.

That ranking is not a ranking of memory. Claude Code loads `CLAUDE.md` when the file exists, and auto memory is on by default for local sessions, but the surveys do not ask who turned either on. Copilot Memory became generally available on paid plans on **28 October 2026**, after the JetBrains wave, so almost none of that 21% is the new memory product ([GitHub Changelog](https://github.blog/changelog/2026-10-28-github-intelligence-puts-your-code-context-and-history-to-work/)). Stack Overflow’s field dates are not printed on the pages opened, so that survey is not dated against the same launch. A preview statistic on the changelog, 93% better preference adherence and 42% more efficient workflows among reviewed Copilot CLI sessions that used memory, is a quality sample, not adoption.

Dedicated memory products sit on a different scoreboard, and it is install events, not people. On pepy.tech, fetched 31 October 2026, with CI included in the headline totals, `langgraph` had **55,981,298** downloads in 30 days and `mem0ai` **2,551,466**. A different endpoint, as compiled by Benchclaw from pypistats with a cutoff of 12 October 2026, puts `mem0ai` at **2,020,516** in the last month and `graphiti-core` at **619,128**. That second table was not the pypistats page itself, so Mem0 over Graphiti is a weaker order than Mem0’s opened pepy total. Both Mem0 figures can be true because the windows differ. Neither is users. LangGraph’s lead, roughly twenty times Mem0, counts an orchestration framework whose memory APIs are optional checkpointers and stores. Stack Overflow’s **30%** for LangChain is an orchestration answer, not LangGraph memory use ([pepy langgraph](https://pepy.tech/projects/langgraph), [LangGraph memory](https://docs.langchain.com/oss/python/langgraph/add-memory), [Stack Overflow AI](https://survey.stackoverflow.co/2026/ai)). Zep’s package downloads were “not measured” in that Benchclaw table, Community Edition is described there as unsupported, and no opened page gives a Zep customer count. Letta has star counts only, about 25.3k on `letta` and 3.7k on `letta-code` in search extracts of GitHub. Stars are a weak signal, and Letta cannot be placed on either the survey scale or the download scale. Aider’s `aider-chat` package is a real opened figure, **284,004** downloads in 30 days against 11.0 million all-time, with the last listed release on 12 February 2026, and Aider is a coding CLI that edits a repo, not a memory store ([pepy aider-chat](https://pepy.tech/projects/aider-chat)).

**Claude Code** does git-shaped project instructions when a team commits `CLAUDE.md`, keeps auto memory in a local directory rather than in the repo, runs as a local CLI a script can spawn with that vendor’s own JSON flag, and on Team and Enterprise plans has SSO plus an audit export of conversation identifiers that omits chat title and content. It does not do encrypted or real-time storage, port forwarding, a public TLS edge, or an email inbox, and that CLI flag is not a text protocol an arbitrary harness implements ([Claude Code memory](https://code.claude.com/docs/en/memory), [Claude audit logs](https://support.claude.com/en/articles/9970975-how-to-access-audit-logs), [Claude SSO](https://support.claude.com/en/articles/13132885-set-up-single-sign-on-sso), [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)). **GitHub Copilot** does hosted repository facts shared with collaborators and user-level preferences the billing organization can view on Business and Enterprise, plus custom instruction files that stay git-shaped only if the team commits them, plus SAML and an enterprise audit log of agent actions on github.com kept **180 days** that excludes local prompts. It does not do a git front end for those memories, real-time encrypted storage, port forwarding, a public TLS edge, an inbox, or a subprocess any harness speaks. Forking a repository does not copy its stored memories ([Copilot Memory](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-memory), [agent audit events](https://docs.github.com/en/copilot/reference/agentic-audit-log-events), [Copilot audit logs](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/review-audit-logs), [GitHub SAML](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/iam-configuration-reference/saml-configuration-reference)). **Cursor** does version-controlled project rules, dashboard Team Rules on Team and Enterprise plans, Team-plan SAML and member, admin, and unpaid-admin roles, and an Enterprise audit log of sign-ins, membership, settings, and integrations. That log’s payloads omit prompts, agent output, and generated code. Cursor does not do encrypted storage, real-time sync, port forwarding, a public TLS edge, or an inbox, and it is the harness, not a subprocess of one. Navigation labels for an “Origin” git host and a Tailscale integration were not opened, so they are not scored ([Cursor Rules](https://cursor.com/docs/context/rules), [Cursor teams](https://cursor.com/docs/account/teams/setup), [Cursor members](https://cursor.com/docs/account/teams/members), [Cursor compliance](https://cursor.com/docs/enterprise/compliance-and-monitoring)). **Codex**, third on both surveys, does local repo work, local git checkpoints around a task, and MCP client commands, on the CLI page that was opened. That page does not describe encrypted storage, a hosted git service, port forwarding, a public TLS edge, an inbox, team administration, or an admin audit trail ([Codex CLI](https://learn.chatgpt.com/docs/codex/cli)).

**Mem0** is the usage leader among products whose job is memory, and on the pages opened it does a memory library or hosted store, not a git front end, not real-time file sync, not port forwarding, not a public TLS edge, not an inbox, and not a text protocol for an arbitrary harness. Encryption-at-rest, encryption-in-transit, and BYOK wording exists only in search extracts. A fetch of the security URL redirected to a trust page that returned no body, and two extracts disagree on whether HIPAA is “compliant” or “self-attested,” so that compliance language is a weak vendor claim, not a confirmed control ([pepy mem0ai](https://pepy.tech/projects/mem0ai)). **Letta MemFS** does the closest opened match to a git front end: the agent’s memory is a git repository of Markdown, edits become shared memory only when committed and pushed, and an organization can own a shared cloud repo that other cloud agents pull. The opened docs do not show encryption, real-time multi-writer sync, email, port forwarding, a public TLS edge, an admin audit trail, or a text protocol any harness speaks, and shared repos are cloud-only. No download or user count was opened, so Letta is first on overlap with that job and unranked on use ([MemFS](https://docs.letta.com/concepts/memfs/), [shared memory](https://docs.letta.com/concepts/shared-memory/)). No opened source shows a widely used product that is real-time, encrypted, and git-fronted at once. OpenCode, Antigravity, and Gemini Code Assist are on the surveys and were not scored, because their storage formats were not opened.

## ngrok is the only tunnel with a signup number, and the number is undated

No 2025–2026 Stack Overflow, JetBrains, or similar survey that ranks tunnel products was found, and no trustworthy revenue figure was found for them. The rank below is by the strength of the usage evidence that was opened, not by which feature checklist is longer. Absence of a count is not evidence that a tool is small.

**ngrok** is first because it is the only one with a large figure for the tunnel product itself. The about page, fetched 31 October 2026, says “the **15.3 million** developers who've signed up... so far,” and that the founder grew ngrok to 5 million users before a Series A. The page dates neither figure. A blog post updated 19 October 2026 says “millions of developers,” which is softer and still not a monthly active count ([About ngrok](https://ngrok.com/about), [ngrok cheatsheet](https://ngrok.com/blog/the-ngrok-cheat-sheet)). Signups are not monthly active tunnels. The old open-source ngrok 1.x repo, archived, with a last push in 2024, is not 2026 usage. **Microsoft dev tunnels** are second with no user count: they are the port-forwarding implementation inside current VS Code, private by default to the signed-in GitHub account, and the overview still said public preview, no SLA, not for production, when fetched 31 October 2026. The service remains capacity-capped at **5 GB** and **10 tunnels** per user per month. The small `microsoft/dev-tunnels` repo, 518 stars, is not the usage signal. VS Code distribution is ([VS Code port forwarding](https://code.visualstudio.com/docs/debugtest/port-forwarding), [dev tunnels overview](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/overview), [Azure limits](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/azure-subscription-service-limits)). **Cloudflare Tunnel** is third with no tunnel, quick-tunnel, or `cloudflared` download count. The client is active, quick tunnels need no account, and first-party agent docs name it. **16,361** GitHub stars on `cloudflared`, last push 30 October 2026, are a weak proxy ([cloudflared](https://github.com/cloudflare/cloudflared)). **Tailscale Serve and Funnel** are fourth. Company figures are not feature figures. On 3 April 2025 Tailscale said it was trusted by over **10,000** business customers and hundreds of thousands of individual users, and that in September 2024 it crossed 1 million devices connected at once. On 21 January 2026 it said “millions of users.” Funnel was still marked beta on a page last validated 20 January 2026. The client repo’s **38,384** stars are not a Funnel install count ([5 years of Tailscale](https://tailscale.com/blog/5-things-5-years), [Tailscale, 21 Jan 2026](https://tailscale.com/blog/hypergrowth-isnt-always-easy), [Funnel](https://tailscale.com/kb/1223/funnel)). **frp** is fifth, the top self-hosted reverse proxy by stars: **110,353**, last push 23 October 2026. Stars are weak, and they are not a claim that frp is used more than ngrok. localtunnel (**22,496** stars, last push 29 August 2025), bore (**11,571**, last push 4 February 2026), and zrok (**4,797**, last push 31 October 2026) are real repos with weaker or staler evidence and no user counts. Pinggy appears in 2026 comparison articles only. No user count or star count was verified, so it is not in this rank.

Agent documentation matches the top of that list and does not add a count. xAI’s Grok connector doc, fetched 31 October 2026, calls ngrok and Cloudflare quick tunnels “two popular options” and gives the commands, and it warns that quick tunnels do not support server-sent events ([Grok tunneling](https://docs.x.ai/grok/connectors/custom-mcp-tunneling)). Anthropic’s MCP tunnels page, a research preview, specifies `cloudflared` as the outbound connector inside the customer network, aimed at a private path rather than a public laptop URL ([Claude MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview)). Cursor’s own MCP doc supports stdio, SSE, and a URL, including localhost, and names no tunnel ([Cursor MCP](https://cursor.com/docs/context/mcp)). ngrok’s own gateway doc tells readers to put a local MCP server on an ngrok URL for Claude Code, Cursor, ChatGPT, and Grok. That is vendor instruction, not independent usage. No opened Claude, Cursor, or Grok doc tells the reader to use Tailscale, frp, or dev tunnels for an agent.

**ngrok** does local HTTP and TCP forwarding and a public TLS edge that ngrok terminates unless the customer pays for end-to-end TLS, plus private internal endpoints, and it does team auth and account audit logs only as paid add-ons (SSO and RBAC at $10 per user per month, the governance suite that includes audit logs at $15 per user per month on top of that). Self-serve request history is Traffic Inspector, **24 hours** on Free and **72 hours** on Hobbyist and Pay-as-you-go. The free plan is one team member and an interstitial page. ngrok does not do git storage, an inbox, or a text protocol any harness uses to drive storage, mail, and audit ([ngrok pricing](https://ngrok.com/pricing)). **Dev tunnels** do port forwarding and a public HTTPS edge with TLS terminated at Azure, private to the creating Microsoft, Entra, or GitHub account unless anonymous access or a tenant, GitHub-org, or tunnel-token grant is turned on. They do not do git storage, an inbox, a retained admin audit log, or a harness text protocol ([dev tunnels security](https://learn.microsoft.com/en-us/azure/developer/dev-tunnels/security)). **Cloudflare Tunnel** does port forwarding and a public TLS name, including a temporary `trycloudflare.com` URL with no account, and the Zero Trust account has admin audit logs described as retained **18 months**, while Access request logs on Free are **24 hours**. Quick tunnels are public to anyone with the URL. An email one-time PIN exists and does not support non-interactive clients. Named tunnels can sit behind Access, which is a separate team gate. Tunnel does not do git storage, an inbox, or a harness text protocol, and no seat price was visible on the pricing page that was opened ([Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), [Zero Trust logs](https://developers.cloudflare.com/cloudflare-one/insights/logs/)). **Tailscale Serve** does private port publishing inside the tailnet, on an HTTPS name, with ACLs and identity headers. **Funnel** does a public TLS-only edge on ports 443, 8443, and 10000, still documented as beta, with no visitor login, and the relay does not decrypt the stream. Neither does git storage, email, or a harness text protocol. Export of configuration audit logs and network flow logs is documented for Premium and Enterprise. Whether Free can see configuration audit logs in the console was not confirmed ([Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve), [log streaming](https://tailscale.com/docs/features/logging/log-streaming)). **frp** forwards a local port only if the operator runs the server side on a public machine. It does not include a vendor public TLS edge, an inbox, a git store, or a vendor audit log.

## Slack shows an agent in the channel; email usage is still a vendor story

No opened 2025–2026 survey ranks Slack, Teams, Discord, Gmail, or Outlook as the channel developers use with an agent. Historical “hundreds of millions of users” lines for Slack and Teams were not re-opened from the vendors and are not used. A chat product’s human user base would not be agent-inbox adoption even if it had been opened. The rank is documentary.

**Slack** is first because two independent product docs show an agent or an agent product attached to a workspace, and still no count of people who message an agent there. Anthropic’s Slack doc says the Claude app, which needs a paid Slack plan and a Slack admin, can be reached by direct message, Slack’s assistant panel, and @Claude in a thread, and that on Team and Enterprise a mention can hand a coding task to Claude Code. The page gives no install count, says it describes an earlier per-user app, and points at Claude Tag as the current product. Slack conversations with Claude stay out of claude.ai history ([Claude Slack](https://claude.com/docs/connectors/slack)). Cursor’s Enterprise audit log records `slack_account_link` and team settings for a default repo, branch, and model. That shows a linkage an admin can see. It is not a user count ([Cursor compliance](https://cursor.com/docs/enterprise/compliance-and-monitoring)). **AgentMail** is second, the only agent-email product in this pass with both a live price list and several named production stories, every one of them a vendor claim. Free is **3 inboxes**, **3,000 emails a month**, and **100 a day**. Developer is $20 a month. Startup is $200 a month. OIDC and SAML SSO are Enterprise only. The customers index states, among other stories, that Lanesurf runs hundreds of inboxes and millions of messages and that AISDR has hundreds of inboxes and thousands of emails a week. The index does not give AgentMail’s own customer, inbox, or message total, so those stories cannot become a market share ([AgentMail pricing](https://www.agentmail.to/pricing.md), [AgentMail customers](https://www.agentmail.to/customers)). **Resend Inboxes** shipped on **22 October 2026**, nine days before this count, with 3 inboxes included and extra inboxes at $1 on paid plans, threads shared by the app, the team, and agents, and connectors named for Claude Code, Cursor, Codex, Grok, and Gemini through MCP or skills. The announcement and the pricing page state no volume. It is too new to rank on use ([Announcing Inboxes](https://resend.com/blog/announcing-inboxes), [Resend pricing](https://resend.com/pricing)). Microsoft Teams appears as one sentence on AgentMail’s customers index, a vendor claim that one product “lives in” Teams. It is not ranked. Discord, Gmail, and Outlook were not verified as agent inboxes on a page opened for this count. A search snippet that Claude Tag lists Teams as “coming soon” was not opened and is not a finding.

**Slack**, as documented for Claude, does group messaging an agent can join. It does not, on that page, do email, a git store, port forwarding, a public TLS edge, or a local text-protocol sidecar. **AgentMail** does email inboxes, threads, webhooks, SMTP, and an MCP server on every tier, with organization seats on paid plans and SAML only on Enterprise. It does not do git-backed storage, inbound port forwarding, a public TLS hostname for a process on the user’s machine, an audit of coding-agent actions, or a local subprocess of any harness. The MCP server is a remote tool API ([AgentMail pricing](https://www.agentmail.to/pricing.md)). Resend’s opened pages describe the same boundary: an inbox on the customer’s domain, not the rest of the seven jobs.

## GitHub records agent actions; Cursor records who changed a setting

No opened page gives a customer count for Cursor, Claude, Devin, Dust, Sourcegraph, Zep, Mem0, or LangSmith. GitHub’s Octoverse 2026 body did not load, so a search-extract claim that 55% of Copilot monthly active users use agentic features is not treated as verified, and neither is an unopened “50 million Copilot users” line. A usage rank of admin consoles by seats cannot be made. What can be ranked is the host product on the coding-agent surveys above, and, separately, how explicit the opened log is about what an agent did. Those are not the same order, and they are not averaged.

On the host-product surveys, GitHub Copilot, Cursor, and Claude Code are the admin surfaces a large share of respondents already touch. Devin is on the Stack Overflow table at **2.9%** and is absent from the JetBrains list that was opened, so a richer log there is not evidence of wider administration. Dust, LangSmith, Sourcegraph, and Zep have real docs and no opened usage number, so they are not placed on a people rank.

On explicitness, three opened logs record an agent doing something, and they record different things. GitHub enterprise owners can filter `actor:Copilot` and see agentic activity for **180 days**, with `actor_is_agent`, an agent session id, and the person who initiated the event. Examples are actions on GitHub objects such as `pull_request.create`. A public-preview stream can include Copilot request or response bodies, truncatable at 1 MB, for specific enterprise setups. The same vendor’s Copilot review page says the log does not include prompts a user sends to Copilot locally, and recommends streaming to a SIEM ([agent audit events](https://docs.github.com/en/copilot/reference/agentic-audit-log-events), [review Copilot audit logs](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/review-audit-logs)). Dust’s Enterprise log, viewed in an admin screen and exportable, distinguishes human and agent actions, including `agent.executed` and `tool.executed` ([Dust audit logs](https://docs.dust.tt/docs/audit-logs)). Devin’s enterprise audit API includes `create_session`, `send_message`, `terminate_session`, and `ai_guardrail_violation`, and the page does not state retention or a customer count ([Devin audit logs](https://docs.devin.ai/api-reference/v3/audit-logs/enterprise-audit-logs)). Cursor states the opposite for its main Enterprise log: payloads never include prompts, agent output, or generated code. Failed sign-ins are not logged. Grok Bot shell and browser actions are named as a separate recording path that was not opened ([Cursor compliance](https://cursor.com/docs/enterprise/compliance-and-monitoring)). Claude’s Enterprise export covers **180 days** and records sign-in, SSO changes, and conversation created, deleted, and renamed. “Title and content of chats and projects are not available to be exported” ([Claude audit logs](https://support.claude.com/en/articles/9970975-how-to-access-audit-logs)). LangSmith’s Enterprise log, retained up to **400 days**, is focused on write operations, including SSO, SCIM, and agent-registry writes, and the opened page does not say it stores prompts or model output ([LangSmith audit logs](https://docs.langchain.com/langsmith/audit-logs.md)). Sourcegraph writes structured JSON to standard error for a SIEM and says an in-app viewer is not the current audience. The opened entity list covers auth, RBAC, users, and completion quotas, not chat prompts ([Sourcegraph audit log](https://sourcegraph.com/docs/admin/audit-log)). Zep’s Enterprise dashboard log records member, key, project, and dashboard data operations, and it says API and SDK calls are not included ([Zep audit logging](https://help.getzep.com/audit-logging.md)). Mem0 is not ranked. No first-party page documenting SAML or OIDC, or an admin audit of what an agent did, was opened.

**GitHub**, for a team already on Enterprise and Copilot, does SAML SSO and an admin-visible audit of agent actions on GitHub objects, plus the license and policy events on the Copilot review page. It does not, on the pages opened, do real-time encrypted project storage, port forwarding, a public TLS edge for local services, or an inbox, and the log is not the local prompt stream. **Cursor** does team auth and an admin log of who changed the team. It does not do a transcript of what the agent wrote, and the network and storage jobs were not on the pages opened. **Claude** Team and Enterprise do SSO, with invite-only, just-in-time, and SCIM provisioning named on the setup page, and an org export of metadata. They do not put chat content in that export. Devin and Dust do a clearer agent-action record than Cursor or Claude’s export, and nothing opened shows they are as widely administered. None of these admin pages describe a userspace subprocess of an arbitrary harness.

## MCP stdio is the subprocess protocol the leading harnesses already speak

A survey rank of protocols cannot be made. No Stack Overflow or JetBrains question opened here asks whether the respondent uses MCP, ACP, or A2A. The order is by how well public evidence matches a userspace subprocess that any of the leading harnesses can drive over a text protocol.

**MCP over stdio** is first. The spec dated **28 July 2026** still defines stdio as newline-delimited JSON-RPC over the standard streams of a client-launched subprocess. Streamable HTTP is the other standard binding and is not a local subprocess ([MCP transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)). Named clients, from a community matrix plus vendor docs, include Claude Code, Claude Desktop, VS Code GitHub Copilot, Cursor, and ChatGPT. Codex documents `codex mcp`. Cursor’s audit log has an `mcp_server_config` event whose `server_type` is `HTTP` or `STDIO` ([MCP client matrix](https://modelcontextprotocol.io/extensions/client-matrix), [Codex CLI](https://learn.chatgpt.com/docs/codex/cli), [Cursor compliance](https://cursor.com/docs/enterprise/compliance-and-monitoring)). Install volume is large and is not people. In the npm window 23–29 October 2026, `@modelcontextprotocol/sdk` had **87,026,138** downloads and `@modelcontextprotocol/server` **21,176,440**. Those packages are not two versions of one install, and the v1 SDK line implements the spec only through 25 November 2025. The PyPI stats API for the package named `mcp`, retrieved 31 October 2026, reports **235,193,557** in `last_month` and does not name an end date. The project homepage was not opened, so that is a count for the package name. CI and dependency installs dominate this kind of number. Adding the npm and PyPI figures, or calling them users, would overstate adoption ([npm sdk downloads](https://api.npmjs.org/downloads/point/last-week/@modelcontextprotocol/sdk), [npm server downloads](https://api.npmjs.org/downloads/point/last-week/@modelcontextprotocol/server), [pypistats mcp](https://pypistats.org/api/packages/mcp/recent)).

**ACP** is second and is the same shape pointed the other way: an editor spawns the agent. The introduction says local agents run as subprocesses of the code editor and speak JSON-RPC over stdio. JetBrains says dozens of agents, including Cursor, can be added to its AI chat via ACP. “Dozens” is the vendor’s wording, not a census. No survey share, registry count, or download figure was opened. Cursor’s docs navigation includes an ACP entry. That page was not opened, so Cursor’s ACP behavior is not described ([ACP introduction](https://agentclientprotocol.com/get-started/introduction), [JetBrains](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/)). **Vendor CLIs** are third in this list even though the harnesses are the most-used products above. Claude Code can be run as a subprocess with `-p` and `--output-format json`. Codex can be run as `codex exec`. Each speaks its own CLI. A third-party tool does not become available in every harness by speaking that CLI ([Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview), [Codex CLI](https://learn.chatgpt.com/docs/codex/cli)). In-process libraries, the OpenAI Agents SDK, LangGraph, and Google’s Agent Development Kit, are real and are not a text protocol a foreign harness drives. No download or survey figure was opened for the Agents SDK or ADK, so they are not ranked against each other. Stack Overflow’s **24%** for the OpenAI Agents SDK is an orchestration answer on the narrative page, not a subprocess measurement ([OpenAI Agents SDK](https://openai.github.io/openai-agents-python/), [ADK](https://adk.dev/), [Stack Overflow AI](https://survey.stackoverflow.co/2026/ai)). **A2A** is a released 1.0.0 spec for agents to call each other over JSON-RPC, gRPC, and HTTP. It is not a client-launched local subprocess, and the spec page gives no adoption count ([A2A specification](https://a2a-protocol.org/latest/specification/)).

**MCP stdio** does the subprocess shape: any of the leading harnesses that already speak it can launch a local process and talk text to it. MCP does not, in the spec, store memory, forward a port, terminate public TLS for the user’s service, provide an inbox, or record an admin audit trail. Shipping `ngrok`, `cloudflared`, `tailscale`, or `devtunnel` as a userspace process is a tunnel CLI, not that protocol. No widely measured line-oriented local memory server, distinct from MCP’s own newline-delimited stdio, turned up. A memory server on that transport would be an MCP server.

## The smallest evidenced stack still leaves the store, the mail, and the trail apart

A team already sitting on the best-evidenced tools would be running **Claude Code** or **GitHub Copilot** as the harness, committing project instructions to ordinary git, publishing a laptop port with **ngrok** or, inside VS Code, with **dev tunnels**, talking to the agent in **Slack**, buying **AgentMail** if the channel has to be email, administering sign-in and the agent-action log in **GitHub Enterprise** when Copilot is the agent, and attaching local tools over **MCP stdio**. That is the smallest set the opened evidence supports. It is not a product.

Walk the seven jobs across that set. Job 1, real-time encrypted storage with a git front end, is the miss. Committed `CLAUDE.md` or Copilot custom instructions are git only because the team commits them, and they are not a memory service. Copilot Memory is hosted facts, not files, and it was generally available for three days. Letta is the git filesystem and has no usage figure. Mem0 is the memory-library download leader and is not git, and its encryption wording was not confirmed from an opened page. Job 2 and job 3 can be one tunnel. ngrok is the one with a signup claim. Dev tunnels are the one already inside VS Code, still a preview. Cloudflare Tunnel is the one Anthropic and Grok both name, with no count. None of the three is the store or the inbox. Job 4 does not fit in one vendor with a usage trail. Slack is the group channel the docs show. Email is AgentMail’s vendor stories, or Resend’s nine-day-old inbox with no volume. Job 5 and job 6 sit on the forge or the IDE, not on the tunnel or the mailbox. GitHub’s 180-day log is agent actions on GitHub objects. Cursor’s Enterprise log is who changed a setting. Claude’s export keeps identifiers and drops content. ngrok’s account audit log is a paid add-on on top of paid SSO. Cloudflare’s account audit log is long-lived, and there is no tunnel-user count to put next to it. Job 7 is a protocol the harnesses already speak, not one of those products. Claude Code’s JSON subprocess mode and Codex `exec` are real, and they are each a single vendor’s CLI.

The jobs that remain split are the store, the human-and-agent thread, and the admin record of what the agent actually did. A team can buy a closer match for each one, Letta or Mem0, AgentMail or Resend, Devin or Dust, and those closer matches are exactly the tools that lack a people denominator. Nothing opened is one process that does the seven jobs. That is a statement about the pages and the counts that were opened, not a proof that no unopened product bundles more.

## Conclusion

The scoreboard you pick changes the competitor. People-surveys name Claude Code, then Copilot, then Codex, then Cursor, and those products are harnesses with admin consoles, not encrypted git memory or a tunnel. Package downloads name Mem0 among memory libraries and name MCP among protocols, and both numbers are install events. A vendor about page names ngrok, without a date. Product docs name Slack, without an install count. Mixing 39% of professionals with 2.6 million PyPI downloads and 15.3 million undated signups would invent a market share none of the sources contains.

What that leaves, for someone deciding what they are up against, is an installed stack rather than a category leader. The tools with the best overlap on a single job are the ones with the worst usage evidence, and the tools with the best usage evidence each miss most of the seven jobs. Copilot Memory’s general availability on 28 October 2026 can move the hosted-memory picture, and neither survey can see it yet. Cloudflare Tunnel and dev tunnels can be more widely installed than ngrok’s signup lead is able to prove. The combination in the brief is not what any of these scoreboards is measuring.
