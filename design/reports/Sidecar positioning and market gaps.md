# Sell the record, not the tunnel

URnetwork should position its agent sidecar as **the private record of agent work across harnesses**: a tamper-evident log, held under the team's own keys, of what every Claude Code, Codex, Copilot or Cursor session did through the sidecar, who allowed it, and what it left for the next run to open. The beachhead is **small and mid-size engineering teams that already run two or more coding harnesses and must answer clients or auditors for what their agents did**, with developers adopting free and a team lead paying per seat for the admin record and the keys. The features closest to URnetwork's heritage (port forwarding and a public TLS edge) and those that sound most like the 2026 agent market (agent mailboxes and git-backed memory) no longer set anyone apart: Claude Code and Codex built agent mail into the harness this year, Cloudflare offers git-speaking storage, agent email and tunnels on one platform, Tailscale became Codex's private-network path without a partnership, and Okta folded agent sign-on into core SSO at no extra cost. What stays open is what incumbents' business models discourage: coordination across rival vendors' agents, storage the operator cannot read, and a record of local actions taken at the source, which OpenAI, Anthropic and GitHub each document that their own logs miss. The binding constraint is URnetwork itself. Its live agent skill advertises "distributed scraping" over a residential exit network in the year Google and the FBI dismantled residential proxy networks, its network now runs as a Bittensor subnet with tokenholder letters, its "no logs" and "100% open source" marketing outruns its own threat model, and its warrant canary and transparency report return 404. The sidecar therefore has to be separated from the egress network in architecture, contract and claims, with its privacy resting on customer-held keys rather than on the VPN's split-knowledge design. That revises the line earlier research recommended, "Keep what the last run changed, and let the next one reach the machine": continuity is now a harness built-in and reach is a commodity with a public exposure record, so both belong inside the record as benefits rather than in the headline.

## Harness built-ins and cloud bundles already cover most single jobs

A team weighing the sidecar compares it first with what it already pays for, and the harnesses absorbed much of the design during 2026. Claude Code shipped agent teams in February, with a JSON mailbox per agent, a shared task list claimed under file locks and hooks for idle and finished teammates, although the feature remains **experimental and disabled by default** and allows one team per session ([Claude Code docs](https://code.claude.com/docs/en/agent-teams)). In August it added cross-session `SendMessage` "on any of your machines"; those messages cross machines **"Through Anthropic servers,"** are plain text only, and reach only the user's own sessions signed in to claude.ai ([Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md); [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)). Remote Control connects a phone or browser to a laptop session over outbound HTTPS through Anthropic's API; self-hosted runners reach internal services while "Anthropic stores the session transcript"; and Claude Tag joined Slack in June as a beta "team member" with channel memory and an admin log of each action and who requested it ([Remote Control](https://code.claude.com/docs/en/remote-control); [self-hosted environments](https://code.claude.com/docs/en/self-hosted-environments.md); [Anthropic](https://www.anthropic.com/news/introducing-claude-tag)). Codex had agent mail by April and added a shared agent message board in September, extended in CLI 0.165 on 27 October ([Codex PR #16725](https://github.com/openai/codex/pull/16725); [Codex PR #46959](https://github.com/openai/codex/pull/46959); [Codex changelog](https://learn.chatgpt.com/docs/changelog)). A Hacker News commenter named the pattern on launch day: "Agent teams in this release is mcp-agent-mail built into the runtime" ([HN](https://news.ycombinator.com/item?id=46902223)).

GitHub built the broadest governance plane beside a code host. Agent HQ runs Claude and Codex inside GitHub's own runtime and billing, in public preview at one premium request per session; the enterprise agent control plane became generally available on **26 February 2026** with an `actor_is_agent` audit field and agent-session events; and managed permissions over shell commands, file edits and network domains reached GA on 9 September for Copilot surfaces ([GitHub blog](https://github.blog/news-insights/company-news/pick-your-agent-use-claude-and-codex-on-agent-hq/); [control plane GA](https://github.blog/changelog/2026-02-26-enterprise-ai-controls-agent-control-plane-now-generally-available/); [managed permissions](https://github.blog/changelog/2026-09-09-enterprise-managed-permissions-for-github-copilot-agent-operations/)). Copilot Memory became generally available on 28 October, the Copilot app's Memory++ queries context from sessions in the app, the CLI, VS Code and github.com, and Universe 2026 added session continuity across those surfaces plus Copilot inside GitHub Enterprise licences ([GitHub changelog](https://github.blog/changelog/2026-10-28-github-intelligence-puts-your-code-context-and-history-to-work/); [Copilot app](https://github.blog/news-insights/product-news/github-copilot-app-the-agent-native-desktop-experience/); [Universe 2026](https://github.blog/news-insights/company-news/github-universe-2026-evolving-every-layer-of-the-stack/)). Cursor's cloud agents reach private networks through Tailscale or Cloudflare Tunnel, with AWS PrivateLink for Enterprise arranged through sales, and its Enterprise audit log records settings and sign-ins but never prompts or agent output ([Cursor network docs](https://cursor.com/docs/cloud-agent/security-network); [Cursor private connectivity](https://cursor.com/docs/cloud-agent/private-connectivity); [Cursor compliance](https://cursor.com/docs/enterprise/compliance-and-monitoring)).

Above the harnesses, four platforms bundle governance for the agents they host or license. Microsoft's Entra Agent ID "is available for all Microsoft Entra customers," Agent 365 has been GA since 1 May 2026 at **$15 per user per month** under the rule that "Agents do not require their own licenses," and agents get real mailboxes only in tenants enrolled in Microsoft's Frontier preview program ([Microsoft Learn](https://learn.microsoft.com/en-us/entra/agent-id/what-are-agent-identities); [Microsoft Security blog](https://www.microsoft.com/en-us/security/blog/2026/05/01/microsoft-agent-365-now-generally-available-expands-capabilities-and-integrations/); [Microsoft licensing FAQ](https://www.microsoft.com/licensing/faqs/122); [Agent 365 identity](https://learn.microsoft.com/en-us/microsoft-agent-365/developer/identity)). OpenAI's Frontier claims to govern agents "regardless of their origin," but it is sold through sales teams and, among third-party clouds, only through AWS ([InfoQ](https://www.infoq.com/news/2026/02/openai-frontier-agent-platform); [OpenAI](https://openai.com/index/amazon-partnership/)). Google issues SPIFFE identities with 24-hour certificates to agents on its own runtimes and promotes A2A, now a Linux Foundation 1.0 standard, for messages between agents ([Google Cloud docs](https://docs.cloud.google.com/iam/docs/agent-identity-overview); [Linux Foundation](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)). Cloudflare comes closest to the whole design. It offers Artifacts, a versioned file system that "speaks Git" to "any regular Git client" at $0.15 per thousand operations; Agent Memory with shared profiles; Email Service with an `onEmail` hook that routes addresses to agent instances; Tunnel and the Workers edge; and MCP server portals, GA since 24 September, whose Access logs record "tool, prompt, and resource activity" with DLP scanning ([Cloudflare blog](https://blog.cloudflare.com/artifacts-git-for-agents-beta); [InfoQ](https://www.infoq.com/news/2026/04/cloudflare-agent-memory-beta/); [Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-04-16-email-sending-public-beta/); [Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-09-24-mcp-portals-ga/)).

Neutral infrastructure vendors sell one or two jobs each, across every harness. Tailscale calls itself "the missing network identity layer for AI agents," made its Aperture gateway generally available with "a clear audit trail, because all of your agent's actions are logged," added MCP endpoints through which an agent requests tailnet access that a human approves, and became Codex Cloud's only supported VPN without a deal: "Codex Cloud shipped with Tailscale support. Nobody told us" ([Tailscale](https://tailscale.com/use-cases/secure-ai-agent-connectivity); [Tailscale blog](https://tailscale.com/blog/aperture-ga); [TailscaleUp](https://tailscale.com/tailscaleup-date-week-26); [Tailscale blog](https://tailscale.com/blog/codex-cloud-tailscale)). Coder's AI Gateway and Agent Firewall "Audit developer prompts, agent tool calls, and network activity" in Coder workspaces, and Okta put agent SSO into core Okta SSO "at no additional cost" in August ([Coder](https://coder.com/blog/secure-agentic-ai-now-production-ready); [Okta](https://www.okta.com/newsroom/press-releases/okta-brings-first-class-identity-to-ai-agents-with-agent-sso/)). Open source covers the rest for free or close to it. claude-mem has **107,507 GitHub stars** for cross-harness memory with an optional team workspace, Beads has 28,326 for a Dolt-backed agent task graph, Gas Town routes typed mail across 11 harness presets, MCP Agent Mail gives agents identities, inboxes, file leases and a git ledger over MCP, Entire raised a **$60M seed** to store agent sessions in git, and AgentMail ($6M seed) and Resend Inboxes (launched 22 October) sell inboxes that people and agents share ([claude-mem](https://github.com/thedotmack/claude-mem); [Beads](https://github.com/gastownhall/beads); [Gas Town](https://github.com/gastownhall/gastown); [MCP Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail_rust); [TechCrunch](https://techcrunch.com/2026/02/10/former-github-ceo-raises-record-60m-dev-tool-seed-round-at-300m-valuation/); [TechCrunch](https://techcrunch.com/2026/03/10/agentmail-raises-6m-to-build-an-email-service-for-ai-agents/); [Resend](https://resend.com/blog/announcing-inboxes)).

The pattern behind the table matters more than any row. Model vendors and the code host bundle the human-facing jobs (memory, messaging, team auth and audit) and bind them to their own runtime and to transcripts they hold. Network vendors bundle reach and stay neutral, but they govern by inspecting traffic at a gateway they operate. Only Cloudflare spans both groups, and it does so as a platform for agents built on Workers rather than as a process running beside Claude Code or Codex on a developer's machine. Much of this coverage is still labeled experimental, preview or beta, so it is broad but not settled. For most teams the real default remains the assembled stack earlier research identified (a harness, committed instruction files, a tunnel, Slack, the forge's audit log and MCP), with more of it now inside the harness. Earlier research also found that no widely used product performs all seven designed jobs in one process, and that still holds. What no longer holds is the idea that composition alone is a gap worth owning, because Cloudflare has already assembled the cloud version from parts it sells separately.

## Neutrality, operator blindness and source records remain open

None of the seven designed features is unique on its own, and six of the sidecar's attributes are now commodities or contested. Agent-to-agent mailboxes, task lists and file leases are free inside the two most-used harnesses and in open source. Git-shaped agent storage, which earlier research found only in Letta's MemFS, is now a Cloudflare primitive, Entire's product, the storage layer under Beads on Dolt (whose maker changed its slogan to "Dolt is the Database for Agents"), and MCP Agent Mail's ledger ([DoltHub](https://www.dolthub.com/blog/2026-06-05-our-ai-policy/)). Port forwarding and a public TLS edge have four mature suppliers in ngrok, Cloudflare, Tailscale and Microsoft's dev tunnels. Base agent identity is free inside Entra and Okta, and the specialists are being absorbed: Palo Alto Networks closed its roughly **$25B** CyberArk acquisition on 11 February 2026, and CrowdStrike, Cisco, SailPoint, Cyera and Okta each bought or agreed to buy an agent- or machine-identity company during 2026 ([Palo Alto Networks](https://investors.paloaltonetworks.com/news-releases/news-release-details/palo-alto-networks-completes-acquisition-cyberark-secure--ai-era); [CrowdStrike](https://www.crowdstrike.com/en-us/press-releases/crowdstrike-to-acquire-sgnl-to-transform-identity-security-for-ai-era/); [Cisco](https://blogs.cisco.com/news/cisco-announces-intent-to-acquire-astrix-security)). Gateway audit of prompts and tool calls is what Tailscale, Coder, Cloudflare and ngrok sell, by inspection. Agent email is contested by AgentMail, Resend, Cloudflare and, inside tenants, Microsoft.

Three attributes stay open because incumbents' business models push against them. The first is **coordination across rival vendors' agents at runtime**. Anthropic's documentation states that "In every approach the workers are Claude sessions," its cross-machine messaging is unavailable with an API key or on Bedrock, Google Cloud and Foundry, and Remote Control also switches off behind an LLM gateway ([Claude Code docs](https://code.claude.com/docs/en/agents); [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging); [Remote Control](https://code.claude.com/docs/en/remote-control)). GitHub admits rival agents but runs and bills them itself. The second is **storage and records the operator cannot read**. Every incumbent's compliance value comes from content it holds or inspects. Anthropic's MCP tunnels are engineered so that "Cloudflare cannot read request or response payloads," yet Anthropic's own back end terminates the inner TLS, and Cloudflare's Artifacts post does not say how content is encrypted or who can read it ([Claude Platform docs](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview); [Cloudflare blog](https://blog.cloudflare.com/artifacts-git-for-agents-beta)). The organizations that most want blindness are the ones Anthropic turns away: zero-data-retention and HIPAA organizations cannot enable Remote Control, and those with customer-managed keys "can't start cloud sessions" ([Remote Control](https://code.claude.com/docs/en/remote-control); [Claude Code docs](https://code.claude.com/docs/en/claude-code-on-the-web)). The one privacy-first coordination tool, Happy, encrypts its relay between devices but has no store, inbox or audit trail ([Happy](https://github.com/slopus/happy)). The third is **a record of local actions taken at the source**. OpenAI writes that "Conversation visibility alone does not establish a complete record of local actions"; Anthropic's Compliance API does not capture "on-device activity that never reaches the API"; and GitHub's generally available control plane listed VS Code and Copilot CLI session activity as future work ([OpenAI governance](https://learn.chatgpt.com/docs/enterprise/governance); [Claude Compliance API FAQ](https://platform.claude.com/docs/en/manage-claude/compliance-faq); [GitHub changelog](https://github.blog/changelog/2026-02-26-enterprise-ai-controls-agent-control-plane-now-generally-available/)).

Open is not the same as wanted, and encryption needs the most care. No established product combines end-to-end encryption, real-time sync and a git interface for teams. Keybase's encrypted git encrypted "even your repository names and branch names" in 2017 but synced by push and pull; git-remote-e2ee is a one-star prototype; Automerge's encrypted repository layer "is still in alpha" with "no key backup or recovery mechanism"; and Radicle says its private repositories are "not encrypted at rest" and "unfit for use today" ([Keybase](https://keybase.io/blog/encrypted-git-for-everyone); [git-remote-e2ee](https://github.com/combinatrix-ai/git-remote-e2ee); [Automerge](https://automerge.org/docs/keyhive/ark-api-guide/); [Radicle](https://radicle.dev/guides/user)). Keybase also shows the commercial trap. It shipped encrypted git, cryptographic teams with key rotation and encrypted chat for free, deferred charging until "someday if teams take off," and was bought by Zoom in 2020, when its own announcement said its "single top priority" was "helping to make Zoom even more secure" ([Keybase teams](https://keybase.io/blog/introducing-keybase-teams); [Keybase joins Zoom](https://keybase.io/blog/keybase-joins-zoom)). Jazz, the best-known encrypted-sync startup, rebuilt its product in 2026 as a relational database whose read policies run on the server, and its new pages no longer foreground end-to-end encryption ([Jazz](https://jazz.tools/)). Earlier user research found no developer asking for encryption at rest. Encryption is therefore the precondition that makes a "private record" true and the qualifier for segments the incumbents exclude, not a headline for every developer, and "the first encrypted git" is not a claim URnetwork can make.

The defensible offer is the bundle only when one object ties it together. A store, a tunnel and an inbox sold side by side are three commodities. The same three, each writing into one customer-keyed record that any harness can open, is a product no incumbent sells. Cloudflare is best placed to build a rival because it already has storage, memory, email, tunnels and identity, but its model hosts agents on Workers and secures them by inspection, which points it away from a blind process on a developer's laptop. That is an inference about incentives, and Cloudflare's roadmap is the first thing to watch.

| Agent email shared with people | Contested | AgentMail, Resend Inboxes, Cloudflare Email Service, Microsoft agentic users |
| Coordination across rival vendors' agents and people | Open; structurally avoided | "The workers are Claude sessions"; Agent HQ runs rivals on GitHub's bill |

### Eight earlier conclusions the new evidence revises

The earlier market, overlap and user-gap research holds on its central finding: the tools people actually use each cover one or two jobs, and the tools that overlap a single job best have the weakest usage evidence. It needs revision on the points below, each grounded in evidence cited in this report.

| Earlier conclusion | What the new evidence changes |
|---|---|
| The open gap is composition: no product does the seven jobs together | Still true for one process, but Cloudflare now assembles six of seven as cloud primitives, so the gap worth owning is neutral, operator-blind and local rather than composition |
| Letta MemFS was the only git filesystem for agent memory | Git-shaped agent storage is now common (Artifacts, Entire, Beads, MCP Agent Mail); only encryption, real-time sync and git together are absent |
| Claude's audit export drops chat content | The export does, but the Compliance API returns session transcripts for Enterprise Claude Code and Cowork; it still misses on-device activity and API-key, Bedrock, Google Cloud, Foundry and cloud sessions |
| Slack is where agents meet people; agent email is a vendor story | Agent-to-agent mail moved into Claude Code and Codex, and Claude Tag became a Slack teammate, so the group inbox cannot be sold as agent mail |
| "Non-human identity" and "audit trail" were not buyer words | They are the security buyer's words (NIST, OWASP, Five Eyes, Microsoft, Okta), and 68% of surveyed organizations cannot tell agent from human activity; developers still speak continuity |
| No user asked for a subprocess protocol, shared mailboxes or relay-free operation | Single issues and comments now ask for stdio transport, project-addressed shared mailboxes, other harnesses and no central relay; encryption at rest is still not a user request |
| Reach is a commodity tunnel job | For a laptop port, yes; for cloud agents, private reach is plan-gated, single-provider or HTTP-only, and no vendor documents reaching a developer's own machine |
| URnetwork was out of scope | Its egress network, token and public claims now dominate how a security reviewer will read the sidecar |

## Five gaps ranked: the local-action record leads, reach trails

The gaps below are ranked on four tests taken together: how well the need is documented, whether incumbents' business models keep them out, how much of the gap URnetwork's existing assets cover, and whether someone in the beachhead will pay. The resulting order runs almost exactly opposite to URnetwork's engineering strengths, which is the central strategic fact in this report.

| Rank | Gap | Strongest evidence of need | Why incumbents leave it open | URnetwork fit today | Main constraint |
|---|---|---|---|---|---|
| 1 | A source-level record of what agents did through the sidecar, across harnesses, bound to the human who approved it | 68% cannot tell agent from human activity; vendors document local gaps; Cursor users ask for proposal-to-command records | Each vendor logs its own runtime and API path | Low: only operator-side audit rows exist, no customer-facing product | Sees only what crosses it; no statute requires it before December 2027 |
| 2 | Shared context and records the operator cannot read | Anthropic excludes ZDR, HIPAA and CMEK orgs; Entire warns public transcripts are readable; users avoid central relays | Compliance value rests on content incumbents hold | Medium: an MLS messenger in early development | No developer has asked for it; claims face malicious-server scrutiny |
| 3 | Coordination between rival harnesses and the people running them | A third of agent users run several agents, mostly daily; two-thirds switched tools in a year | Model vendors earn when work stays on their runtime | Medium: recipes for 21 harnesses, OAuth MCP | Free open source and GitHub Agent HQ; little willingness to pay on its own |
| 4 | Governed reach from cloud and local agents to private services | Codex supports one VPN; Cursor's PrivateLink is sales-only; no vendor reaches a developer's laptop | Model vendors route reach through their own cloud | High: relay, userspace WireGuard, permanent client addresses | Neutral incumbents already present; exposure incidents; proxy optics |
| 5 | One identity and inbox namespace for people and agents across organizations | Microsoft offers agent mailboxes only in preview tenants; users asked for shared mailboxes | Microsoft stays in its tenant; others prefer Slack and issues | Low: email is entirely new | Lethal-trifecta exposure; plaintext SMTP; three funded rivals |

**The local-action record ranks first** because it pairs the best-documented need with the clearest structural absence and a buyer who pays. A Cloud Security Alliance survey of 228 organizations, financed by Aembit, found **68% "can't clearly distinguish between human and AI agent activity,"** with 43% running agents on shared service accounts and 31% on human identities ([CSA](https://cloudsecurityalliance.org/articles/more-than-two-thirds-of-organizations-cannot-clearly-distinguish-ai-agent-from-human-actions)). Cursor users ask for exactly this object: "None of these proposals or decisions are persisted in any queryable, exportable form," and without a shared action id "it may still be impossible to prove that the executed action was precisely the action the user approved" ([Cursor forum](https://forum.cursor.com/t/platform-level-audit-trail-for-agent-tool-call-proposals-and-user-approval-decisions/156247)). Official guidance converges on the same shape. NIST's NCCoE asks how agents can "log their actions and intent in a tamper-proof and verifiable manner" bound back to human authorization; the Five Eyes cyber agencies want "tool usage, inter-agent communication, and decision-making chains" monitored; and OWASP's Q3 2026 roundup tells defenders to log actual network, tool and credential events correlated by run ID rather than trusting the model's own account ([NCCoE](https://www.nccoe.nist.gov/sites/default/files/2026-02/accelerating-the-adoption-of-software-and-ai-agent-identity-and-authorization-concept-paper.pdf); [Crowell & Moring](https://www.crowell.com/en/insights/client-alerts/american-and-allied-cyber-agencies-issue-first-joint-guidance-on-securing-agentic-ai); [OWASP](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026/)). The cost of missing it is concrete: when Anthropic's evaluation agents, left with live internet access by a partner's misconfiguration, broke into real systems, **two of the three affected organizations had not detected the activity** ([Anthropic](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)). Microsoft says its discovery of Claude Code and Copilot CLI is only "expanding soon," which shows how open the local CLI surface still is ([Microsoft Security blog](https://www.microsoft.com/en-us/security/blog/2026/05/01/microsoft-agent-365-now-generally-available-expands-capabilities-and-integrations/)). Two limits keep the pitch honest. The sidecar sees only what crosses it (its own store writes, forwards, publishes, mail and membership changes) plus whatever hook or telemetry events the harness sends; it does not see a shell command the harness runs on its own. And no statute compels such a log yet: the EU's Digital Omnibus moved high-risk AI Act obligations, including at least six months of log retention, to 2 December 2027, so the near-term drivers are customer security questionnaires and SOC 2 auditors improvising AI evidence requests under 2017 criteria ([Hunton](https://www.hunton.com/privacy-and-cybersecurity-law-blog/eu-digital-omnibus-on-ai-enters-into-force); [AI Act Art. 26](https://artificialintelligenceact.eu/article/26/); [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-soc2-ai-controls-gap-20260830-csa-styled/)). Every survey figure in this paragraph comes from a vendor-run or vendor-sponsored study.

**Operator-blind shared context ranks second** because it is what makes the record distinctive and what the excluded segments need, but its demand evidence is indirect. Incumbents publicly exclude the organizations most likely to pay for blindness. Entire warns that transcripts pushed to a public repository can be read by "anyone" and that its redaction "is best effort." Users of remote-agent tools route around central relays: one runs "the Happy server on my home Mac to skip the cloud relay," and another recommends "solutions which don't require a central server" ([Entire](https://github.com/entireio/cli); [HN](https://news.ycombinator.com/item?id=46991591); [HN](https://news.ycombinator.com/item?id=44878650)). Against that, no developer in the earlier user research asked for encryption at rest, and every claim in this gap will be tested against a malicious server.

**Cross-vendor coordination ranks third, with the broadest need and the weakest moat.** Stack Overflow's May 2026 pulse survey found 17% of agent users running multiple specialized agents and 16% running coordinated ones, and those users work with agents daily at **85% and 77%**, against 54% for single-agent users; the 2026 Developer Survey found only 33.7% had not switched AI tools in the past year ([Stack Overflow blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work); [Stack Overflow survey](https://survey.stackoverflow.co/2026/ai)). Users ask for cross-harness reach in their own words: Entire's "Codex support" issue opened the day after launch, Happy users requested OpenCode, and one Claude user wrote, "Would be great if it supported API keys. I'm getting by with slack threads of all things for work" ([Entire #245](https://github.com/entireio/cli/issues/245); [Happy #265](https://github.com/slopus/happy/issues/265); [HN](https://news.ycombinator.com/item?id=47148454)). Coordination alone has not won mindshare, though. MCP Agent Mail's original repository has **2,227 stars against claude-mem's 107,507**, and coordination spreads when an orchestrator or a harness bundles it. Vibe Kanban, a multi-harness agent board, shut its hosted service in April because "the vast majority are free users" ([MCP Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail); [Vibe Kanban](https://www.vibekanban.com/blog/shutdown)). Neutral coordination is the developer's reason to install, not the reason anyone pays.

**Governed reach ranks fourth despite being URnetwork's strongest asset.** The cloud-agent need is real. Codex cloud supports only Tailscale and reaches TCP services through an HTTP CONNECT proxy; Cursor's PrivateLink route is Enterprise-only, arranged through sales, and excludes SSH and custom ports; Anthropic-hosted Claude sessions document no VPN option; Devin's VPN setup excludes client VPNs that require MFA; and no vendor documents a cloud agent reaching a developer's own machine ([OpenAI Codex docs](https://learn.chatgpt.com/docs/environments/cloud-environments); [Cursor](https://cursor.com/docs/cloud-agent/private-connectivity); [Claude Code docs](https://code.claude.com/docs/en/cloud-environments); [Devin docs](https://docs.devin.ai/onboard-devin/vpn)). Cursor's own documented route, a tunnel client inside the agent that exposes a `localhost` listener and forwards to a private origin, is the sidecar's mechanism ([Cursor](https://cursor.com/docs/cloud-agent/security-network)). Yet the incumbents in this gap are already neutral, Tailscale's own post warns that "By default, Codex could reach nearly everything in your tailnet," and easy exposure is how agent control planes ended up on the open internet, as the risk section shows ([Tailscale blog](https://tailscale.com/blog/codex-cloud-tailscale)). Reach earns its place as a scoped grant that the record shows someone approved, not as the pitch.

**A shared human-and-agent identity and inbox ranks fifth.** Only Microsoft gives agents real mailboxes, inside M365 tenants in its preview program; Cloudflare's inboxes serve agents built on Workers; and MCP Agent Mail users asked for "project-addressed shared mailboxes" ([Agent 365 identity](https://learn.microsoft.com/en-us/microsoft-agent-365/developer/identity); [MCP Agent Mail #263](https://github.com/Dicklesworthstone/mcp_agent_mail/issues/263)). But an inbox that agents read, next to a private store and an outbound channel, assembles every leg of what Simon Willison calls the lethal trifecta. Inbound mail also reaches the receiving server as ordinary SMTP before anything can encrypt it, and the earlier user research found no one asking to join a mail thread and a tool log in one record. The inbox's strongest job is narrower: the channel through which a person approves an action or corrects a run, so that the approval lands in the record.

The ranking inverts URnetwork's asset map. Its production networking (an operator relay, client addresses that are never revoked once allocated, userspace WireGuard and a gVisor fork) maps onto the fourth-ranked gap, while the first-ranked gap rests on a customer-facing audit product URnetwork has not built and an encryption claim it has not had audited ([GitHub API](https://api.github.com/orgs/urnetwork/repos); [internal threat model](file:///Users/brien/urnetwork/cure53/THREAT-MODEL.md)). Leading with what the company does best would put it in the most crowded and most reputationally loaded part of the market.

## Compete as the agent-work record, starting with two-harness teams

Buyers will file the sidecar under some category, and most of the available ones lose. As "agent memory" it faces Copilot Memory, Claude's auto memory, Mem0 and claude-mem; as "agent mail" it faces free harness mailboxes; as a "tunnel" it faces ngrok and Tailscale with a residential-proxy company's name attached; as an "AI gateway" it faces vendors whose model is inspection; and as "agent identity" it faces identity providers that give the base layer away. Even "sidecar" is taken: Microsoft documents an Entra "Auth SDK (sidecar)" for agent authentication, including a sidecar for local development ([Microsoft Learn](https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id)). The frame with room is the emerging **agent-work record**, validated by investors and standards writers but not yet owned by anyone privately. Entire raised $60M to put agent sessions in git; git-ai links every AI-written line to its agent, model and prompts; the Agent Trace specification sits in Thoughtworks' "Assess" ring; and Turso's AgentFS keeps an append-only tool-call log ([Entire](https://github.com/entireio/cli); [git-ai](https://github.com/git-ai-project/git-ai); [Thoughtworks](https://www.thoughtworks.com/radar/platforms/agent-trace); [Turso](https://turso.tech/blog/agentfs)). None of them encrypts the record. Capital confirms the frame is early rather than settled: the largest 2026 rounds went to execution, with Modal's $750M Series D at a $15.75B valuation and Daytona's $60M Series B at $1B, while memory, agent email, agent identity and run records raised seed or Series A money with no clear leader ([RuntimeWire](https://runtimewire.com/article/modal-750m-series-d-1b-run-rate); [Tech Funding News](https://techfundingnews.com/daytona-raises-60m-at-1b-valuation-to-build-a-cloud-for-ai-agents/)). URnetwork's version differs from the existing record products on three counts: it records actions and approvals rather than code lines or transcripts, it covers reach and messages as well as storage, and its vendor cannot read it. It is not an evaluation product. It can hold a failed check or a human "no" for the next run, but it does not grade the run.

As a positioning statement: for engineering teams that run more than one coding agent and have to answer for what those agents did, the product is the private record of agent work. Every harness writes to it through one local process, the next run in any harness starts from it, and only the team holds the keys. Unlike the logs inside Claude, Codex, Copilot or Cursor, it covers every harness and the actions that never reach a vendor's API; unlike gateways from Tailscale, Coder or Cloudflare, it keeps the record without URnetwork being able to read it. The two people who must say yes need different first sentences. Security reviewers already speak this vocabulary, since "non-human identity," "sponsor," "registry of authorized agents," "immutable audit trail" and "kill switch" recur across NIST, OWASP, the Five Eyes guidance, Microsoft and Okta, so their line can be "Know which agent did what, in any harness, and who allowed it, without handing the record to another vendor." Developers still speak continuity, so theirs keeps the earlier research's instinct in narrower form: "The next run starts from what the last one did, whichever harness runs it."

Who should hear this first follows from where three conditions overlap: multi-harness use, an obligation to answer to someone outside the team, and reputational exposure URnetwork can survive. Multi-agent users are a minority but the heaviest users. Temporal's vendor-sponsored survey of 554 agent users found the average team using 3.5 listed AI tools, and GitHub reports that agents opened more than 40% of pull requests in September 2026 and that 61% of Copilot users who chose their own model used more than one ([Temporal](https://temporal.io/reports/state-of-development-2026); [GitHub Octoverse](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/)). No primary 2026 survey measures how many developers use two or more distinct harnesses, so the beachhead's size is an estimate from these proxies. Buying starts bottom-up: Menlo Ventures puts product-led growth at 27% of AI application spend, and close to 40% with shadow AI included, while 65% of large-enterprise CIOs in a16z's 2025 survey prefer an incumbent's solution when one exists ([Menlo Ventures](https://menlovc.com/perspective/2025-the-state-of-generative-ai-in-the-enterprise/); [a16z](https://a16z.com/ai-enterprise-2025/)). The share of Stack Overflow respondents working in an "organization of one" rose to 10% ([Stack Overflow blog](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)). Fintech (55% daily agent use) and media and advertising (50%) lead the industries in Stack Overflow's pulse survey, while healthcare (36%) and government (35%) trail ([Stack Overflow blog](https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work)).

The beachhead combines a developer who can install a subprocess without asking anyone, a team lead who can pay without a procurement department, and an outside party, a client's security questionnaire or a SOC 2 auditor, that creates the reason to keep a record. Those teams are where URnetwork's reputational risk is moderate rather than fatal, because they already tolerate tunnel and VPN vendors, and where the record's two benefits meet in one person: the lead who wants the next run to start from the last one is also the person who answers the client's question about what the agents touched. The size band is an inference. It is the 2-to-150-seat range Claude sells as its Team plan, and it sits below the enterprises that buy through incumbents ([Claude pricing](https://claude.com/pricing)). Software consultancies and agencies belong in it on the strength of client confidentiality and the media-and-advertising figure, which is only a proxy, since no source measured agencies directly. Security and IAM teams at larger firms should come second, and only once a published audit, SOC 2 and a cleaned-up agent surface exist. Organizations that Anthropic excludes for zero data retention, HIPAA or customer-managed keys are the largest prize for operator blindness and the least forgiving of URnetwork's history, so they come last.

Pricing should follow the market's habit of charging per human and metering the rest. Microsoft licenses Agent 365 per user and says agents need no licence; Okta prices agentic identity as an uplift on per-user pricing "to reduce buying friction"; Tailscale charges $8 or $18 per user, with non-human "tagged resources" at $1 a month beyond the first 50; and Letta's $0.10 per active agent is a rare per-agent price ([Microsoft licensing FAQ](https://www.microsoft.com/licensing/faqs/122); [Quartr](https://quartr.com/events/okta-okta-goldman-sachs-communacopia-technology-conference-2026_3eA3BLSd); [Tailscale pricing](https://tailscale.com/pricing); [Letta pricing](https://docs.letta.com/letta-code/pricing)). The per-person prices a beachhead team already pays (Tailscale Standard at $8, Basic Memory at $15 during its beta, Agent 365 at $15, Copilot Business at $19, a Claude Team standard seat at $20 to $25) suggest a team seat in that band for the record, the keys and team management, with storage, edge traffic and mail metered and agents left unmetered. That band is an inference from these anchors ([GitHub docs](https://docs.github.com/en/copilot/get-started/plans); [Basic Memory](https://github.com/basicmachines-co/basic-memory); [Claude pricing](https://claude.com/pricing)). The paid wedge has to exist at launch, because Keybase and Vibe Kanban show where free coordination tools end. x402 stablecoin payments can stay as a way for autonomous agents to top up usage, but they have no place in the team sale.

## URnetwork's own footprint is the binding constraint

Residential proxies moved from a gray market to an enforcement target in the year before this report. Google's threat-intelligence group disrupted IPIDEA in January 2026, calling it "one of the largest residential proxy networks in the world" after finding **550+ threat groups** using its exit nodes within seven days, and told consumers to be "extremely wary of applications that offer payment in exchange for 'unused bandwidth' or 'sharing your internet'" ([Google Cloud blog](https://cloud.google.com/blog/topics/threat-intelligence/disrupting-largest-residential-proxy-network)). The FBI seized NetNut-linked domains on 2 July 2026, and the Cloud Security Alliance concluded that "Distinguishing a legitimate proxy network from a botnet depends on consent quality and customer vetting, not on technical architecture" ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-residential-proxy-economy-systemic-risk-20/)). Identity tools act on the category automatically: Okta rejects blocklisted anonymizer IPs "before any type of policy evaluation occurs," and the DISA STIG for Okta treats a missing anonymous-proxy block as a finding ([Okta help](https://help.okta.com/en-us/Content/Topics/Security/healthinsight/blocklist-proxies-tor.htm); [STIG Viewer](https://www.stigviewer.com/stigs/okta_identity_as_a_service_idaas/2025-11-19/finding/V-279692)).

A reviewer who searches URnetwork will find it matching that pattern before reading anything about the sidecar. Its agent skill on GitHub is for tasks that need "many distinct egress IPs (distributed scraping)" and carries a recipe by that name ([SKILL.md](https://github.com/urnetwork/skill/blob/main/SKILL.md)). Its provider SDK lets apps embed exit nodes that pay out to a Bittensor wallet, and the published examples "start providing without a consent screen of their own," although the contract requires consent ([provider contract](https://github.com/urnetwork/examples/blob/main/PROVIDER_CONTRACT.md)). The homepage features testimonials reading "Passes Proxy/VPN detection" and "I am in iran and working this app perfectly" ([ur.io](https://ur.io/)). The network is presented as Bittensor subnet SN25 by a "UR Foundation" with tokenholder letters and an Investor Centre, while ur.io describes BringYour, Inc. as "a Network Operator for the UR protocol," which leaves an enterprise buyer asking who signs the contract and whether fees feed token incentives ([ur.xyz](https://ur.xyz/); [ur.xyz investors](https://ur.xyz/investors); [ur.io](https://ur.io/)). Privacy communities have already filed it: a long-standing Privacy Guides participant put it on "the list of all the other 'crypto' related VPNs with zero documentation," adding that "None of them have enough nodes to actually be private" ([Privacy Guides](https://discuss.privacyguides.net/t/any-thoughts-on-urnetwork/27989)). Developer visibility is close to nil, with 17 points on the Show HN and zero stars on the agent skill, so buyers will fall back on those category priors ([HN](https://news.ycombinator.com/item?id=43165027); [GitHub API](https://api.github.com/orgs/urnetwork/repos)).

The gap between marketing and evidence is the second-largest liability, and it is self-inflicted. The homepage promises "No logs stored" and "Tor-like anonymization. No logs. 100% open source and reproducible," while the core client repository calls itself "Open core" ([ur.io](https://ur.io/); [ur.io/llms-full.txt](https://ur.io/llms-full.txt); [GitHub API](https://api.github.com/orgs/urnetwork/repos)). The company's public threat model says "There is no independent audit of the protocol, the connect engine, or the operator's server code" and that the fail-closed toggle "still ships off in all five native apps," so in a default client "every application packet crosses the operator unsealed" ([threat model](https://ur.io/docs/threat-model)). That candor is an asset; the mismatch is what a diligence team will quote. The artifacts privacy reviewers weigh most, a warrant canary, a transparency report and the trust-and-safety policy, returned 404 at every public URL tried on 31 October, and the internal transparency report covers only the first half of 2024 ([internal transparency report](file:///Users/brien/urnetwork/docs/trust-and-safety/transparency-report.md)). The agent docs say x402 is "not switched on" while the live endpoint returned a price list ([agents.md](https://ur.io/agents.md); [x402 SKUs](https://api.bringyour.com/x402/skus)). Scale figures do not reconcile: 180,000 users in a November 2025 deck, 1.2 million "networks" and a 3.4 million peak of "devices" in the October 2026 stats feed, and "50K+" Play installs. The published daily average of providers also fell from about 105,000 in August to about 84,000 in October ([internal IETF 124 deck](file:///Users/brien/urnetwork/docs/presentations/Default%20Safe_%20Realizing%20the%20Potential%20of%20Decentralized%20Networks%20%28IETF%20124%29.pdf); [stats feed](https://api.bringyour.com/stats/last-90); [Google Play](https://play.google.com/store/apps/details?id=com.bringyour.network)). Aggregators list a seed of $1.5M or $2M and a directory listing puts the team at 1 to 10 people, ordinary small-vendor objections that the token makes harder to answer ([VCBacked](https://www.vcbacked.co/company/bringyour); [DePIN Hub](https://depinhub.io/projects/urnetwork/); [AppSumo](https://appsumo.com/products/urnetwork/)). Even the IETF 124 talk the company cites appears in no IETF record searched ([IETF bluesheet](https://www.ietf.org/proceedings/124/bluesheets/bluesheets-124-dinrg-202511041930-00.txt)).

Some assets transfer, and one assumption does not. The sidecar can reuse an OAuth-protected MCP server already on the stateless 2026-07-28 spec, add-server recipes for 21 harnesses, account and API-key plumbing, a reproducible-builds repository, and URmessage, an MLS (RFC 9420) messenger whose server "never decrypts anything," though it is in "Early development" ([agents.md](https://ur.io/agents.md); [message-server](https://github.com/urnetwork/message-server)). What does not transfer is the VPN's privacy argument. URnetwork's split-knowledge design, in which "the operator knows who you are; the provider knows where you go," protects egress, but live multi-hop routing runs "through a central hop," and the sidecar's storage, inbox, forwarding and audit would all be operator-hosted ([internal audit briefing](file:///Users/brien/urnetwork/cure53/AUDIT.md); [internal protocol research](file:///Users/brien/urnetwork/docs/protocol/protocol-research.md)). The sidecar's privacy has to rest on keys customers hold, not on network topology. A customer-readable admin record also cuts against the company's existing stance, in which its own encrypted abuse log is deliberately unreadable to the company; an operator-blind trail that customers' admins can read is new design and new audit work ([internal trust-and-safety policy](file:///Users/brien/urnetwork/docs/trust-and-safety/trust-and-safety.md)).

The sidecar also inherits the security record of every feature it bundles. An inbox that agents read, beside a private store and an outbound channel, combines the three legs of Simon Willison's lethal trifecta ("Access to your private data," "Exposure to untrusted content" and "The ability to externally communicate"), about which he writes that "we still don't know how to 100% reliably prevent this from happening" ([Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). A crafted email turned Microsoft 365 Copilot into an exfiltration channel in EchoLeak, and a squatted postmark-mcp package silently BCC'd every outgoing email to an attacker ([Dark Reading](https://darkreading.com/application-security/researchers-detail-zero-click-copilot-exploit-echoleak); [Koi Security](https://koi.ai/blog/postmark-mcp-npm-malicious-backdoor-email-theft)). Easy exposure is how agent control planes reached the internet: Knostic found 1,862 exposed MCP servers, none of a hand-checked 119 requiring authentication, and scanners counted tens of thousands of exposed OpenClaw gateways, which then drew a token-theft CVE rated 8.8 ([Knostic](https://www.knostic.ai/blog/mapping-mcp-servers-study); [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-openclaw-claw-chain-cve-20260517-csa-style/)). Shared memory and configuration are a persistence layer. In May and June 2026 the Mini Shai-Hulud worm planted a Claude Code hook that survived uninstalling the package, and Miasma planted config files for Claude Code, Gemini CLI, Cursor and VS Code that execute when a repository is opened ([OWASP](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026/)). Agents also use whatever channel they share: OpenAI's evaluation agents coordinated through an internal package service and passed credentials among themselves ([OWASP](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026/)). And the developer userspace the sidecar would occupy is where s1ngularity invoked installed AI CLIs with permission-bypass flags to hunt for secrets, and where Shai-Hulud harvested tokens across more than 500 compromised packages ([Wiz](https://wiz.io/blog/s1ngularity-supply-chain-attack); [CISA](https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem)). Reviewers will treat the sidecar as an agentic supply-chain component that holds credentials and opens tunnels, the kind of shadow agent infrastructure Microsoft now lets Intune block when it is OpenClaw ([Microsoft Security blog](https://www.microsoft.com/en-us/security/blog/2026/05/01/microsoft-agent-365-now-generally-available-expands-capabilities-and-integrations/)).

Privacy wording is the last constraint. The FTC acted against Zoom in 2020 for advertising "end-to-end, 256-bit encryption" while Zoom held the keys; ETH Zurich found severe cryptographic flaws under a malicious server in four of five end-to-end-encrypted cloud storage services with over 22 million users combined; a 2026 USENIX paper titled "Zero Knowledge (About) Encryption" attacked three password managers' claims; and TeleMessage's promise of encryption "through to the corporate archive" collapsed when its source code showed plaintext shipped to its archive server ([FTC](https://www.ftc.gov/news-events/news/press-releases/2020/11/ftc-requires-zoom-enhance-its-security-practices-part-settlement); [IACR ePrint](https://eprint.iacr.org/2024/1616); [USENIX](https://www.usenix.org/conference/usenixsecurity26/presentation/scarlata); [Micah Lee](https://micahflee.com/despite-misleading-marketing-israeli-company-telemessage-used-by-trump-officials-can-access-plaintext-chat-logs/)). TeleMessage is the exact failure mode for an "encrypted plus admin audit" product. A privacy brand selling a "private audit trail" also risks reading to a CISO as an unauditable one.

## Rebuild the product and claims around keys, scope and separation

The audit trail moves from the sixth feature to the spine. Every action that crosses the sidecar (a store write or merge, a forward opened or closed, an edge name published, a message read or sent, a member or key added or removed) should emit one signed, hash-chained event. Each event should carry the per-agent identity, the harness and its version, the sponsoring human, a credential reference but never its value, the target, the policy decision and approver, a provenance hash with a pointer into the encrypted store, a run ID and the outcome. No standard yet supplies that schema. It is a synthesis of NCCoE's delegation and non-repudiation questions, OWASP MCP08's call for "immutable audit trails," the AI Act's minimum of recording "the identity of the natural persons who verified the results," and OWASP's warning that logs are one of the places secrets leak ([OWASP MCP Top 10](https://owasp.org/www-project-mcp-top-10/); [AI Act Art. 12](https://artificialintelligenceact.eu/article/12/)). Content stays out of the trail, meaning no prompts, mail bodies, memory files or payloads, so the log is not a second, weaker copy of the private data and erasing content from the store does not break the hash chain. The sidecar should ingest harness hooks and telemetry and mint the shared action ID Cursor's users asked for, so that a proposal, the human's approval and the executed command become one record. Retention should be configurable to at least six months, exports should land in the SIEMs that Entra, Okta, Splunk and CrowdStrike customers already run, and every admin read should itself be logged. Where admins need content, URnetwork should pick one visible, disclosed path, such as Element's AuditBot, which "is visible to your users" and "cannot be hidden," Wire's consented legal-hold device, or Proton-style organization-key escrow with a private-member opt-out, and never a silent server-side copy ([Element](https://ems-docs.element.io/books/element-cloud-documentation/page/audit-bot)).

The store needs semantics that agents can survive. Real-time sync should apply to each agent's or member's working branch, with explicit, reviewable merges into shared branches, the design Ink & Switch reached after finding that real-time co-editing creates a "fishbowl effect" ([Ink & Switch](https://www.inkandswitch.com/upwelling/)). Git objects sync easily, but refs need compare-and-swap or locking, which is why Keybase used locks and git-remote-e2ee rejects the losing push. The coordination tools that skipped this broke under load: MCP Agent Mail's Rust version "repeatedly corrupts SQLite after parallel-WAL snapshot conflicts under agent-swarm load," and one Beads user wrote that "Moving to dolt pretty much made beads unusable for me" ([MCP Agent Mail #278](https://github.com/Dicklesworthstone/mcp_agent_mail_rust/issues/278); [Beads #2573](https://github.com/gastownhall/beads/issues/2573)). Group keys should use MLS, which URmessage already implements, with each share-link redemption bound to a device or agent key through a signed membership operation and each removal forcing a new epoch, so a removed member loses access to new content ([RFC 9420](https://www.rfc-editor.org/rfc/rfc9420.html)). The documentation should also concede what every comparable system concedes, that a removed member keeps whatever it already read. Key recovery should be a disclosed, per-member choice, because enterprises will demand it and zero knowledge forbids it by default. Writes to executable agent-config paths (CLAUDE.md, AGENTS.md, hooks, editor tasks, MCP configs) should wait for human review, and there should be tooling to excise a leaked secret from history. Search and summarization should run on members' machines, which the NYU and Cornell analysis of encryption and AI treats as compatible with end-to-end encryption, rather than on a server ([arXiv](https://arxiv.org/abs/2412.20231)). And because Notion shut Skiff down within months of buying it, and Keybase's future has been "in Zoom's hands" since 2020, the store should always clone as plain git with a documented export ([Reclaim The Net](https://reclaimthenet.org/private-email-and-documents-company-skiff-is-shutting-down-after-notion-acquisition); [Keybase joins Zoom](https://keybase.io/blog/keybase-joins-zoom)).

Reach should be private by default and public only on purpose. Forwards should be visible to the team rather than the internet. Publishing a TLS name should be an explicit, recorded step with authentication on, short-lived hostnames and a refusal to expose known agent control endpoints such as MCP Inspector or an OpenClaw control UI. The edge should default to TLS passthrough so that "end-to-end" stays true, with any terminating mode labeled as one URnetwork can read. The inbox and the edge should default to the customer's own domain, as Resend's agent inboxes do, rather than to `you.ur.network`, whose categorization by secure web gateways nobody has checked ([Resend](https://resend.com/blog/announcing-inboxes)). Making the sidecar installable inside cloud-agent environments would let "any harness" include the Codex and Cursor cloud agents that need private reach today. The inbox should separate the context that reads untrusted mail from the capability to send or reach the network, require human approval for outbound mail to new recipients, record every recipient including BCC, scan writes for secrets, and send from data-center infrastructure, since URnetwork's provider network blocks port 25 by default ([internal trust-and-safety policy](file:///Users/brien/urnetwork/docs/trust-and-safety/trust-and-safety.md)). Email is the heaviest new build serving the lowest-ranked gap, so shipping it after the record and the store is the lower-risk order.

Auth should consume identity rather than issue it. "Easy auth" should mean OIDC and SAML sign-in, SCIM, Okta's Cross App Access (now the Enterprise-Managed Authorization extension for MCP) and SPIFFE where it exists. Every agent should be registered under a sponsoring human, run on short-lived per-run tokens instead of the long-lived `urn_` keys URnetwork issues today, and be reachable by a kill switch in Agent 365 or Okta for AI Agents ([Okta](https://www.okta.com/newsroom/press-releases/okta-brings-first-class-identity-to-ai-agents-with-agent-sso/); [ur.io/llms.txt](https://ur.io/llms.txt)). Being registrable, discoverable and killable by those tools is what keeps a process that opens tunnels from being blocked as shadow infrastructure. The text protocol should be MCP over stdio, the newline-delimited JSON-RPC subprocess binding the leading harnesses already launch, which is also what MCP Agent Mail's users asked for when they requested "stdio transport" ([MCP transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports); [MCP Agent Mail #41](https://github.com/Dicklesworthstone/mcp_agent_mail/issues/41)). "Any harness" should then be stated precisely, because a surface like Cursor's Projects coordinator "always runs as a Cloud Agent" and cannot start a local server at all ([Cursor forum](https://forum.cursor.com/t/agents-window-projects-cant-use-my-local-mcp-servers-cursor-mcp-json-even-in-cloud-local/175734)).

Separation from the egress network has to be architectural, contractual and visible. The sidecar binary should contain no provider mode and route no customer traffic through residential providers. Its storage, relay, edge and mail should run on data-center infrastructure, under a trust-and-safety process that covers hosted endpoints and outbound mail, which the current egress process does not. The contract should name BringYour, Inc., state that sidecar fees carry no token economics, and explain how the operator relates to the UR Foundation. The product should carry a name that does not lean on "sidecar."

| Drop this claim | Why | Say this instead |
|---|---|---|
| "Zero-knowledge" | Reviewers test the term against a malicious server, and a 2026 paper's title mocks it | "URnetwork cannot read your store or your record. Here is the metadata we can see," followed by the list |
| "End-to-end encrypted," unscoped | FTC v. Zoom; TeleMessage | "Encrypted on members' devices under keys your team holds. Agents you run, and the model providers they call, see plaintext. Inbound mail is encrypted on receipt. Passthrough TLS names stay end-to-end; terminated ones do not." |
| "Private audit trail" | Reads to a CISO as unauditable | "Private from us, complete for your admins" |
| "Records everything your agents do" | The sidecar sees only what crosses it and what hooks report | "Records every action through the sidecar, and every harness event you connect, bound to the person who approved it" |
| "Works with any harness" | Cloud coordinators cannot launch a local process | "Works in any harness that runs a local MCP server, and in cloud-agent environments that install it" |
| "Easy" public exposure of local services | Exposed MCP servers and OpenClaw gateways | "Private by default; public when you publish, and every publish is on the record" |
| "Agent sidecar," "agent memory" or "agent mail" as the category | Microsoft's Auth SDK sidecar; free harness built-ins | "The private record of agent work" |

The company-level cleanup is a precondition, not polish, because a reviewer will read the egress network's pages before the sidecar's. It means removing the "distributed scraping" recipe and the evasion and Iran testimonials from anything an agent buyer sees, and reconciling "No logs stored," "100% open source" and "Tor-like" with the threat model, which already tells the truth. It means restoring a dated canary and current transparency reports and publishing the Cure53 results when that audit completes, since the threat model says the 2025 assessments did not examine "logging, retention, the data path, or the protocol" ([threat model](https://ur.io/docs/threat-model)). It also means defining "users," "networks" and "devices," fixing the x402 documentation, publishing sanctions controls, and documenting the IETF talk or ceasing to cite it. An independent audit of the sidecar's client and protocol, a written malicious-server threat model and a metadata disclosure list should all precede the first use of "end-to-end encrypted," the bar Privacy Guides sets when it asks for open-source clients "audited in their entirety by an independent third party" ([Privacy Guides](https://www.privacyguides.org/en/cloud/)). The earlier line, "Keep what the last run changed, and let the next one reach the machine," was right about the two pains and wrong about where the scarcity sits. The record keeps both benefits and changes the subject: continuity becomes what the next run reads from the record, and reach becomes a grant the record shows someone approved.

## Conclusion

The strategic finding is an inversion. The sidecar's defensible ground lies where URnetwork is weakest today, in a customer-facing record, keys the company cannot read and an audited encryption claim, while its commodity ground lies where URnetwork is strongest, in relays and reach. That makes the sidecar less a product extension than a test of whether the company can sell on verifiable claims, because a product whose value is "you can check what happened" cannot share a brand with pages that promise "No logs stored" beside a threat model that lists the logs. The company's best cultural asset, a threat model candid enough to say that a default client's packets cross the operator unsealed, is exactly the evidence culture the record category needs; the work is making the marketing match it.

Privacy also changes meaning in this market. For VPN users it meant hiding from the network; for agent teams it means keeping the vendor out while letting the team's own admins see everything. "Private from us, complete for your admins" reconciles URnetwork's privacy brand with what security reviewers want, and it is the one position that model vendors, which hold transcripts, and gateway vendors, which inspect traffic, cannot copy without undercutting how they make money. The window is set by events to watch rather than by a date: GitHub shipping the local session activity it listed as future work, Microsoft extending discovery to CLI agents, Anthropic or OpenAI offering customer-keyed records across rival harnesses, and Cloudflare turning its storage, email and tunnel parts into a process that runs beside the harness. Any one of those would shrink the first two gaps to a feature, which argues for building the record and the store before the inbox.
